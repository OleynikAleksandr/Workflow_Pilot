# Workflow execution — координация в Control

Review нового плана по умолчанию OFF. При ON Kit согласует пару spec/plan через Claude CLI; успешный отзыв требует позиции автора, изменение пары — нового раунда. Execution запускает процесс, Control координирует ожидание и продолжение, Kit единственный публикует план. Неизменённое согласие не требует лишнего раунда. Ошибка/спор сохраняются для явного решения, OFF возвращает обычную публикацию.

В review:prepare получатель recipient_session_id задаётся на верхнем уровне, execution_origin_session_id находится внутри scope и обозначает происхождение снимка настроек, а не владельца плана. Выбранная строка другого чата не подменяет получателя. parallel_allowed/max_workers/strategy/reason сохраняются для плана; изменение Settings не перенастраивает текущий снимок. Подробный CLI-контракт — [Workflow Kit](../../packages/workflow-kit/docs/modules/workflow-kit-package.md#опциональный-review).

Control содержит AutoPlan, ProjectAutoPlan, ReviewContinuation, PlanReviewClient, ParallelExecution/Kit, исполнителей, подтверждение плана и его проекции в src/control/workflow. Алгоритмы базы 0.6.115 сохранены: sequential работает в основном checkout, parallel использует отдельные worktree. С 0.4.4 переключателя AutoPlan нет ни в интерфейсе, ни в IPC: у любого активного плана одна кнопка `setPlanExecution` («Начать выполнение плана» / «Пауза» / «Продолжить»). У sequential/parallel-плана кнопка включает и выключает прежний механизм продолжений (AutoPlan/ProjectAutoPlan) с его проверками; пауза немедленная, состояние кнопки берётся из этого механизма. Без плана, во время планирования и после выполнения кнопки нет. С 0.4.0 план оркестратора ведут ExecutionControl (кнопка запуска и паузы) и ParallelExecution с волнами, delivery-фазой, сигналами Kit и автопаузой — [оркестрованное выполнение](orchestrated-execution.md). Отложенная ротация 0.6.113/114 не включена.

С 0.2.0 вся координация выполняется в [backend](backend.md). Допуск фоновой работы не требует окна, sidebar или видимой страницы: закрытие клиента, ноль зрителей и потеря lease не выключают AutoPlan, Review и исполнителей. Явная остановка службы (draining) не даёт новых отправок, контекста и назначений, но дожидается текущего ответа, инструментов и команд Kit; отмена остановки продолжает с места ожидания.

ControlFacade создаёт coordination: она владеет разрешениями проектов, журналами отправок, восстановлением основных и назначенных сессий, адресными подписками и допуском интеграции. Модель Desktop в backend вызывает операции переключения/восстановления и получает снимки. Книги назначений, состояния очередей и Map подписок наружу не передаются; очищается только явно адресованный проект. Отображение принадлежит Desktop, состояние настроек — Control. Совместимый AutoPlan-порт для текущей видимой сессии сохранён для Desktop и donor smoke.

Execution предоставляет процессы, физический IO, проверку жизни процесса/загрузки ОС и файловые наблюдатели. Наблюдатели сохраняют ограниченный список входов и перевешивание при замене inode; новых фоновых опросов нет. Control обращается к ExecutionFacade. Kit остаётся единственным владельцем изменений плана, назначений и транзакций; его Review API и CLI используются без второй копии плана.

execution_origin_session_id выбирается из подтверждённого parallel-плана и сверяется со снимком max_workers основной сессии. recipient_session_id остаётся самостоятельным адресом Review; получатель сверяется повторно по сохранённому состоянию непосредственно перед Send. OFF, Stop, draft, неподтверждённые writer-команды и UNKNOWN сохраняют прежние блокировки. Готовый source не доказывает merge safe: диагностическое поручение, последовательная интеграция и финальная передача имеют отдельные сохранённые этапы без повторного Send.

Новые worktree и quarantine используют .workflow-pilot-worktrees и .workflow-pilot-delete-. Донорские проекты открываются по исходному формату Kit; перенос регистра локальных проектов не выполняется. Два приложения не должны исполнять один план одновременно.

packages/workflow-kit содержит Kit 1.8.0; resources/workflow-kit генерируется staging, установленный runtime обновляет installer. Циклы Kit устранены разделением правил и команд; [совместимость проектов](project-compatibility.md) описывает продолжение формата 1.7.2. Временные корневые re-export удалены; scripts и tests используют текущие модули. Архитектурная проверка запрещает циклы без исключений, обход ControlFacade из Frontend, импорты корневых мостов и физическое IO из Control.

Проверки: прежние F01–F20/A01–A06, Review recipient/restart/final-send, тесты ControlFacade для отделённых снимков, сохранения UNKNOWN/origin и адресной очистки; полный unit-all, изолированный electron-smoke, kit-check и architecture. Реальные службы, модельные агенты и профиль пользователя в fixtures не используются. Проверки оркестрации — `tests/orchestrated-execution.test.mjs`, `parallel-execution.test.mjs`, `execution-control.test.mjs`, `session-roles.test.mjs`.
