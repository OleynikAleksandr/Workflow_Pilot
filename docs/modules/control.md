# Control — проекты, сессии и контекст

Композиция backend (`src/backend/bootstrap.mjs` → модель Desktop в `src/backend/desktop-model.mjs`) создаёт ControlFacade с Execution, однократно вызывает configureProjects/attachSessions/configureWorkflow. Повтор отклоняется CONTROL_ALREADY_CONFIGURED, CONTROL_SESSIONS_ALREADY_ATTACHED или CONTROL_WORKFLOW_ALREADY_CONFIGURED. Модель Desktop использует явные операции фасада; внутренние data, mutationTail, tickets, Map не доступны. Control живёт в [backend](backend.md) и не зависит от подключённых клиентов: клиент обращается к нему только через allowlisted API, отключение клиента не меняет stores, сессии и AutoPlan.

ProjectsService владеет WorkspaceSessions и очередью записи. select/newSession/bindChat/snapshot/whenIdle предоставляют операции и отделённые снимки. Setup.preview возвращает token, apply перепроверяет входы. Doctor, readiness, deletion и lifecycle находятся в Control/projects. Проекты и логические сессии принадлежат Control; один current plan checkout принадлежит Kit. SessionPlans вызывает установленный Kit; ContextService проверяет recovery и кеширует по актуальным входам. Отдельного плана чата нет.

Ключ сессии включает workspace/sessionId/assignmentId/taskId. Scoped store отклоняет чужой адрес; смена видимого проекта не меняет фонового владельца. Контекст отправляется однократно, UNKNOWN запрещает автоматический повтор; restart сохраняет привязки. Исходы Send — в [Browser](browser.md).

Control не импортирует Electron, fs, child_process. IO проходит через ExecutionFacade/FileAdapter; страницы, Send и подписки — Execution/browser. Control/sessions/service владеет ContextSession, ConversationRecovery, таймером и ручной привязкой. Backend предоставляет browser host; draining приостанавливает новые отправки и контекст через `pause`, отмена остановки продолжает с места ожидания. AutoPlan/Review/parallel — Control/workflow, настройки — Control/settings, onboarding — Control/startup. Architecture gate запрещает обход фасадов и циклы; attachSessions — внутренний порт, не публичный IPC.

createPlugin использует тот же ProjectsService через приватный Execution-мост существующего MCP; мост поднимает backend, поэтому плагин работает без открытого окна. Внешняя сессия хранит хеш идентификатора разговора, не запускает браузер и AutoPlan. Контракт и ограничения — [плагин ChatGPT](chatgpt-plugin.md).

PluginLaunch хранит только в памяти одну явно подготовленную панель и одну команду запуска. Меню Desktop проверяет identity проекта через plugin.open и передаёт её ожидающей панели; выбранная сессия и браузер не меняются. Ожидание ограничено 45 секундами, claim одноразовый и действует 15 секунд, при неизвестном результате повтора нет. Закрытие/перезапуск не воспроизводит команду. Snapshot отделяет принятие API от выдачи полного проверенного контекста через MCP и содержит его размер/хеш; это не доказательство чтения моделью. Фоновая оркестрация не включается.

control-facade.test проверяет владение, restart, detached snapshots, UNKNOWN и откат записи; backend-api и backend-end-to-end — те же операции через API без клиента. chatgpt-plugin.test проверяет UI→MCP→Control. Electron smoke проходит реальные IPC на изолированных fixtures, включая удаление и внешнюю сессию. Живую приёмку выполняет пользователь.
