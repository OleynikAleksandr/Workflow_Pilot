# Control — проекты, сессии и контекст

Композиция backend (`src/backend/bootstrap.mjs` → модель Desktop в `src/backend/desktop-model.mjs`) создаёт ControlFacade с Execution, однократно вызывает configureProjects/attachSessions/configureWorkflow. Повтор отклоняется CONTROL_ALREADY_CONFIGURED, CONTROL_SESSIONS_ALREADY_ATTACHED или CONTROL_WORKFLOW_ALREADY_CONFIGURED. Модель Desktop использует явные операции фасада; внутренние data, mutationTail, tickets, Map не доступны. Control живёт в [backend](backend.md) и не зависит от подключённых клиентов: клиент обращается к нему только через allowlisted API, отключение клиента не меняет stores, сессии и выполнение планов.

ProjectsService владеет WorkspaceSessions и очередью записи. select/newSession/bindChat/snapshot/whenIdle предоставляют операции и отделённые снимки. Setup.preview возвращает token, apply перепроверяет входы. Doctor, readiness, deletion и lifecycle находятся в Control/projects. Проекты и логические сессии принадлежат Control; один current plan checkout принадлежит Kit. SessionPlans вызывает установленный Kit; ContextService проверяет recovery и кеширует по актуальным входам. Отдельного плана чата нет.

Ключ сессии включает workspace/sessionId/assignmentId/taskId. Scoped store отклоняет чужой адрес; смена видимого проекта не меняет фонового владельца. Контекст отправляется однократно, UNKNOWN запрещает автоматический повтор; restart сохраняет привязки. Любая новая локальная сессия использует [стартовый канал панели](orchestrator-startup.md): ContextSession сохраняет короткий bootstrap и неизменяемый recovery, DialogueDelivery проверяет свежесть и готовность, StartupContext хранит пакет и квитанции в существующем WAL. Исходы Send — в [Browser](browser.md).

Новый проект раскрывается сразу. Для всех автоматических несостоявшихся стартов, включая обычного O, readiness повторно проверяется ограниченное время без выбора карточки: до 60 наблюдений с интервалом 500 мс, с проверкой документа и поколения. Отправка, отмена и закрытое назначение прекращают наблюдение.

`cancelPreparation` до Send меняет поколение и сохраняет `preparationPaused` в сессии. Черновик и файлы остаются; фоновые события и перезапуск не возобновляют подготовку. Явный retry снимает паузу, а после ошибки вложений разрешает только проверенную замену собственного незавершённого файла. `pilot:retry` запускает длительную подготовку без удержания общего UI actionPending; `pilot:cancel-context` доступен во время ожидания. Sidebar показывает отдельную стадию загрузки и число готовых частей; доступны отмена, затем повтор или новая сессия. После начала Send отмена не создаёт разрешения повторить сообщение.

Control не импортирует Electron, fs, child_process. IO проходит через ExecutionFacade/FileAdapter; страницы, Send и подписки — Execution/browser. Control/sessions/service владеет ContextSession, ConversationRecovery, таймером и ручной привязкой. Backend предоставляет browser host; draining приостанавливает новые отправки и контекст через `pause`, отмена остановки продолжает с места ожидания. Выполнение планов, Review и parallel — Control/workflow, настройки — Control/settings, onboarding — Control/startup. Architecture gate запрещает обход фасадов и циклы; attachSessions — внутренний порт, не публичный IPC.

createPlugin использует тот же ProjectsService через приватный Execution-мост существующего MCP; мост поднимает backend, поэтому плагин работает без открытого окна. Внешняя сессия хранит хеш идентификатора разговора, не запускает браузер и выполнение плана. Контракт и ограничения — [плагин ChatGPT](chatgpt-plugin.md).

AssignmentDialogue сохраняет авторский intent, вызывает идемпотентный эффект Kit и публикует WAL. O выбирает task/context и принимает результат, Control не сочиняет их. DialogueDelivery связывает физический конец SDK-хода с прежним scheduler без требования user bubble. [Контракт ролей](assignment-dialogue.md) и [восстановление](assignment-dialogue-reliability.md).

PluginCommunication владеет реестром O/нескольких E, приглашениями, допуском scope, очередью и WAL. PluginProjects передаёт свежие факты назначения; DialogueDelivery связывает канал с прежним scheduler и наблюдениями страницы/команд, без второго плана. Execution сохраняет мутации до подтверждения через fsync. Перед SDK проверяются identity, назначение, разрешение, занятость/черновик и одноразовое намерение. Start/Continue разрешает план, Stop отзывает отправки всего плана; restart требует Continue, UNKNOWN не повторяется. Sidebar адресата не выбирает. Контракт — [плагин](chatgpt-plugin.md).

control-facade.test проверяет владение, restart, detached snapshots, UNKNOWN и откат записи; backend-api и backend-end-to-end — те же операции через API без клиента. chatgpt-plugin.test проверяет UI→MCP→Control. Electron smoke проходит реальные IPC на изолированных fixtures, включая удаление и внешнюю сессию. Живую приёмку выполняет пользователь.

С 0.4.0 WorkspaceSessions хранит роль сессии (orchestrator, discussion, executor) дополнительными полями v6, согласует её после публикации плана оркестратора (`reconcileRoles`, `assignOrchestrator`) и запрещает архивировать оркестратора активного плана; проект с активным планом архивируется только с подтверждённым `stopExecution`. Recovery запрашивается у Kit с `--role`, ContextCache разделяет пакеты по ролям, а запись исполнителя с удалённым worktree открывается из сохранённой проекции. Контракт — [оркестрованное выполнение](orchestrated-execution.md).


Старт всех новых локальных сессий — [единый канал панели](orchestrator-startup.md), независимо от стратегии и состояния плана. DOM содержит только приглашение; ролевые правила E тоже читаются через MCP. Старый генератор вложений отключён. Получение пакета не назначает O и не разрешает выполнение задач.
