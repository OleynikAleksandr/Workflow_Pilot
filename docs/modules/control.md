# Control — проекты, сессии и контекст

Порядок работы: bootstrap создаёт ControlFacade с Execution, настраивает проекты/контекст и подключает сессии; Desktop вызывает явные операции этих портов. configureProjects/attachSessions/configureWorkflow допускаются однократно, повтор даёт CONTROL_ALREADY_CONFIGURED, CONTROL_SESSIONS_ALREADY_ATTACHED или CONTROL_WORKFLOW_ALREADY_CONFIGURED. Setup.preview(input) возвращает результат проверки и token, setup.apply(token) перепроверяет входы перед записью. ProjectsService предоставляет select/newSession/bindChat/snapshot, скрывая WorkspaceSessions и очередь записи; whenIdle() позволяет дождаться её завершения. Ошибки подготовки и жизненного цикла описаны в связанных контрактах, исходы Send — в [Browser](browser.md).

Control содержит WorkspaceSessions, WorkspaceSetup/Readiness, WorkspaceDeletion, ProjectDoctor, очистку состояния, SessionPlans, ContextSession/Cache и ConversationRecovery в src/control. ControlFacade используется Desktop для создания/выбора проектов и Chat/Work, открытия прежних чатов, восстановления, подготовки контекста, Doctor и удаления. Фасад удерживает хранилище и очереди; наружу выходят явные операции и отделённые снимки. Доступа клиента к data, mutationTail, tickets и Map кеша/реестра сессий нет.

Проекты и логические сессии принадлежат Control, единственный current plan checkout — Kit. SessionPlans вызывает установленный Kit, ContextService проверяет его recovery и кеширует пакет по актуальным входам; отдельного плана чата нет. Смена видимого проекта не меняет адрес фоновой сессии. Ключ включает workspace, sessionId, assignmentId и taskId; scoped store отклоняет чужой адрес. Полный контекст отправляется один раз, UNKNOWN не разрешает автоматический повтор. Сохранённые привязки и recovery остаются адресными при restart и частичном сбое.

Control не импортирует Electron, fs и child_process. Физические операции идут через ExecutionFacade/FileAdapter; браузерные страницы, Send и подписки принадлежат Execution/browser. Control/sessions/service владеет ContextSession, ConversationRecovery, таймером и привязкой вручную открытого разговора. Desktop предоставляет presentation и технический browser host.

Локальный порт attachSessions предоставляет операции координаторов для workflow coordination и Desktop; это не публичный IPC-контракт. AutoPlan/Review/parallel находятся в Control/workflow, настройки — в Control/settings, startup flow — в Control/startup, проверки жизненного цикла — в Control/projects/lifecycle. Корневые временные re-export удалены. Импорты внутренних модулей Control из Frontend, физическое IO внутри Control и обход ExecutionFacade запрещены architecture gate.

Проверки: control-facade.test проверяет Chat/Work, сохранённую принадлежность, независимость фонового адреса, отделённые снимки, неизменность плана Kit, UNKNOWN и откат неудачной записи. Прежние тесты контекста/recovery/storage продолжают проверять поведение; Electron smoke проходит реальные IPC-пути на изолированных fixtures, включая прерывание подтверждённого удаления. Smoke использует внедряемый beforeFinish и файловую fixture вместо изменения внутреннего store. Живой UI проверяет пользователь.
