# Проекты, архив и удаление

ControlFacade предоставляет создание/выбор проекта и Chat, recovery, Doctor, архив и удаление. `control/projects/lifecycle.mjs` координирует остановку и очистку, `workspace-deletion.mjs` — preview, подтверждённое намерение и recovery. Desktop передаёт явные действия и показывает подтверждения; физические файлы и команды обслуживает Execution. Состояние проектов и настройки имеют по одному владельцу в Control, план checkout — в Kit.

Каждый workspace имеет сохраняемый случайный workspaceId; projectId принадлежит Kit, sessionId — разговору. Worktree имеет собственный workspaceId и parentWorkspaceId. Переименование сохраняет ID, удаление/создание даже с тем же именем и путём создаёт новую identity workspace. Путь нужен IO, но не доказывает владельца истории/выбора/разрешения. Публичный API плагина возвращает id=workspaceId и отдельный projectId; legacy projectId принимается только при однозначной записи. Архив адресуется по workspaceId/projectId, архив сессий — дополнительно по sessionId. «В архив» есть у каждой строки проекта и не требует предварительного выбора. Backend свежо читает план и сверяет сохранённый execution complete с точными projectId/scopeId и всеми DONE. Complete при ACTIVE/READY_FOR_ACCEPTANCE scope архивируется без предупреждения остановки, сохраняя complete и закрытый grant; возврат не запускает работу. Архив проекта не означает пользовательскую приёмку Kit scope.

Running/pausing/paused/finalizing, устаревший scope или неподтверждённый снимок требуют подтверждения stopExecution. UI сначала обращается к backend; только PLAN_ACTIVE вызывает вопрос, поэтому устаревшая карточка не обходит защиту и не создаёт лишнее предупреждение для complete. Отказ не закрывает и не перезагружает активный чат. Подтверждённая остановка обновляет роли, ставит незавершённый план на паузу и сохраняет файлы; возврат требует Continue.

«Убрать из списка» отключает проект и всех его исполнителей, оставляя папки. «Удалить с диска» после preview и одного предметного подтверждения удаляет репозиторий и собственные worktree. Облачные чаты ChatGPT сохраняются.

Незавершённые назначения, ошибочный план, dirty worktree и зависшая транзакция Kit не запрещают preview/подтверждение. Завершать задачи перед удалением не нужно. Подтверждение показывает точные пути и потерю незакоммиченных результатов. Принадлежность подтверждается сохранённой identity проекта/назначения и связями Git; состояние DONE/INTEGRATED не подделывается, managed-файлы Kit не исправляются.

После подтверждения сначала сохраняется журнал намерения (режим disk/forget), затем запрещаются новые назначения и отправки, отзывается связь, освобождаются страницы и адресно останавливаются собственные локальные/MCP-команды. Ожидаются scheduler, terminal evidence и очереди сохранения. Общая служба и соседние проекты продолжают работу. Перед физическим удалением повторно сверяются identity каталогов и принадлежность; поздно созданный собственный worktree включается в ту же очистку. Смена выбора в UI не меняет цели.

Удаление очищает родителя/исполнителей, настройки executionControl/продолжений/очередей, watchers, кэш, активные регистрации/приглашения и сообщения. Сохранённый запрет старых сессий и команд исключает их восстановление поздним callback или restart. История принятой доставки может сохраниться как диагностика, но не как действующая связь. Явное повторное добавление оставленной папки создаёт новый workspaceId и требует нового допуска. История удалённой сессии не переносится по пути; legacy допустим только по точному живому sessionId без противоречащих ID проекта/workspace.

Частичная ошибка сохраняет намерение; повтор/restart продолжает ту же операцию до подтверждённой очистки. Успех не сообщается заранее. Pending Kit удерживает выполнение своего проекта при запуске backend, оставляя архив доступным. Старый boot/UNKNOWN не означает успех команды и не вызывает её повтор. Если остановку живой операции нельзя доказать, возвращается `PROJECT_COMMAND_STOP_UNCONFIRMED`; неподтверждённые чужие процессы не уничтожаются. Для остановки собственных команд пользователь не переносит session ID и не просит агента завершить задачу.

Защищены корень, домашняя папка, профиль/runtime, donor и пересекающиеся проекты. Симлинк, подмена inode/пути, чужой Git/worktree или изменившийся projectId дают конкретный отказ (`DELETE_PROTECTED`, `DELETE_PATH_CHANGED`, `DELETE_WORKTREE_CHANGED`, `PROJECT_REPLACED`); ошибка доступа сохраняет код. Пропавшая папка не является доказательством принадлежности. Отмена подтверждения не останавливает работу и не удаляет файлы.

Очистка записи пропавшего исполнителя доступна в Настройках и не удаляет файлы. Она запрещена при открытом ребёнке/родителе, незавершённых командах, активном назначении или UNKNOWN в ledger. Закрытие Настроек либо изменение записи между просмотром и подтверждением требует повторного выбора. Полный контекст не отправляется повторно в прежний чат; Send после UNKNOWN автоматически не повторяется.

Отдельное признание исхода неизвестным в диагностике команды сохраняет прежнюю проверку session/project/digest и не подтверждает её успех. Это не обязательный шаг удаления всего проекта.

Unit, настоящий частный App Server без модельных ходов, HTTP API и Electron smoke проверяют незавершённые/dirty проекты, собственную занятую команду и живого соседа, UNKNOWN, пропавший worktree, отказ подтверждения, подмену пути, частичный сбой/restart и зависший Kit. Рабочий профиль не используется. Живую приёмку интерфейса Mac выполняет пользователь отдельно.

[Chat-only контракт](chat-only-startup.md): schema 9 атомарно присваивает workspaceId при миграции, проверяет уникальность и сохраняет прежние projectId/sessionId, назначения, пакеты и квитанции без нового Send. Выбора режима, чтения или конвертации старых Work-сессий нет; некорректные данные отклоняются без потери исходника.

## Закрытый план

В 0.5.40 parseWorkflowPlan читает целый внешний JSON-блок между однозначными workflow-state маркерами. Fences, кириллица и экранированные примеры внутри task_brief/prepared_task не обрывают чтение. Неполный JSON, неверная структура и повторные маркеры отвергаются. Этот разбор используют backend closedPlan, legacy loadContext и проверка identity удаления; fallback поставляемого workspace-setup-worker исправлен на полный блок без импорта src. Уже безопасные потребители и установленный Kit без необходимости не переписываются.

ClosedPlanCache получает текст родителя точного closedPlanCommit через ExecutionFacade. Проверяются projectId/scopeId и сохранённый владелец, все исходные статусы DONE; ключ содержит workspaceId/projectId/scopeId/sessionId/commit. Поздний ответ удалённого/заменённого workspace игнорируется. В 0.5.41 активная карточка sidebar после current=false/NONE показывает только «План закрыт» и готовность нового плана: исторические title/задачи/счётчик/прогресс/действия не выводятся. Review и имя сессии сохраняются, новый план не создаётся. Подтверждённое закрытие и пустая карточка сохраняются при загрузке/ошибке подробностей без raw exception; внутренние история и безопасная диагностика остаются.

Положительный результат кэшируется; ошибка допускает максимум два чтения при обычных обновлениях, без нового scheduler. Явное открытие/обновление сессии сбрасывает только неудачные записи; restart создаёт новый кэш. Переход к новому плану не присваивает ему старую историю. Git fixture реально проходит четыре task:start/commit, archive Kit и чтение родителя. Адресный renderer-тест передаёт четыре DONE, затем loading/error и новый current plan: закрытая карточка пуста, новый план содержит только новые задачи. Панель ChatGPT закрытого разговора не меняется. Живая приёмка 0.5.41 ожидается.
