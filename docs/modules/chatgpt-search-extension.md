# Официальное расширение ChatGPT search

## Ответственность и поведение

Workflow Pilot 0.5.33 автоматически загружает, устанавливает и подключает официальное ChatGPT search 1.11 перед первой страницей ChatGPT. Ручная установка пользователем не нужна. Backend использует свою прежнюю persistent session; браузерный профиль и вход в аккаунт сохраняются. Все Chat-страницы и исполнители этой службы получают одно расширение.

Это обязательная предпосылка [URL-старта](chat-only-startup.md) в Chromium. Проверенный клиентский код ChatGPT ограничивает автоотправку q по источнику перехода и признаку поискового расширения. Официальный content script устанавливает dataset.searchExtension=1 при document_start. Workflow Pilot не меняет этот script, User-Agent, Referer, текст редактора или кнопку отправки и не добавляет Enter. Это не публичная гарантия OpenAI, что любое q будет отправлено: [живая приёмка](../acceptance/chat-only-startup.md) остаётся отдельной.

Официальный источник расширения — [ChatGPT search в Chrome Web Store](https://chromewebstore.google.com/detail/chatgpt-search/ejcfepkfckglbgocfkanmcdngdijcgld), указанный [OpenAI](https://help.openai.com/en/articles/9237897-searching-the-web-with-chatgpt). [Electron](https://www.electronjs.org/docs/latest/api/extensions-api) загружает unpacked-расширение в конкретную persistent session; подключение повторяется при каждом новом backend. Настройка поисковой системы Chrome для интерфейса Workflow Pilot не используется.

## Контракт и зависимости

Execution: `ChatGPTSearchExtension` в `src/execution/browser/chatgpt-search-extension.mjs`, экспорт через ExecutionFacade. Вход конструктора — `{session,directory,fetch?,pin?,timeoutMs?}`. Backend передаёт собственную `session.fromPartition(identity.partition)` и каталог `identity.dataDir/browser-extensions/chatgpt-search`; остальные параметры — закреплённые значения приложения. UI и MCP не могут переопределять pin или URL.

- `prepareNavigation(url)` возвращает null для другого origin; для https://chatgpt.com ожидает `ensure()`.
- `ensure()` возвращает `{ready:true,version,officialId}` только после проверки локальной копии и успешного loadExtension. Одновременные запросы разделяют одну Promise. При ошибке последующее явное открытие может повторить подготовку; бесконечного фонового повтора нет.
- `SEARCH_EXTENSION_PIN` закрепляет официальный Store ID, версию 1.11, точный versioned Google blob, размер 12091 байт, SHA-256 CRX и каждого файла. Официальный пакет имеет SHA-256 `95bb61ea1d4c2fd4f96fa02a3ea6943c7b9ae0f935b055dc1cd9884d8868e4f2`. Будущий latest автоматически не принимается; обновление pin проходит отдельный выпуск и проверки.

### Загрузка, установка и кэш

Первому открытию ChatGPT нужен доступ к официальному Google download host. Загрузка использует HTTPS, ограниченный список Google-хостов, максимум три перенаправления, timeout 30 секунд и лимит размера. Запрос не использует cookies браузера. Ошибочный HTTP, чужое перенаправление, изменённый/усечённый/слишком большой CRX запрещают установку. SHA проверяется до разбора ZIP.

ZIP разбирает yauzl 3.4.0. Проверяются все имена, дубликаты, типы, размеры и hashes; запрещены traversal, абсолютные пути, обратные слеши, симлинки, специальные файлы и лишние записи. Manifest должен соответствовать закреплённым имени/версии, Manifest V3 и одному content script для https://*.chatgpt.com/* при document_start. Исполняемые файлы, manifest и иконки сохраняются побайтно. Установочный `_metadata/verified_contents.json` проверяется в исходном CRX, но не переносится в unpacked-копию: Electron удаляет такие метаданные.

Готовая версия находится в `<directory>/<version>-<sha16>/`: оригинальный package.crx и extension с семью проверенными файлами. Все родительские каталоги проверяются без перехода по симлинкам. Установка идёт в собственный временный каталог, с flush файлов и rename готовой версии; POSIX дополнительно синхронизирует родительский каталог. Частичная копия не загружается. Повреждённая версия сохраняется в `.rejected-<uuid>` и заменяется новой проверенной загрузкой; неизвестные/старые папки не удаляются. Симлинк вызывает отказ вместо восстановления через его цель.

Повторный backend проверяет CRX и состав кэша, затем подключает его без HTTP. В работающем backend проверенная загруженная версия переиспользуется; после выгрузки расширение загружается снова. Распакованный Electron ID может отличаться от Store ID из-за пути установки: доверие основано на исходном SHA; результат загрузки сверяется по имени, версии и точному пути.

### Порядок навигации и ошибки

Backend связывает `prepareBrowserNavigation` → BrowserSessions.prepareNavigation с тем же экземпляром адаптера. Первая страница нового Chat ещё не загружается, пока расширение не готово. Hook ожидается до loadURL и до расходования одноразового bootstrapToken. После await перепроверяются request, epoch, освобождение страницы, main-frame переходы, пользовательский ввод и canContinue. Более новый переход выигрывает; iframe не отменяет подготовку. Ошибка до чистого корня не приводит к отправке q. Прежние preflight, принадлежность, revoke/WAL, sent по регистрации и запрет q reload сохраняются.

Публичные ошибки имеют код `CHATGPT_SEARCH_EXTENSION_` и суффикс DOWNLOAD, INTEGRITY, CACHE_UNSAFE, INSTALL или LOAD. Сообщение объясняет загрузку/проверку/каталог/подключение; не содержит тикета, q или контекста. Приложение показывает существующую ошибку открытия страницы. Исправление соединения/доступа и повторное открытие разрешают новую подготовку расширения; это не разрешает повтор уже отправленной или неизвестной q-попытки.

Расширение не подтверждает отправку сообщения, регистрацию панели, сохранение адреса, чтение контекста или выполнение плана. Эти свидетельства остаются раздельными.

## Проверка

`search-extension-unit`: cold/cache/offline/concurrent/retry, timeout/redirect/лимиты, ZIP и manifest, симлинки, повреждение, атомарный отказ и ошибка Electron. `search-extension-startup`: ожидание до первой страницы/q, отказ без расходования токена, отмена/release/ввод/чужой переход, latest wins и iframe.

`node scripts/check-search-extension.mjs` запускает настоящий Electron с отдельными профилями: cold download/install/load официального пакета, content script до локального документа, одна q-отправка, запрет повтора/refresh, новый процесс offline, блокировка повреждённого кэша и восстановление. Все ChatGPT HTTPS-запросы отвечает локальный fixture; ни одна модель не запускается. Изолированный electron-smoke также подключает настоящее расширение до своих первых/новых Chat и не отправляет q без признака расширения. Его persistent partition расположен только внутри одноразового smoke userData.

Результаты записывает Kit в проверенных коммитах. Поставка содержит downloader/pin и yauzl; оригинальный CRX и пользовательский кэш в архивы приложения не включаются. Состав исходников/pin подтверждает общий release-manifest. Настоящий ChatGPT, native Windows/Linux, VM и clean-install требуют отдельной пользовательской приёмки.
