# Kit и продолжение существующих проектов

Workflow Pilot открывает папку проекта донора без импорта прежнего профиля приложения. Control создаёт новые Chat-сессии, читает project_id и единственный `.harness/plans/todo-plan.md`; номер чата не выбирает и не копирует план. История привязок браузера, cookies и настройки донора не переносятся. Recovery берётся из Kit выбранного checkout.

## Источник и обновление

`packages/workflow-kit` — единственный источник Kit 1.10.2. `scripts/stage-workflow-kit.mjs` формирует `resources/workflow-kit` и сверяет состав и SHA всех файлов с исходным пакетом. Установленный `.harness/kit` и managed-секции обновляет только installer. Изменение owned-файлов требует новой версии пакета, runtime и lockfile; формат current plan при этом не меняется.

ControlFacade.setup принимает выбранную папку через preview, возвращает состояние и одноразовый token; apply повторно проверяет входы и вызывает installer в процессе Execution. Для поддерживаемых версий, включая выпущенные 1.7.2, 1.8.1, 1.8.2, 1.9.0 и 1.9.1, выполняется штатный kit-update. Сохраняются project_id, байты текущего плана, незакоммиченные изменения задачи и предшествующие Git-коммиты. Новая сессия продолжает NONE, ACTIVE или частично DONE из того же checkout. Сервисный commit обновления не завершает пользовательскую задачу.

Неизвестная версия, изменённый owned-runtime и чужой index останавливают обновление. `operation.lock` не снимается автоматически, даже если указанный процесс уже завершён. Незавершённая transaction, assignment или integration должна быть разобрана прежним клиентом до обновления. Проверка transaction выполняется под блокировкой до записи runtime/manifest. Readiness учитывает содержимое operation.lock и transaction в отпечатке; нового фонового опроса нет. При занятом проекте подключение не предлагает обновление и не объявляет проект готовым. Отказ сохраняет план, журнал, index, runtime и HEAD.

Блокировка координирует операции Kit, а не всю жизнь двух приложений. Одновременное исполнение одного плана в доноре и Workflow Pilot не поддерживается: завершите работу прежнего клиента перед продолжением. UNKNOWN, Send и recovery подчиняются прежним правилам Control; открытие папки не разрешает повторную отправку.

Исключение для активного orchestrated 0.5.7 — отдельная штатная [миграция диалога](assignment-dialogue-reliability.md#переход-старого-плана) от O после безопасной паузы. Журнал и installer обновляют parent/child, сохраняют проверенный SHA и продолжают тот же operation_id. Это не разрешение обычному upgrade обходить dirty/UNKNOWN/живую операцию. Новые планы получают dialogue_version=1, прежние не переключаются молча.

Installer 1.10.2 поддерживает также 1.9.9, 1.10.0 и 1.10.1 и доставляет точное `.DS_Store` в managed ignore для root/nested workspace/worktree. Пользовательские секции и manifest сохраняются, повтор идемпотентен. Реальная установка development Kit 1.10.0 → bundled 1.10.1 проверена с сохранением текущего плана. Только неотслеживаемая Finder metadata не удерживает штатную подготовку; tracked metadata, пользовательский файл и исходник продолжают давать MAIN_DIRTY. Ничего не удаляется/не untrack, глобальный Git не меняется. До Start BLOCK использует существующее предложение kit-update/Doctor, без обхода настоящей dirty-защиты. Изолированный пакет выпущенной 1.10.1 проверяет upgrade до 1.10.2 с сохранением байтов плана и переходом на ролевой протокол 11.

Новые orchestrated-планы Kit 1.10.2 имеют preparation_version=1 и согласованные [поручения](prepared-tasks.md). Старые Chat brief-only планы при чтении не меняют схему/digest и не получают авторизацию задним числом; их поздний prepare сохраняется. Режим Work не поддерживается.

## Данные сессий и обратный переход

Новая версия читает прежние Chat-данные. В schema 8 добавлен titleSource=topic; identity/адрес/тикет не заменяются. Выпущенная 0.5.35 отвергает topic своим validator и сохраняет исходный файл. После первого такого имени одной замены bundle на 0.5.35 недостаточно: обратный переход требует отдельно согласованного восстановления совместимых данных из проверенной копии без молчаливой потери новых данных. Installer receipt подтверждает только bundle, не data rollback. Поведение воспроизводит immutable validator из v0.5.35 в tests/fixtures/released-session-schema-0535.json; рабочий профиль тестами не изменяется. [Контракт имён](session-titles.md).

## Зависимости Kit

Командные модули сохраняют прежние публичные экспорты и CLI. Общие правила выделены по ответственности:

| Модуль | Ответственность |
| --- | --- |
| transaction-state | operation lock, журналы, проверка и подтверждение завершённой транзакции, запрет конкурирующей интеграции |
| validation-rules | конфигурация, проверки задач и документации |
| assignment-contract | принадлежность worktree, неизменяемый контракт назначения и готовность окружения |
| commit-references | поиск и доказательство ссылок задач в Git-истории |
| integration-proof | доказательство source/merge и ожидаемого изменения общего плана |
| review-state | сохранённое состояние Review, входы, согласование и завершение публикации |

transaction, task-integration, task-assignment, actions и plan-review выполняют команды поверх этих правил. recovery читает review-state без зависимости от команд публикации. integration-proof получает узкий callback разрешения ссылок только для объявленных зависимостей из предшествующей базы назначения; он не импортирует validate или команды интеграции. Статические циклы запрещены для всего Kit без исключений.

## Проверяемая совместимость

`tests/fixtures/released-kit/kit-1.7.2.tar.gz` — неизменяемый архив исходного runtime до T007; manifest закрепляет исходный репозиторий, commit, путь и SHA256. Fixture не собирается из новой версии с подменой строки VERSION.

`migration-compatibility.test.mjs` создаёт отдельные временные проекты настоящим 1.7.2 и проверяет открытие через ControlFacade, preview/apply, новые сессии, restart, recovery и следующий commit для NONE/ACTIVE/частично DONE. Проверяются точные байты плана, identity, предшествующая история и commit-ссылки DONE. Отдельный сценарий прерывает старый commit после подготовки кандидата, проверяет отказ обновления без записи и завершает транзакцию старым runtime. Неизвестная версия и чужая блокировка также сохраняются. `workflow-kit-upgrade.test.mjs` проверяет продолжение активной задачи. Неизменяемый 1.8.1 из собственного v0.5.4 закреплён manifest fixture: upgrade до 1.9.4 сохраняет задачу и точные байты прежних сигналов; активные назначения/интеграции запрещают обновление до записи.

Неизменяемый Kit 1.8.2 из v0.5.7 закреплён отдельным архивом/digest. Проверены продолжение активной задачи после обычного update и журналируемая миграция старых назначений с прерываниями, готовым SHA, доработкой, уже INTEGRATED и отказом dirty. Ни одна проверка не использует Test_02 или живой профиль.

Неизменяемые Kit 1.9.2 из v0.5.11, 1.9.3 из 0.5.23, 1.9.4 из 0.5.24, 1.9.5 из 0.5.27, 1.9.6 из 0.5.28 1.9.7 из 0.5.29 и 1.9.8 из v0.5.32 проверяют update до текущего 1.10.1: незавершённые назначения/интеграции дают отказ до записи; начатая обычная задача, изменения и журнал сигналов сохраняются, commit и следующая задача выполняются новым runtime.

Все fixtures изолированы во временных папках. Они не меняют отдельные донорские репозитории, реальные проекты, профили, службы и не запускают модели. Живую проверку интерфейса выполняет пользователь; unit-all, kit-check, migration-compatibility, architecture и electron-smoke проверяют автоматизируемые контракты.
