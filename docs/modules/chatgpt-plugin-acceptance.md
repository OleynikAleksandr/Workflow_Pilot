# Плагин Workflow Pilot 0.5.20 — приёмка

**A–D — NOT_RUN.** Главная [матрица живого диалога](automatic-agent-dialogue-acceptance.md) проверяет авторские task/context от O, вопросы E, многоходовое решение, result, acceptance, интеграцию и итог. Fixtures/Review/поставка не подтверждают автономность реального ChatGPT.

## Среда и версии

Приложение/backend 0.5.20, Kit 1.9.3, панель `0.5.20-communication-4`, протокол панели 4, dialogue_version=1, роли 6. SourceCommit и комплект — release-manifest.json. [Installer](release.md) при занятом backend оставляет проверенный pending: пользователь останавливает прежнюю службу, завершает установку и запускает новую версию. Старую активную службу нельзя выдавать за обновлённую.

Новые workspace/разговоры; O Chat либо Work, E Chat. Второй режим O проверяется отдельно. Первичная общая настройка MCP и вход выполнены заранее. Индивидуальное подтверждение/подключение каждого E не считается допустимой подготовкой автоматического опыта. Разработка не запускает модели и не управляет окнами.

## Проверка перехода на новую панель

Отдельно от автоматического bootstrap проверить старый разговор после обновления службы: обновить каталог существующего подключения и выполнить свежий `workflow_pilot_panel`. Ожидаются актуальные build/protocol, SDK и автоматическая привязка без ID/Enable. URI текущего MCP должен соответствовать content-addressed HTML; сам этот URI не доказывает версию ранее сохранённого iframe. Старый tool-result не заменяет новый вызов. Профиль/cookies/историю не очищать.

Для нового O панель должна открыться по первоначальным инструкциям без дополнительного поручения. Для E — автоматически после Start без посещения карточки. Успех ручного восстановления существующего чата не засчитывает автоматический bootstrap.

После закрытия и повторного открытия чата проверить исходную панель до нового вызова: получает ли lifecycle/SDK, восстанавливает ли binding и ожидание. Новая рабочая панель после повторного вызова не исправляет доказательно «мёртвое» представление старого вызова. Этот опыт зависит от хоста и учитывается отдельно.

## Матрица

| Проверка | Нужное доказательство | Живой статус |
| --- | --- | --- |
| A | Один Start, два E без визитов; O task/context, E result, O acceptance/merge, DOCS/итог | NOT_RUN |
| B | Нехватка данных/ошибка, вопрос → уточнение → факты → решение, продолжение без пользователя | NOT_RUN |
| C | Новая попытка по revision_request, старый SHA не принимается повторно, зависимость после интеграций | NOT_RUN |
| D | Пять адресатов, занятый O, отдельно закрытие клиента/restart/Stop/UNKNOWN/удаление | NOT_RUN |
| Обновление ресурса | Свежий каталог/вызов выбирают новый HTML при сохранённой старой панели | NOT_RUN |
| Восстановление прежнего iframe | Фактический SDK/lifecycle до нового вызова, не только восстановленные поля | NOT_RUN |
| Темы/узкая панель/экспорт | Читаемые стадии/авторство; through_seq/страницы/gaps и отсутствие секретов | NOT_RUN |
| Legacy P0/P1 / прямое внешнее подключение | Отдельный прежний контракт без подмены A–D | NOT_RUN для 0.5.20 |
| Native Windows/Linux / clean VM | Настоящая установленная ОС | Отложено пользователем |

Ручные ID/Enable/открытие E, рабочий DOM Send, backend-авторство содержательного task/result или merge без O — FAIL целевого сценария. SDK может отображать user bubble; отличать вызов SDK от DOM по журналу, не внешнему виду. Verify и target:active не атомарны, host confirmations не обходятся.

## Предшествующее доказательство

На 0.5.5 пользователь видел `0.5.2-communication-1`; свежие runtime/MCP отдавали новый HTML, общий URI допускал сохранённую копию. Точное хранилище старой панели не установлено. В 0.5.6 подтверждён новый O с автоматической панелью, но S1 затем FAIL: конфликт lifecycle и потеря начатой страницы E.

Test_02 0.5.7 — FAIL целевого workflow: E активировались после посещения карточек, сделали два коммита, но не отправили O авторские result и не завершили план. Accepted/read backend-поручений не подтверждали авторство O. Этот результат сохранён; исправления и fixtures не отменяют его.

Пользователь ранее подтвердил обмен прежней пары при свёрнутом Chrome и сообщил о завершении обмена при закрытом интерфейсе/живой службе; build последнего опыта отдельно не снят. Восстановленная панель Chrome 0.5.3 показывала подключённый SDK и несовместимость. Это не подтверждение новых назначений или восстановления любого уничтоженного iframe.

## Возврат результата

Отчёт: PASS/FAIL/NOT_RUN отдельно, фактические версии/sourceCommit/URI, project/scope/назначения/попытки, полный список действий пользователя, времена bootstrap/SDK/read/yield/физического конца, result/acceptance/integration, очищенный экспорт с фиксированным through_seq. Недоступные страницы и gaps ограничивают вывод. Enrollment, raw metadata, cookies и bridge-токены не включать.

После отчёта пользователь принимает результат или поручает доработку. Scope автоматически не архивируется. Встроенный Chat/Work, Chrome, iPad, сон и остановленная служба — отдельные среды. [Автоматическая матрица и границы](assignment-dialogue-reliability.md#проверки-и-граница-доказательств).
