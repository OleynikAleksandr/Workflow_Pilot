## Условия начала

Установленный комплект и работающая служба должны быть версии 0.5.3; панель — build `0.5.3-communication-1`, протокол 1. Проверить существующее подключение и фактический свежий MCP-каталог. Installer может оставить pending при работающей старой службе; точные команды завершения установки приведены в handoff. Только пользователь запускает установленное приложение и включает связь.

В том же UI resource `ui://workflow-pilot/projects-v1.html` теперь интерфейс связи. Создание новых разговоров из панели, навигационные пробы и пункт «Новый чат через плагин» удалены. Прямая привязка уже открытого разговора через workflow_open_project/workflow_connect_project сохранена. Исторические результаты старого интерфейса не являются приёмкой нового канала.

## Матрица 0.5.3

| Проверка | Критерий | Статус |
| --- | --- | --- |
| P0 / Chat | Одна отложенная probe пробуждает завершивший ход разговор; он читает сообщение один раз | NOT_RUN |
| P0 / Work | Тот же сценарий, отдельно с точной версией клиента | NOT_RUN |

| Stop / expiry / reload | Новые отправки прекращены; новая панель требует bind/Enable; late report не стирает read | NOT_RUN |
| Две панели / сеть / restart | Нет слепых повторов claimed/accepted/rejected/unknown; ошибки и пробелы видны | NOT_RUN |
| Темы / размеры / экспорт | Читаемый русский UI; полный очищенный JSONL, сохранённый журнал при ошибке экспорта | NOT_RUN |

SDK accepted — принятие запроса, а read — отдельная квитанция. Привязка в момент bind не исключает необъявленную навигацию между verify и target:active. При недостаточных metadata/capabilities или неподтверждённой адресации P1 не запускается. Busy/черновик и жизненный цикл iframe проверяются наблюдением, без предполагаемых API и без DOM-обхода. Codex не заменяет Chat/Work.

## Что вернуть

Версии службы, build панели, клиента и режим; run/participant/message IDs и хеши привязки; шаги, фактический разговор-получатель, наличие ручного продолжения; PASS/FAIL/NOT_RUN каждого сценария; очищенный JSONL, summary/gaps и коды ошибок. Исходные session metadata, cookies, токены и bridge descriptor не включать. Результат пользователя определяет следующую доработку или приёмку; сведения о fixtures/сборке в него автоматически не переносятся.
