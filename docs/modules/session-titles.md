# Содержательное имя сессии

Контракт Workflow Pilot 0.5.36 / Kit 1.10.2, ролевой протокол 11. Обычный агент даёт первую тему на языке пользователя в первом содержательном ходе, как только она определена, до выбора режима, Review и плана. Обсуждение без плана тоже получает имя. Команда открытия панели не является темой; фиктивный план не создаётся. Канонический SESSION_TITLE_RULE хранится в packages/workflow-kit/src/lib/role-protocol.mjs и используется startup/recovery/адресными инструкциями; PLAN ссылается на правило. E сохраняет task-имя.

## Вызов и принадлежность

`workflow_session_set_title(title)` виден модели. Python MCP передаёт отдельный action `sessionTitle` прежнего bridge (ui-mutation) → callback backend → PluginProjects → ProjectsService/WorkspaceSessions. Новый транспорт, модельный ход, bootstrap и панель не запускаются. Произвольные project/session ID и пути не принимаются: свежие host metadata проверяются через modelInput, enrollment и participantTarget. Выбор sidebar не определяет получателя.

Допустима только своя живая обычная Chat-сессия P/S/O/self без назначения E. Чужая, удалённая, архивная, отменённая или неподтверждённая привязка отклоняется. Сохранение идёт в существующей очереди мутаций; внутри неё повторно проверяются projectId, сессия и отмена. Смена выбранного проекта не перенаправляет запись, поздний вызов не воскрешает удалённую сессию. План, роль, project display name и разрешение выполнения не меняются.

## Имя и результат

Нормализатор sessionName сводит пробелы, оставляет до 80 Unicode-символов и 200 UTF-8 байт; пустое/нестроковое имя недопустимо. Источник хранится как `titleSource=topic`, отдельно от ручного имени. Приоритет: manual → scope → topic → page. Первый topic заменяет стартовый page/null; повтор того же или другого topic не меняет уже принятое имя. Опубликованный scope может штатно заменить topic; поздний page-title не возвращает техническое имя. Пользователь может переименовать сессию вручную.

Ответ после долговечной записи содержит фактические `title`, `titleSource`, `changed`; при отказе от замены — `reason=manual|scope|already-named`. У успешной первой записи changed=true. Повтор после утраты ответа идемпотентен. Ошибка записи не подтверждает успех. Лишние поля дают PLUGIN_SESSION_TITLE_INPUT, некорректное имя — PLUGIN_SESSION_TITLE_INVALID, неподходящая цель — PLUGIN_SESSION_TITLE_TARGET, неподтверждённое сохранение — PLUGIN_SESSION_TITLE_SAVE; ошибки существующей identity/записи сохраняют свой контракт.

Backend публикует общий snapshot/SSE: точная карточка обновляется и при выборе другого проекта. Topic переиспользует прежний ChatGPT-title sync для manual/scope. Если своей страницы сейчас нет, локальное имя уже сохранено, синхронизация проверяется при штатном открытии. Локальный ответ не доказывает удалённый PATCH; ошибка sync не отменяет topic и не повторяет q. Свежий результат синхронизации фиксируется отдельно.

## Совместимость и проверка

Нужен новый MCP snapshot с инструментом. При его отсутствии агент не заявляет о переименовании и не открывает панель/startup повторно ради имени. Обновление Kit не переустанавливает приложение и не обновляет уже открытый каталог ChatGPT автоматически.

Новая версия читает старые записи. Старый validator 0.5.35 при schema 8 не принимает topic: после его записи откат одного bundle недостаточен. [Условия восстановления данных](project-compatibility.md#данные-сессий-и-обратный-переход) и [поставка](release.md) различают bundle rollback и данные; профиль не очищается автоматически.

Проверки используют настоящий Python MCP/bridge, backend/store и Electron renderer: тема до плана, обсуждение без плана, соседний выбранный проект, ручное/scope-имя, повторы, Unicode/лимиты, отказ записи, чужая/архивная цель, restart и late page-title. Immutable validator 0.5.35 воспроизводит ограничение downgrade без рабочего профиля; immutable Kit 1.10.1 проверяет upgrade. [Живая приёмка](../acceptance/session-choice-and-delivery.md) остаётся за пользователем.
