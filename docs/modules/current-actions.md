# Текущие действия: одно место внимания

Контракт Workflow Pilot 0.6.0. Backend строит общую `workProgress`; основная MCP-панель использует `src/frontend/desktop/ui/current-actions.mjs` и общий [выбор пользователя](user-choice.md). Кнопка «Текущие действия», клиентский dialog и его IPC/preload/HTTP-путь удалены. Ролевые полномочия и внутренние S/P/O/E не меняются ради надписей. [Desktop](desktop.md), [панель](chatgpt-plugin.md), [тайминги](dialogue-timing.md).

## Распределение информации

[Постоянный SDK](sdk-messaging.md) не имеет mode/case/slots или кнопки включения. Панель показывает фактическую стадию сообщения: передачу, принятие ChatGPT, чтение или конкретную ошибку. Обычная занятость агента не означает ожидания отправки.

| Место | Содержание |
| --- | --- |
| Sidebar | Навигация по проектам/сессиям, нейтральная роль/индикатор агента; активный опубликованный план с задачами, прогрессом, одной кнопкой Start/Пауза/Продолжить; закрытая карточка без старого содержимого; штатный Review |
| Панель Workflow Pilot | Одна главная причина внимания или текущая операция, компактная независимая работа других участников, выбор, история, свёрнутая диагностика |
| ChatGPT Chat | Обсуждение и содержательные объяснения агента |

В дереве нет полного выбора, оранжевой фразы «ждёт вашего выбора», доплановой пустой карточки, постоянной startup-карточки или повторных стадий/раундов/таймеров. Слева остаются нейтральные состояния задач опубликованного плана, а не копия текущего процесса. Завершённый раунд Review не закрепляется уведомлением. Переключатель Review сохраняет собственное значение/блокировки; он отделён от карточки плана и динамического статуса.

Единственная кнопка исполнения находится в опубликованном плане слева. Полное сообщение справа объясняет, где её нажать; второй кнопки Start нет. Read-only вывод в панели без клиентского обработчика действия направляет к нужной сессии приложения.

## Роли, стадии и приоритет

`participantName` задаёт «Агент» для P/S/SELF, «Оркестратор» для O, «Исполнитель <task>» для E, «Рецензент» для Review. До специального назначения используется «Агент». После выбора orchestrated роль O меняется сразу, до публикации. «Планирование»/«Обсуждение» не используются как лицо, которое работает или ждёт. Отдельные названия «Планировщик»/«Собеседник» не назначаются по случайной реплике.

Общая проекция передаёт actor, stage, recipient, reason/action, устойчивый key/choiceId, elapsedMs и историю с ID. Полный пакет, ticket, q, chatUrl и raw metadata в preview не попадают. Приоритет: блокирующая причина → выбор пользователя → известная операция → обычное ожидание. Для независимых участников продолжающаяся работа и проблемы остаются компактно в том же разделе. Вторые обычные ожидания и суммарная строка того же выбора скрыты; один вопрос E не объявляет остановленным весь план.

| Наблюдаемый факт | Сообщение |
| --- | --- |
| Конкретная операция неизвестна, чат отвечает | Агент работает над ответом |
| Выбрана оркестрация, O готовит документы | Оркестратор готовит план |
| Review PREPARED | Ожидаем начала рецензирования |
| Review действительно RUNNING | Рецензирование плана · Claude · раунд N |
| План опубликован, Start ещё не был | План ждёт вашей проверки и запуска. Нажмите «Начать выполнение плана» слева |
| Recovery подготовки направлен O | Передаём запрос подготовки T001 оркестратору |
| Канал O не готов, запрос ещё pending | Восстанавливаем соединение с оркестратором |
| SDK принял сообщение, read ещё нет | Ожидаем, когда оркестратор получит сообщение |
| Result ещё передаётся | Результат T001 готов · передаём оркестратору |
| Result прочитан | Оркестратор получил результат · ожидаем решение |
| Выбор сохранён; чат O ещё занят | Выбор сохранён; SDK передаёт уведомление независимо от занятости чата |
| E ещё без task | Исполнитель T001 ожидает поручение оркестратора |
| MAIN_DIRTY | Точная причина, мешающие безопасные пути, действие Продолжить после устранения |

Стадия Review берётся из канонического состояния Kit своего проекта при sync/wait, даже если файловое уведомление пропущено и выбранный клиент ещё хранит IDLE. Общая фраза ответа не перекрывает известный раунд или рассмотрение замечаний. Чтение другого проекта не подставляет Review выбранного sidebar проекта. Метка task ID не меняет адресата. Read не объявляется недоставленностью или началом тестов. SDK/generation/lease/read/yield и gate доступны в диагностике.

Ожидаемые регистрация, передача и восстановление нейтральны, как и `owner-unavailable`, `freshness-reload`, отложенная перезагрузка и «ожидаем подтверждение конца хода»; черновик на серверной странице, «Серверная страница не готова к доставке» и ветвление (пауза плана) оранжевые с выполнимой инструкцией ([общий разговор](shared-conversation.md)). Проекция `blocker` берёт настоящее удерживающее сообщение участника, включая доплановый scope=null, независимо от incoming нового плана. Активный ответ и команда объясняют нормальное ожидание; manual Stop и неизвестный legacy-эффект требуют внимания и называют доступный шаг. Завершённый gate перестаёт быть текущей причиной; разрешение Start само его не сбрасывает.

## Выбор и история

`offered` — одна доступная оранжевая карточка с вопросом и вариантами; рекомендуемый первый. Сохранение в пути нейтрально, кнопки защищены от второго нажатия. Только долговечный receipt переводит решение в `chosen`: короткое нейтральное «Выбрано… · передаётся агенту», затем факт доставки. Прежний вопрос/варианты/большая рамка убираются.

Отказ записи сохраняет возможность выбрать с конкретной причиной и не вызывает действие/доставку. Принятый выбор с ошибкой эффекта или UNKNOWN не предлагается отправить заново. По подтверждённому read агентом выбор один раз переносится в историю; SDK accepted не подменяет read. Новая необходимая реакция получает новый оранжевый акцент и конкретный шаг. Цвет всегда дополнен текстом/значком.

История фильтруется по projectId/workspaceId/sessionId, а не имени/пути. SDK-попытки до и после плана имеют устойчивые message_id/attempt ID, фактическое время и безопасный код отказа. Сохранённое непрочитанное сообщение не получает отметку доставки. Восстановление нейтрально; исчерпанный отказ приоритетнее карточки выбранного режима и предлагает прочитать входящие. История дедуплицируется по устойчивому ID сообщения/выбора/старта. Даты берутся из сохранённых событий. Старым событиям без даты не придумывается текущее время; дата остаётся пустой. SSE/restart/другой клиент не создают новый успех и не сбрасывают выбор. Модель настроек действительно загружает сохранённые executionControl/userChoices вместе с остальным состоянием.

Review хранит ограниченную историю `review_events` в прежнем state.json Kit: изменение политики, подготовка пары, запрос запуска, положительное spawn, отзыв, позиция автора, ошибка/отмена/устаревание и публикация. Каждый факт имеет устойчивый ID и своё фактическое время. История остаётся после PUBLISHED, рестарта и очистки материалов; legacy review_history даёт только известные отзывы/позиции, без выдуманной передачи или даты. Подготовка пары не доказывает запуск Claude.

## Startup и адрес

`startupLaunch`/`startupContextState` согласуют текущую сохранённую сессию с исторической попыткой. Свой нормализованный постоянный URL, sent по текущему ticket/participant, account proof, совпадающий addressCandidate и отсутствие cancel/login loss/conflict сохраняют адрес даже при старом lost. Проверенное совпадающее наблюдение даёт confirmed; сохранённый адрес при ещё не наблюдаемой странице — saved. Один URL не удостоверяет identity и не объявляет чужой текущий документ своим.

Другой нормализованный текущий адрес даёт conflict и конкретное действие открыть сохранённый чат. Реальное отсутствие доказанного адреса, отмена или незавершённая передача остаются видимыми; последнего случайного `/c/...` недостаточно для перепривязки. Bind сохраняет chatUrl/addressStatus согласованно. Не повторяются q, startup и неизвестный Send.

Подготовка → передача → чтение N/M отображаются в текущей области. Долговечный startup.complete важнее старого delivery=pending; успех переходит в историю с устойчивым `startup:<message_id>`, подтверждённым временем или пустой датой для старой записи. Новое открытие не создаёт событие заново. Stale снимок — отдельный факт необходимости актуального контекста перед решением, а не потеря адреса и не разрешение нового q. Отмена, conflict и реальные ошибки приоритетнее исторического успеха как разрешения продолжать.

## Закрытая панель, native и HTTP

Полная карточка и текущая лента находятся в основной MCP-панели. Клиентского окна-копии, замены в меню и скрытия страницы ради него нет. В HTTP-клиенте без MCP iframe удалённый fallback выбора недоступен; новый вход не создаётся. Наличие SDK/lease само по себе не доказывает видимость iframe.

В исходных узлах sidebar остаются только необходимые операции подготовки/восстановления: session-notice с retry/cancel/observe/return и conversation-recovery с reconnect. Успешный startup постоянно не показывается. Оранжевая plan-attention и её действие в sidebar скрыты; основной запрос действия находится в MCP-панели. Штатные кнопки плана и необходимые самостоятельные операции восстановления сохранены.

Несколько панелей могут видеть один backend-выбор: CAS по project/session/choice ID/generation сохраняет ответ один раз. Переключение сессий не меняет адресата сохранённого решения. Работа без открытого окна и фоновая очередь сохраняются.

## Перенос, часы и доступность

Текст имеет min-width:0, normal wrapping, overflow-wrap:anywhere и автоматическую высоту. Для инструкций нет nowrap/ellipsis/clipping или обязательного tooltip. Значок и таймер — отдельные колонки; при ширине ≤480 px таймер переходит в собственную строку. Длинный русский текст и непрерывный ID читаются полностью без горизонтальной прокрутки.

Таймер отражает текущую наблюдаемую стадию: создание сообщения — очередь, send.report — accepted/ожидание read, message.read — обработка, сохранённый yield — ожидание физического конца. При отсутствии квитанции используется наблюдение backend; неизвестный elapsedMs пустой. Это не рассуждение модели, ETA или CPU-время. Исторические и клиентские часы не смешиваются.

Смысл строки и кнопки меняется только при семантическом изменении; секундный tick обновляет счётчик на месте. SSE не заменяет сфокусированные кнопки выбора, live-region объявляет переход состояния, не каждую секунду. Сохраняются клавиатура, доступные имена, видимый focus, темы, контраст и prefers-reduced-motion.

## Проверки

Семантику проверяют work-progress, panel-dialogue-view, workflow-channel, sidebar, user-choice-view, settings-workflow-state, user-choices и startup tests. `electron-smoke` запускает настоящий Chromium layout: 320/480/900 CSS px × light/dark × 100/200% текста, полные текст/инструкция/таймер, длинный ID и снимки. jsdom не доказывает перенос. Native/HTTP fixtures проверяют отсутствие кнопки и окна-копии; настоящий backend → Python MCP → HTML/SDK проверяет оба раунда Review и историю публикации. [Приёмка 0.5.35](../acceptance/release-0535-defects.md) и прежняя [D001–D011](../acceptance/release-0534-defects.md) сохраняют отдельный live/native статус.

## Подтверждённое действие пользователя

[Согласованная спецификация в Git](https://github.com/OleynikAleksandr/Workflow_Pilot/blob/7677f9fd8073f8b4b0a88e5c457f60c80666460d/docs/planning/attention-and-closed-plan.md).

executionIssue отделяет внутреннее ожидание, остановленную операцию и пользовательский шаг. READINESS_BUSY/READINESS_CHANGED/CONCURRENT_CHANGE/PROJECT_RECOVERY_REQUIRED показывают «Ожидаем завершения операции проекта», без технического «Повторите проверку». Исходная ошибка остаётся в состоянии Control для диагностики. Решение оркестратора и terminal receipt/cleanup нейтральны; отсутствие новых событий и длительность сами не создают оранжевый статус.

MAIN_DIRTY предлагает сохранить/зафиксировать свои изменения и нажать «Продолжить». Подтверждённый выход из аккаунта требует входа в указанной сессии. Исчерпанная SDK-доставка предлагает прочитать входящие в чате. Неизвестный отказ без безопасного пользовательского шага показывается как остановка с причиной, без обещания автоматического восстановления. Grant, Stop, неизвестный эффект и проверки Kit не ослабляются.

У активного выбора один оранжевый акцент; сохранённый выбор нейтрален. Дублирующая тревога в now/sidebar не показывается, независимые работающие участники видны. «Открыть чат» допустимо только с конкретным требуемым действием. Прежние полные проверки палитры/layout относятся к 0.5.40; причина отдельных предшествовавших smoke-тайм-аутов не установлена. В 0.5.41 адресные render-тесты проверяют пустую закрытую карточку: только «План закрыт» и готовность нового плана, Review/имя сессии сохранены. Проверки SDK охватывают нейтральное восстановление и исходный message_id; полный electron-smoke этого раунда не запускался. Живая приёмка 0.5.41 — NOT_RUN.
