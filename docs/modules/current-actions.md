# Текущие действия: одно место внимания

Контракт Workflow Pilot 0.5.34. Backend строит общую `workProgress`; MCP-панель и явная клиентская область используют один компонент `src/frontend/desktop/ui/current-actions.mjs` и общий [выбор пользователя](user-choice.md). Ролевые полномочия и внутренние S/P/O/E не меняются ради надписей. [Desktop](desktop.md), [панель](chatgpt-plugin.md), [тайминги](dialogue-timing.md).

## Распределение информации

| Место | Содержание |
| --- | --- |
| Sidebar | Навигация по проектам/сессиям, нейтральная роль/индикатор агента; только опубликованный настоящий план с задачами, прогрессом, одной кнопкой Start/Пауза/Продолжить; штатный Review |
| Панель Workflow Pilot | Одна главная причина внимания или текущая операция, компактная независимая работа других участников, выбор, история, свёрнутая диагностика |
| Клиентская область «Текущие действия» | То же представление выбранной сессии при явном открытии пользователем, доступно без работающего MCP iframe |
| ChatGPT Chat | Обсуждение и содержательные объяснения агента |

В дереве нет полного выбора, оранжевой фразы «ждёт вашего выбора», доплановой пустой карточки, постоянной startup-карточки или повторных стадий/раундов/таймеров. Слева остаются нейтральные состояния задач опубликованного плана, а не копия текущего процесса. Завершённый раунд Review не закрепляется уведомлением. Переключатель Review сохраняет собственное значение/блокировки; он отделён от карточки плана и динамического статуса.

Единственная кнопка исполнения находится в опубликованном плане слева. Полное сообщение справа объясняет, где её нажать; второй кнопки Start нет. Read-only вывод в панели без клиентского обработчика действия направляет к нужной сессии приложения.

## Роли, стадии и приоритет

`participantName` задаёт «Агент» для P/S/SELF, «Оркестратор» для O, «Исполнитель <task>» для E, «Рецензент» для Review. До специального назначения используется «Агент». После выбора orchestrated роль O меняется сразу, до публикации. «Планирование»/«Обсуждение» не используются как лицо, которое работает или ждёт. Отдельные названия «Планировщик»/«Собеседник» не назначаются по случайной реплике.

Общая проекция передаёт actor, stage, recipient, reason/action, устойчивый key/choiceId, elapsedMs и историю с ID. Полный пакет, ticket, q, chatUrl и raw metadata в preview не попадают. Приоритет: блокирующая причина → выбор пользователя → известная операция → обычное ожидание. Для независимых участников продолжающаяся работа и проблемы остаются компактно в том же разделе. Вторые обычные ожидания и суммарная строка того же выбора скрыты; один вопрос E не объявляет остановленным весь план.

| Наблюдаемый факт | Сообщение |
| --- | --- |
| Конкретная операция неизвестна, чат отвечает | Агент работает над ответом |
| Выбрана оркестрация, O готовит документы | Оркестратор готовит план |
| Review PREPARED | Ожидаем начала рецензирования |
| Review действительно RUNNING | Рецензирование плана · Claude · раунд N |
| План опубликован, Start ещё не был | План ждёт вашей проверки и запуска. Нажмите «Начать выполнение плана» слева |
| Recovery подготовки направлен O | Запрос подготовки T001 ожидает доставки оркестратору |
| Канал O не готов, запрос ещё pending | Канал оркестратора восстанавливается; запрос T001 ещё не доставлен |
| SDK принял сообщение | Хост принял сообщение для конкретного получателя; чтение ещё не подтверждено |
| E ещё без task | Исполнитель T001 ожидает поручение оркестратора |
| MAIN_DIRTY | Точная причина, мешающие безопасные пути, действие Продолжить после устранения |

Стадия Review берётся из его собственного состояния/run/round. Чтение снимка другого проекта не подставляет Review выбранного sidebar проекта. Метка task ID не меняет реального адресата сообщения. SDK accepted сохраняет смысл даже при последующей потере lease: принятое сообщение не называется недоставленным запросом подготовки.

## Выбор и история

`offered` — одна доступная оранжевая карточка с вопросом и вариантами; рекомендуемый первый. Сохранение в пути нейтрально, кнопки защищены от второго нажатия. Только долговечный receipt переводит решение в `chosen`: короткое нейтральное «Выбрано… · передаётся агенту», затем факт доставки. Прежний вопрос/варианты/большая рамка убираются.

Отказ записи сохраняет возможность выбрать с конкретной причиной и не вызывает действие/доставку. Принятый выбор с ошибкой эффекта или UNKNOWN не предлагается отправить заново. По подтверждённому read агентом выбор один раз переносится в историю; SDK accepted не подменяет read. Новая необходимая реакция получает новый оранжевый акцент и конкретный шаг. Цвет всегда дополнен текстом/значком.

История дедуплицируется по устойчивому ID сообщения/выбора/старта. Даты берутся из сохранённых событий. Старым событиям без даты не придумывается текущее время; дата остаётся пустой. SSE/restart/другой клиент не создают новый успех и не сбрасывают выбор. Модель настроек действительно загружает сохранённые executionControl/userChoices вместе с остальным состоянием.

## Startup и адрес

`startupLaunch`/`startupContextState` согласуют текущую сохранённую сессию с исторической попыткой. Свой нормализованный постоянный URL, sent по текущему ticket/participant, account proof, совпадающий addressCandidate и отсутствие cancel/login loss/conflict сохраняют адрес даже при старом lost. Проверенное совпадающее наблюдение даёт confirmed; сохранённый адрес при ещё не наблюдаемой странице — saved. Один URL не удостоверяет identity и не объявляет чужой текущий документ своим.

Другой нормализованный текущий адрес даёт conflict и конкретное действие открыть сохранённый чат. Реальное отсутствие доказанного адреса, отмена или незавершённая передача остаются видимыми; последнего случайного `/c/...` недостаточно для перепривязки. Bind сохраняет chatUrl/addressStatus согласованно. Не повторяются q, startup и неизвестный Send.

Подготовка → передача → чтение N/M отображаются в текущей области. Долговечный startup.complete важнее старого delivery=pending; успех переходит в историю с устойчивым `startup:<message_id>`, подтверждённым временем или пустой датой для старой записи. Новое открытие не создаёт событие заново. Stale снимок — отдельный факт необходимости актуального контекста перед решением, а не потеря адреса и не разрешение нового q. Отмена, conflict и реальные ошибки приоритетнее исторического успеха как разрешения продолжать.

## Закрытая панель, native и HTTP

Нейтральный переход «Текущие действия» открывает общую клиентскую область выбранной сессии. Переход не дублирует вопрос/варианты/оранжевый статус и не вызывает модель. Наличие SDK/lease не является доказательством видимости iframe, поэтому переключение явное.

`pilot:current-actions` — фиксированный канал представления, обслуживаемый клиентом после проверки своего webContents/main frame. Он не меняет backend и не выдаёт lease. Во встроенном окне живой WebContentsView временно отсоединяется в штатный host, sidebar расширяется для области; закрытие возвращает **тот же документ** без новой навигации. В in-process smoke работает соответствующий suspend. HTTP-клиент скрывает изображение страницы и расширяет UI iframe; закрытие восстанавливает представление. Reload/pagehide сбрасывает только состояние представления.

Одновременно в одном окне видна одна полная интерактивная карточка. Несколько окон могут видеть один backend-выбор: CAS по project/session/choice ID/generation сохраняет ответ один раз. Отдельной книги решений или нового разрешения у клиентской области нет. Переключение сессий и неподключённая/закрытая панель не оставляют чужой выбор. При внешнем разговоре, которому нельзя создать backend-страницу, сохраняется пояснение даже при другом активном процессе проекта.

## Перенос, часы и доступность

Текст имеет min-width:0, normal wrapping, overflow-wrap:anywhere и автоматическую высоту. Для инструкций нет nowrap/ellipsis/clipping или обязательного tooltip. Значок и таймер — отдельные колонки; при ширине ≤480 px таймер переходит в собственную строку. Длинный русский текст и непрерывный ID читаются полностью без горизонтальной прокрутки.

Таймер отражает текущую наблюдаемую стадию: создание сообщения — очередь, send.report — accepted/ожидание read, message.read — обработка, сохранённый yield — ожидание физического конца. При отсутствии квитанции используется наблюдение backend; неизвестный elapsedMs пустой. Это не рассуждение модели, ETA или CPU-время. Исторические и клиентские часы не смешиваются.

Смысл строки и кнопки меняется только при семантическом изменении; секундный tick обновляет счётчик на месте. SSE не заменяет сфокусированные кнопки выбора, live-region объявляет переход состояния, не каждую секунду. Сохраняются клавиатура, доступные имена, видимый focus, темы, контраст и prefers-reduced-motion.

## Проверки

Семантику проверяют work-progress, panel-dialogue-view, sidebar, user-choice-view, settings-workflow-state, user-choices и startup tests. `electron-smoke` запускает настоящий Chromium layout: 320/480/900 CSS px × light/dark × 100/200% текста, геометрия текста/таймера, длинный ID и снимки. jsdom не доказывает перенос. Native smoke проверяет возврат того же documentId, HTTP fixture — доступ без MCP iframe, скрытие и возврат страницы. [D001–D011](../acceptance/release-0534-defects.md) сохраняет отдельную живую приёмку ChatGPT, macOS-окон/assistive technology, native Windows/Linux и iPad/Tailscale.
