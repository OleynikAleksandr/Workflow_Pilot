# Встроенное окно

С 0.5.0 на macOS и с 0.5.1 на всех трёх ОС (macOS, Windows, Linux) обычный запуск открывает встроенное окно фоновой службы: родной сайдбар и настоящая страница ChatGPT (WebContentsView Chromium) в одном окне, без передачи кадров через HTTP. Ввод, буфер обмена, меню правой кнопки, перетаскивание файлов и вставка картинок работают средствами Chromium. Служба по-прежнему владеет страницами и работой ([Backend](backend.md)); закрытие окна не останавливает страницы, наблюдателей, выполнение планов, Review, MCP и туннель.

Выпуски трёх ОС одинаковы по интерфейсу. HTTP-клиент ([Desktop-клиент](desktop.md)) остаётся для проверки, для iPad ([удалённый доступ](remote-access.md)) и для будущей службы без экрана (VPS); на всех ОС он открывается пунктом «Окно через HTTP (тест)» в меню значка и в меню встроенного окна; переключателя режима в Настройках и отдельного ярлыка нет.

## Страницы службы: режимы

- `BackendBrowserHost` создаёт страницы в режиме, выбранном при старте службы: `view` во всех выпусках (Linux-выпуск и так требует сеанс X11 с DISPLAY, [Linux](linux.md)). `offscreen` — режим службы без экрана (этап VPS); сейчас его выбирает только флаг разработки `--backend-page-mode=offscreen` (packaged-сборка флаг игнорирует). Режим не меняется во время работы: offscreen задаётся при создании webContents.
- В режиме `view` страница — WebContentsView с прежними webPreferences (partition, preload наблюдателя, sandbox, `backgroundThrottling: false`). Пока окно её не показывает, она находится в скрытом окне-хосте (BaseWindow без собственной страницы, не на экране, без фокуса и без кнопки на панели задач).
- `attach(id, container, bounds)` переносит страницу в контейнер окна, `detach(id)` — обратно в окно-хост; страница не перезагружается, CDP-подключение и перехват выбора файлов сохраняются. В одном окне показывается одна страница. Адрес — id страницы или browserSessionId.
- Кадры для HTTP-зрителей в режиме `view` снимаются через CDP `Page.captureScreenshot`: у страницы в окне-хосте нет поверхности экрана, capturePage отвечает «Current display surface not available for capture». В режиме `offscreen` — capturePage по событиям paint. Popup-окна авторизации остаются скрытыми окнами службы.

## Окно

- Встроенное окно — тот же модуль клиента (`frontend/desktop/client.mjs`, режим `embedded`), который точка входа `src/main.mjs` передаёт службе фабрикой `nativeWindow`; служба не импортирует код frontend. Окно подключается к API службы по loopback со своим clientId (`native-…`): тот же allowlist каналов, журнал операций до эффекта и lease. Вместо кадров оно прикрепляет WebContentsView выбранной страницы справа от сайдбара.
- Встроенное окно и HTTP-клиент работают одновременно: пишет держатель lease, другой наблюдает или забирает управление («Взять управление»). Архив, цвета и выбор файла открываются у окна-инициатора; выбор файла и загрузки встроенного окна идут через зрителя без кадров.
- Меню правой кнопки страницы — системное: вырезать, копировать, вставить, выделить всё.
- Закрытие окна (кнопка, Cmd+W, Cmd+Q в меню окна, «Завершить» на плитке Dock) закрывает только окно: страница возвращается в окно-хост, lease освобождается, каналы окна снимаются. Остановка службы — из меню значка («Остановить фоновую службу…») или меню окна; сигналы ОС (выход из системы) останавливают службу штатно.
- macOS: пока окно открыто, у службы есть плитка Dock и меню приложения (activation policy `regular`); после закрытия служба снова без плитки (`accessory`). Windows и Linux: окно со своим меню и кнопкой на панели задач, служба без окна видна значком в трее (где трей есть). Окно, открытое фоновым процессом, выводится вперёд явно.

Отдельный пункт «Принудительно остановить службу…» в меню окна и значка требует подтверждения и обходит ожидание безопасной точки. Встроенное окно вызывает собственный backend напрямую; HTTP-клиент передаёт подтверждённую операцию через lease. Подробности и ограничения — [остановка службы](backend-shutdown.md).

## Текущие действия

С 0.5.34 нейтральный переход открывает [общую клиентскую область](current-actions.md) без модели и работающего MCP iframe. Native временно отсоединяет WebContentsView выбранной страницы в штатный host и расширяет UI; закрытие dialog возвращает тот же documentId без навигации. Канал pilot:current-actions отвечает только за представление и не выдаёт lease/разрешение. Выбор сохраняется тем же backend CAS; в одном окне одна полная карточка. Это проверено скрытым renderer smoke, не живыми окнами пользователя.

## Запуск

- Обычный запуск на любой ОС (Finder, Dock, Spotlight, меню «Пуск», ярлык, повторный запуск) — короткий процесс клиента: он запускает службу, если она не работает, вызывает операцию `window.open` и завершается. Работающая служба на `window.open`, activate и пункт значка «Открыть Workflow Pilot» показывает своё окно или выводит его вперёд.
- `window.open` — класс операций `window`: без lease и журнала (показ, а не работа), с удалённого устройства запрещена (`REMOTE_LOCAL_ONLY`). Служба другой версии (например, 0.4.x, запущенная до установки) или без встроенного окна получает прежнее окно клиента с объяснением.
- «Окно через HTTP (тест)» запускает клиент с флагом `--http-client`. Fixture-клиенты (`--client-fixture`) остаются окнами клиента; путь запуска в fixtures включает `--client-launcher`.
- Выбор «Фоновая служба: на этом компьютере / удалённая (адрес)» и служба без экрана относятся к этапу VPS.

## Проверка

`tests/backend-native-pages.test.mjs` — страницы `view` и `offscreen` на настоящей fixture-службе (таймеры в окне-хосте, кадры, ввод, перенос без перезагрузки). `tests/backend-native-window.test.mjs` — встроенное окно (состояние, lease, страница, закрытие и повторное открытие), процесс запуска, `window.open` без lease и отказ удалённому устройству, встроенное окно вместе с процессом HTTP-клиента. Полный тест представления (`browser-presentation`) идёт в режиме `view`. Fixture-окна скрыты и не берут фокус.

Ограничения: popup-окна авторизации во встроенном режиме показываются как окна клиента с кадрами; при открытых встроенном окне и HTTP-клиенте в Dock (панели задач) две кнопки. Автоматические проверки идут на macOS; встроенное окно на Windows и Linux проверено только этими fixtures, не нативно. Живая приёмка — [сценарий](../acceptance/backend-independence.md).
