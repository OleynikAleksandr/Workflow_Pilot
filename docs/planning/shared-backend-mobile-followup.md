# Отложено: мобильные клиенты, клиентский API и серверное размещение

Невыпущенные требования после выпуска 0.6.0 ([серверная доставка на Mac](../modules/shared-conversation.md)). Решение пользователя 29.10.2026: сначала Mac; мобильные устройства проверяются через ChatGPT Web в браузере и адаптируются позже. Каждый пункт ниже получает собственную спецификацию и план после отдельного поручения.

## Принятое направление (сохраняется)

- Общий постоянно работающий backend управляет проектами, планом, инструментами, автоматизацией и серверными страницами ChatGPT; пользовательские приложения — клиенты.
- Приложения iOS/iPadOS и Android открывают тот же настоящий разговор напрямую у OpenAI в собственном WebView (WKWebView / Android WebView), без кадров с компьютера, проксирования HTML ChatGPT и внедрения панелей в DOM ChatGPT. Мобильные Safari/Chrome не заменяют проверку WebView.
- Закрытие или выгрузка клиента не останавливает серверную работу. Исполнители — обычные ChatGPT Chat.

## 1 Клиентский API v2 и независимый выбор

- Сейчас выбор сессии и создание сессии меняют общий выбор store и навигацию встроенного окна (`pilot:new-session`, `src/backend/desktop-model.mjs:1466–1476`); веб-UI работает через v1 `ui.invoke` с глобальным lease (`src/frontend/client/connection.mjs:83–115`).
- Нужно: пространство имён `client.*`, регистрация `clientInstanceId`, права устройства (`operate`/`observe`/`admin`), клиентское состояние выбора, создание/открытие сессии без смены общего выбора, `client.operations.get` — состояние операции по ключу между boot (сейчас повтор `requestId` возвращает только прежнюю запись, после restart — `unknown`, `src/backend/protocol.mjs:117–123`), события `session.target`, `participant.delivery`, `server-page.attention`, класс `presence` без lease. Lease v1 остаётся правом общей серверной страницы и v1-изменений.
- Прямой удалённый desktop-клиент (своя страница ChatGPT, панель-наблюдатель) обязателен в этой ветке (АР: удалённые desktop-клиенты загружают разговор напрямую).

## 2 Мобильные оболочки

- Две области: наш UI (существующий `src/frontend/desktop/ui` через шлюз в режиме `direct`, мост на v2) и ChatGPT WebView без наших скриптов, мостов и подмены User-Agent; внешние ссылки — в системный браузер; узкий мост только в нашей области (open-session, presence, external-link).
- Хранилище: отдельный `WKWebsiteDataStore` для нашей области на iOS; изоляция cookie-хранилища Android проверяется. Адрес backend не секрет; токен устройства — cookie нашей области.
- Подключение: Tailscale на устройстве с тем же владельцем tailnet (шлюз проверяет `Tailscale-User-Login`; iOS — одна активная VPN), пара по коду с подтверждением на компьютере.
- Проверить на реальных устройствах: способы входа OpenAI (email/пароль, Apple, Google, passkey, SSO — доступные аккаунту; запрет провайдера — NOT_AVAILABLE без обхода), анти-бот/«неподдерживаемый браузер», отображение iframe панели, клавиатура, вложения, внешние ссылки, фон/выгрузка, поворот; различимость исходов «нет доступа / не найден / нет коннектора» без DOM.
- Порядок: iOS/iPadOS, затем Android; итог PASS/FAIL/INCONCLUSIVE/NOT_AVAILABLE по каждой платформе отдельно.

## 3 Эксплуатация

- Автозапуск backend при входе в систему и перезапуск после падения (Mac LaunchAgent, Windows Run entry, Linux `systemd --user`) по явному включению: сейчас LaunchAgent есть только у MCP-исполнителя (`src/execution/runtime/service.mjs`), backend запускает клиент.
- Linux-сервер без экрана: среда Chromium (Xvfb + `view` или `offscreen`), первичное доверие устройства без локального экрана (сейчас подтверждение только на компьютере), Tailscale/Serve на сервере, административный доступ для входа OpenAI (кандидат — кадры только для устройства `admin` и страниц «требуется вход»), проверка ChatGPT search extension и q/ticket bootstrap, сверка условий OpenAI для серверной автоматизации. Серверная конфигурация VPS остаётся вне scope без отдельного поручения (AGENTS.md).
- Публичный адрес backend (вне tailnet) — отдельное решение с моделью угроз.
