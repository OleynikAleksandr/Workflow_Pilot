# Диалог O/E: результаты, интеграция и переход

Обязательная третья часть [спецификации](orchestrator-owned-dialogue.md) и [контракта надёжности](orchestrator-owned-dialogue-reliability.md), scope `orchestrator-owned-dialogue-refactor`.

## Обязательный результат исполнителя

После подтверждённого commit --task E отправляет O result: изменения, фактические проверки/ограничения, полный source_commit, proof ID Kit, excluded_changes и артефакты. Ошибка проверок/неподтверждённый commit требуют вопроса или блокировки. Финальный текст E не заменяет канал.

Backend проверяет назначение/попытку/proof. O читает отчёт, проверяет diff инструментами и посылает revision_request либо acceptance по result_id и точному SHA. При недоступном канале E сохраняет отчёт в ожидании; backend не сочиняет его по коммиту.

## Приёмка и доработка

Acceptance относится к конкретной версии; изменённый worktree, активная команда/transaction или новый SHA запрещают прежнюю приёмку.

До интеграции O открывает revision_request: Kit сохраняет неизменяемые result/commit/checks, отзывает acceptance и создаёт новую попытку той же задачи/worktree. Main ещё не DONE. Это штатный переход с allowlist E, recovery, журналом и provenance, а не повтор завершённого task:start или ручная правка DONE. Новая попытка требует новых проверок/коммита/result/acceptance.

Переход разрешён только при безопасном worktree без pending integration. E не принимает себя и не завершает main. После интеграции нужна новая задача через расширение плана.

## Интеграция

Kit хранит acceptance по result_id/source_commit/attempt. O вызывает integration:start/continue; новый режим отвергает merge без актуальной приёмки, scheduler не сливает по одному READY. Новый SHA требует новой acceptance; неизменная операция после сбоя продолжается с тем же operation_id. Существующий Kit сериализует main.

Конфликт/check failure возвращается O с operation_id и сохранённым MERGE_HEAD. O исправляет разрешённые пути текущей операции или адресно организует ремонт, затем штатный repair/continue; принудительный ours/theirs запрещён. До назначения, затрагивающего занятый main, текущая интеграция должна быть разрешена или безопасно завершена.

Только Kit подтверждает INTEGRATED/DONE. Проверка независимых результатов допускает любой порядок, слияния последовательны. Зависимая задача получает поручение после интеграции предшественников. Поздняя коррекция не переписывает старые доказательства.

## Завершение плана

После обычных интеграций O адресно поручает DOCS с итогами; после DOCS выполняет delivery/cleanup, проверяет main и сообщает итог пользователю. Backend закрывает разрешение только после всех DONE, финальной обработки O и разрешения оставшихся сообщений. Пустая очередь не означает завершение; последний result/ответ не должен быть отрезан.

Канонические роли — `packages/workflow-kit/src/lib/role-protocol.mjs`; startup/recovery/шаблоны/MCP/messages/backend validation согласованы. Обновление открытого чата не повторяет task:start. Несовместимость запрещает поручение по старому протоколу.

## Совместимость и переход

Новый диалог получает явную версию capability в состоянии плана/назначения, Kit, backend, панели и MCP. Новые orchestrated-планы после обновления используют новый контракт. Старые sequential/parallel и legacy эксперимент сохраняют свой маршрут и доказательства; не переключать их молча по текущему флагу UI. Сохранить внешние DOM exports и Review-процесс.

Активный orchestrated scope 0.5.7 не переотправляет recovery/assignment-start и не мигрирует автоматически в середине хода. Поддержать штатную адресную миграцию при паузе и безопасной точке: сверить все назначения/коммиты/операции, записать версию, отправить через канал обновление правил O/E без повторения работы и продолжить после общего Continue. Пока есть занятый/неопределённый ход, миграция ждёт или возвращает точную причину; штатное удаление всё равно доступно.

Для уже готового E: после безопасного подключения O получает service-факт «есть результат без отчёта», затем просит E по каналу сформировать result по существующему коммиту. Backend не выдаёт собственный текст за отчёт E и не повторяет commit. Для уже интегрированных задач новые result/acceptance не требуются. Исторические UNKNOWN не отправляются заново и не подделываются read/DONE; переход требует установленного исхода либо адресного отказа, не общего сброса журнала.

Установленный Kit обновляется только installer, источники — packages/workflow-kit. Зафиксировать совместимый следующий номер Kit и протокол; проверить upgrade текущего и предыдущего комплекта. Несовместимость должна давать предметный код до запуска или эффекта, без ручного join. Рабочий опыт Test_02 не изменять в разработке; миграция проверяется на его обезличенной форме в fixtures, живой опыт — только по поручению пользователя.
