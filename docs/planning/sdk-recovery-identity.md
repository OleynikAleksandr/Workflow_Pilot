# Восстановление SDK-доставки и идентичность workspace

## Результат и основание

27.10.2026 пользователь поручил согласовать и полностью выполнить исправления с выпуском macOS/Windows/Linux, установкой на Mac и публикацией GitHub. Выпуск 0.5.38 состоялся, но живая приёмка не пройдена: уведомление Review получило SDK_ERROR примерно через 2,1 секунды, UNKNOWN навсегда удержал последующий выбор оркестрации. История повторно созданного workspace содержала события удалённой сессии из той же папки. Первопричина исключения SDK неизвестна: прежний catch удалял детали. Не объявлять её исправленной без новых свидетельств.

Цель: временный сбой SDK-уведомления восстанавливается без нового выбора пользователя, повторного поручения, двойного применения решения или интеграции. История, разрешения и доставка принадлежат конкретным идентификаторам. SDK остаётся единственным рабочим отправителем O/E/приложения; ChatGPT определяет очередность обработки. Не возвращать DOM-send, ожидание busy/idle, режимы эксперимента или внешние активирующие скрипты.

## Идентичность

Существующий projectId (Kit project_id) обозначает проект. Отдельный сохраняемый случайный workspaceId обозначает конкретную рабочую копию/запись workspace; Git worktree одного проекта имеет собственный workspaceId. sessionId обозначает разговор. Имя и путь — атрибуты и способы найти запись, но не доказательство владения. Совпадение имён либо повторное использование пути не связывает записи. Простое переименование сохраняет идентификаторы; удаление и новое создание порождают новую идентичность workspace, даже при том же имени/пути.

Миграция существующего store атомарно присваивает отсутствующий workspaceId, сохраняет projectId/sessionId и текущие планы. После повторного открытия ID не меняется. Уникальность workspaceId проверяется. Новые события выбора/истории содержат projectId, workspaceId, sessionId. История панели фильтруется по доказанной принадлежности текущему workspace и его сессиям; путь не является фильтром авторизации. Legacy-запись допустима только при точном совпадении живого sessionId и отсутствии противоречащего projectId/workspaceId; записи удалённой сессии не присваиваются новой по имени/пути. При удалении очищаются связанные choices/keys/manual/history, соседние записи сохраняются.

Проверить использование идентичности в store, snapshot/API, получателе плагина, choices, history и cleanup. Добавить workspaceId в адресный контракт там, где определяется владение рабочей копией; сверять его при claim/read/recovery, сохраняя остальные проверки project/scope/session/assignment/attempt. Старый WAL дополняется только по существующей однозначной сессии с совпадающей identity проекта; без доказательства — явный отказ. Не переименовывать все IO-параметры workspace: путь по-прежнему нужен файловой системе.

## Доставка и восстановление

Поручение и уведомление различны: текст и message_id долговечно сохраняются один раз; SDK несёт только ссылку на чтение. Повтор уведомления не создаёт новое поручение, назначение или новый пользовательский выбор. В текущем канале сохранить журнал отдельных попыток уведомления (attempt ID, исход, разрешение, время). Поздний ответ относится к своей попытке и не переписывает новую. Один реально активный SDK-вызов на адресата; две панели не создают второй sender. Исторический UNKNOWN не является вечным общим замком.

Ровно один вызов на attempt сохраняется. Допускаются максимум три автоматические попытки уведомления одного message_id, с ограниченной задержкой после сбоя (например 2 и 5 секунд), без ожидания окончания работы агента. Сроки обслуживает существующий wait/sync, не новый фоновый scheduler. Новые допустимые сообщения не удерживаются из-за завершившейся неудачной попытки другого сообщения. После лимита сохраняется понятная ошибка конкретного сообщения; нет бесконечного polling/retry. Reconnect/restart не обнуляет число попыток. Ручные Stop/Пауза, отмена, identity/grant/stale/version/store ошибки не обходятся. Рабочие сообщения не получают grant до Start.

Различать локальную ошибку до вызова SDK, явный отказ хоста, временное исключение и неизвестный исход после вызова. Автовосстановление распространяется только на уведомления с сохранённым message_id и новым контрактом защиты повторного выполнения. Не повторять прежний прямой DOM/URL/legacy Send неизвестного исхода. Старые SDK-уведомления разрешено перевести на новый контракт лишь после проверки адресата и формата; иначе отобразить конкретное ограничение. UNKNOWN остаётся фактом истории попытки; подтверждённое адресное чтение прекращает повторные уведомления и освобождает дальнейшую доставку, не объявляя SDK accepted или DONE.

Адресный read возвращает актуальные идентификаторы других непрочитанных входящих этого получателя, включая UI-события до плана, с проверками актуальности и роли. Это не выбор момента работы агента: один полученный SDK-сигнал позволяет забрать накопленные данные. Устаревшие версии Review/выбора не применяются; каноническое состояние Kit проверяется перед действием.

Защита повторного выполнения не сводится к просьбе в тексте. Чтение, обработка, result, acceptance SHA и интеграция остаются разными фактами. Повторное чтение обработанного message_id возвращает явный признак уже обработанного события и запрещает повтор эффекта; незавершённая обработка возобновляется по каноническому Kit-состоянию. Существующие idempotency keys и receipts операций используются повторно; новые уведомления не повторяют task:start/создание назначения/интеграцию. Для UI сохраняется уже применённое решение, повторная доставка не повторяет act. При невозможности доказать исход реальной операции сохраняется адресная блокировка этой операции, а не фиктивное DONE или глобальная остановка транспорта. Не обещать exactly-once произвольных внешних команд модели.

## Диагностика и интерфейс

Сохранять ограниченные структурированные сведения об SDK-исключении: стадия, тип/код, очищенное сообщение, время, message_id/attempt; без body, токенов, enrollment, URL query и raw host metadata. Проверять формат и размер на backend. Принятие host capability не доказывает успешную отправку. Точный исход прежнего SDK_ERROR восстановить задним числом невозможно.

Единое представление ошибки действует до и после публикации плана. Во время автоматического восстановления — нейтральное сообщение; после исчерпания попыток — конкретная причина и требуемое действие. Не писать бесконечно «передаётся», когда передач нет. Ошибка не прячется за карточкой сохранённого выбора. Не добавлять вторую панель действий или новые режимные переключатели. История содержит попытки/восстановление без ложной отметки доставки.

## Проверки

1. На fixture кнопка Review → исключение SDK → кнопка оркестрации: выбор сохранён один раз, последующая доставка и чтение разрешены; агент получает актуальные решения. Первая ошибка не удерживает получателя навсегда.
2. SDK принял уведомление, ответ потерян; повтор/поздний ответ/две панели/restart: одно поручение, адресные receipts и отсутствие двойного эффекта. Read во время retry прекращает дальнейшие attempts; обработанное не выполняется заново. Одинаковые ID с чужой identity не принимаются.
3. Stop/grant/смена scope/отмена во время retry предотвращают отправку. Retry budget сохраняется; SDK постоянно недоступен — явная ограниченная ошибка, не вечный цикл.
4. Три параллельных результата, двусторонние уточнения, зависимая задача, DOCS/acceptance точных SHA/интеграции/cleanup/complete проходят существующий общий путь. Сбой одного уведомления не меняет зависимости задач.
5. Два одинаковых имени, повторное использование пути, удаление/создание, restart миграции и worktree с общим projectId: различимые workspaceId и изолированная история, разрешения и доставка. Старая сессия не может подтвердить новый выбор.
6. Реальный закреплённый SDK в изолированном host fixture: JSON-RPC error, isError, timeout, поздний Promise. Проверить очищенную диагностику и правильный UI через существующий renderer fixture. Это не живая приёмка ChatGPT.
7. Полные unit-all/architecture, electron-smoke, executor-channel/codex-tools-live, kit-check И kit-assignments, kit-upgrade. Проверки не ослаблять; прежние assertions вечного UNKNOWN-барьера заменить новыми инвариантами с отдельными отказами. Python без bytecode, cache preflight перед production/package проверками.

## Поставка

Новая свободная возрастающая версия, согласованные app/panel/protocol и role/Kit при изменении контракта. Старые iframe не получают новый контракт молча. До сборки DOCS переносит рабочие правила в модули и удаляет эту временную спецификацию с точной Git blob ссылкой для recovery. Три ОС из одного закоммиченного sourceCommit; manifest, семь assets, размеры/SHA/состав и macOS подпись проверяются. Штатная установка готового bundle в /Applications и собственный checkout; при работающей службе — verified pending, без остановки и перезапуска пользователем не санкционированной службы. GitHub tag/draft/assets/publication/remote проверяются отдельно. Native Windows/Linux и живая новая ChatGPT-приёмка отмечаются NOT_RUN. Donor и пользовательский тестовый профиль не менять. Старую 0.5.38 сохранять для сравнения/отката.
