## 11. Критерии приёмки и проверки

Изолированные тесты подтверждают собственную логику. Живые проверки ChatGPT выполняет пользователь в штатном Electron; они не заменяются mocks и пока не выполнены.

- [ ] Только Chat: нет выбора/создания/подключения Work через UI, backend или MCP; старые Work-записи сохраняются без автоисполнения, миграция повторяема и не портит назначения. Внутренние workflow/worktree не затронуты.
- [ ] Первоначальная загрузка корня без `q`, вход и пустой черновик подтверждены на нужном documentId. Наблюдение старого чата не разрешает bootstrap; выход и unknown блокируют его.
- [ ] В Electron отправляется ровно предусмотренная короткая команда с действительным тикетом. Пользовательский черновик не теряется и не добавляется; отдельно проверено восстановление черновика после загрузки.
- [ ] Контекст и попытка сохранены до отправки. Формат тикета, TTL, identity и идемпотентность сохранены; новый тикет не считается отзывом старого.
- [ ] Порт передаёт фактический URL/isMainFrame для in-page, полной навигации и redirect. Проверены кратковременный redirect в Work, iframe, дубли, поздние события и release. Последующий `/c/…` не стирает нарушение.
- [ ] Регистрация текущего тикета выставляет `sent` без deliver/DOM-поиска сообщения. URL и прежний участник этого не делают. Прогресс контекста виден до постоянного адреса; оба порядка событий работают.
- [ ] Две параллельные сессии, переключение карточек, чужой URL и старая панель не смешивают адрес, identity и контекст.
- [ ] Отзыв по ticket_hash сохраняется в WAL, повторяем и работает после рестарта. Проверены ошибка записи, потерянный ответ и оба порядка гонки enroll/revoke. После выигрыша enroll отзыв не считается удалением участника или разрешением перепривязки.
- [ ] Отмена между записями двух хранилищ восстанавливается. До её завершения новый запуск заблокирован; поздний вызов не выдаёт отменённый контекст и не оживляет попытку.
- [ ] Собственная навигация отменяет только продолжение контроллера; новый tick не повторяет q, T1/T2 не сбрасываются.
- [ ] Runtime запрещает reload с q даже без данных о попытке: crash, ручное обновление, пустое q, эквивалентный loadURL. Чистая точка входа не считается новой отправкой; control отдельно восстанавливает только подтверждённый chatUrl.
- [ ] Падение до исчезновения q, потеря адреса и поздняя регистрация не соединяют два разных разговора. Зафиксировано фактическое удаление q браузером; защита от него не зависит.
- [ ] Все части контекста и SHA проверяются; неполный ack/чужой получатель отклоняются. Потерянный ответ не создаёт дубликат или ложную готовность. Подтверждение контекста не запускает план.
- [ ] Истёкший/отозванный тикет, BINDING, IDENTITY_REQUIRED и отсутствие startup_context дают понятную причину без выдуманного успеха или обхода подтверждений.
- [ ] Повторное открытие Chat не отправляет bootstrap. Диагностика разделяет загрузку, адрес, регистрацию, контекст и не раскрывает q/тикет.
- [ ] Регрессии enrollment, startup-context, communication-store, context-session, session-runtime и миграции проходят. Удалён только заменённый DOM-ввод; необходимые наблюдатели и совместимые внешние экспорты сохранены.
- [ ] Согласованы README, документы старта, инструкции, MCP-контракты, backend-ошибки и Workflow Kit. Все невыполненные живые проверки обозначены как таковые.


## Граница реализации и выпуска

Публикация плана не начинает task:start. Сейчас поручены спецификация, Claude Review и публикация to-do. Сборка, подпись, установка и GitHub Release в scope не входят: публикация to-do не означает выпуск приложения. Реализация начнётся по отдельному поручению. Это последовательный CLI-план вне Workflow Pilot; выдуманный execution_origin_session_id не подставляется. Перевод маршрута на оркестрацию требует штатного выбора пользователя.

Последняя документальная задача обновляет невыпущенные specs и статусы проверок. README и module contracts описывают последний выпуск до отдельного delivery-раунда; будущий DOCS перенесёт принятые изменения и удалит выпущенные временные specs. Не заявлять, что 0.5.30 уже Chat-only.

## Живой протокол

На выделенном пользователем workspace в штатном Electron: первый проект/новый Chat после login; отдельно непустой root draft и ранее выбранный Work; точный первый текст, одна отправка, panel registration, части/SHA, отсутствие автозапуска плана. Затем оба порядка адреса/регистрации, переключение карточек, два Chat, отмена до/во время регистрации, потеря связи, renderer crash до исчезновения q. Фиксировать наблюдаемые статусы без тикетов. Действия выполняет пользователь, не агент через UI.

Все живые случаи изначально NOT_RUN; Review и mocks не меняют их на PASS. При несовместимости q/режима/черновика bootstrap останавливается без DOM fallback. Пока живой путь не проверен, допустим итог «изолированные проверки пройдены, внешняя приёмка pending», но не «готово к выпуску». Критические pending блокируют будущий выпуск, а не маскируются документальным DONE.

## Матрица задач

| Задача | Проверяемый результат | Проверки Kit |
|---|---|---|
| T001 | Миграция Chat-only, допуск API/store, история, соседние проекты и OFF | unit-all, architecture |
| T002 | URL/mainFrame/redirect, release, безопасный reload без q | startup-recovery, unit-all, architecture |
| T003 | WAL revoke/enroll/read/cancel и оба порядка гонки, restart/error | orchestrator-startup, unit-all |
| T004 | Один dispatch, preflight на корне, sent/address, восстановление | startup-recovery, orchestrator-startup, unit-all, architecture |
| T005 | Только Chat во всех UI-входах, история и раздельный прогресс | startup-recovery, unit-all |
| T006 | Сквозной настоящий Electron fixture и интеграция | electron-smoke, unit-all, architecture |
| DOCS | Фактические результаты и pending; без delivery | Стандартный документальный контроль Kit, включая 28000 байт; application checks не назначены |

Smoke проверяет пользовательские входы и Electron-навигацию на локальном fixture, но не реальный chatgpt.com. Устаревшие assertions вложений/Work заменить новыми наблюдаемыми гарантиями, не отключать. Если потребуется менять исходники Kit, добавить ОБЕ проверки kit-check и kit-assignments штатным task:update; сейчас изменение Kit не предусмотрено.
