# Отложено: следующие этапы независимого backend

Статус: невыпущенные требования после 0.2.0. Выпущенный контракт — [Backend](../modules/backend.md); доказательства и ручной сценарий — [приёмка](../acceptance/backend-independence.md). Эти пункты не входили в план 0.2.0 и требуют отдельного поручения и плана.

## Вне границ 0.2.0 (решения исходной спецификации)

- Публичный веб-доступ и мобильная приёмка клиента. API пригоден для другого компьютера, но выпуск слушает только loopback; удалённый доступ требует отдельной модели угроз, транспорта и аутентификации.
- VPS-развёртывание backend, перенос проектов между компьютерами и распределённое выполнение. Серверная конфигурация VPS не входит в текущий scope.
- Новая оркестрация выполнения ([отдельное требование](orchestrated-execution-next.md)) и новые правила конфликтов ручных действий пользователя с автоматизацией; существующие защиты draft/Stop/UNKNOWN сохранены.
- Голос, камера и микрофон в изображении страницы.
- Автоматическое возобновление операций UNKNOWN после падения backend; сейчас нужна сверка пользователем.
- Автозапуск фоновой службы при входе в ОС.

## Технический долг и непроверенное

- Перенос in-process smoke (`npm run smoke`, `frontend/desktop/bootstrap.mjs` и `application.mjs`) на связку клиент/backend и удаление in-process окна. Сейчас он только стенд разработки; release-пути до него не доходят.
- Адаптация плотности кадра при изменении состава мониторов после создания страницы без reload ChatGPT. Сейчас плотность — максимальный scaleFactor на момент создания.
- Сжатие или dirty frames вместо полных PNG, если живая проверка покажет недостаток комфорта; собственный видеокодек не создавать.
- Отдельный macOS helper-bundle со своей identity — только если живая проверка reopen/Dock/значка в топологии activate/reopen одного bundle не пройдёт.
- A12: моделирование отказа записи диска (журнал операций, stores, descriptor).
- Нативная приёмка Windows x64 и Ubuntu 24.04 x64/X11 (в том числе отсутствие tray), clean-install.
- Коды плагина `PLUGIN_DESKTOP_REQUIRED`/`PLUGIN_DESKTOP_UNAVAILABLE` сохранены ради совместимости, хотя означают недоступность фоновой службы; переименование — только с миграцией клиентов.
- Пункт `INSTALL.txt` о переходе на версию с фоновой службой (остановить службу перед повторной установкой) — сейчас эти действия описаны в README и контракте поставки.

## Критерии будущей работы

Каждый пункт получает собственную спецификацию и план; автоматические проверки остаются изолированными fixtures без модельных ходов, живую приёмку выполняет пользователь. Непроверенные ОС не объявляются готовыми.
