# Workflow Pilot 0.2.1 — исправления живой проверки 0.2.0

Статус: невыпущенные требования. Основа — [Backend](../modules/backend.md) 0.2.0. Поручение пользователя: исправить найденные при первом живом запуске проблемы, добавить нужную диагностику и выпустить новую версию без остановки перед установкой и публикацией.

## Наблюдения 16.10.2026

- Первый клиент 0.2.0 показывал «наблюдение (управление у другого окна)», изображение «Подключение к Workflow Pilot…» и `RENDER_PROCESS_GONE`. В журнале первого запуска backend нет ни одной принятой мутации.
- Renderer страниц backend дважды завершались извне (`reason: killed`, exit 15) вместе с перезапуском GPU/utility helper. Backend и API оставались живы, страницы не восстанавливались. Изолированные эксперименты: штатный выход/SIGTERM клиента (spawn и LaunchServices) и popup страницы renderer не убивают и не меняют тип процесса backend.
- Переключение сессии большого проекта (запись 325 КБ) завершалось `BACKEND_MESSAGE_SIZE`: `ui.invoke` возвращал полную запись проекта, хотя действие уже выполнилось.
- Backend в какой-то момент стал Foreground-приложением с собственной плиткой Dock; клиент, открытый backend через `spawn`, появился отдельной плиткой. Вне основного окна видны пункты фоновой службы.

## Требования

1. `ui.invoke` и другие операции не возвращают внутренние записи Control; результат, превышающий предел протокола, не превращает выполненное действие в ошибку. Проверка — fixture с большим проектом.
2. Право управления: один запрос acquire за раз; ошибка acquire/renew, кроме занятого другим клиентом lease, повторяется с ограниченной задержкой; заголовок «наблюдение» только при известном другом владельце. Новое соединение того же клиента не ждёт истечения своего прежнего lease.
3. Гибель renderer страницы backend (crashed/killed/oom) восстанавливает ту же страницу перезагрузкой адреса разговора без повторной отправки контекста и Send; повторы ограничены, исход виден в состоянии. Клиент показывает восстановление, а не бесконечное «Подключение…».
4. Backend всегда остаётся accessory (UIElement): политика повторно применяется после диалогов, активации и создания окон. Клиент backend открывает через LaunchServices того же bundle, а не прямым `spawn` исполняемого файла.
5. Диагностика backend: ограниченный журнал `diagnostics/backend-events.jsonl` — подключения и отключения клиентов, lease, открытие клиента и причина, тип процесса в LaunchServices, `child-process-gone` и `render-process-gone` с типом, причиной и кодом; без токенов, текста чата и путей вне профиля.
6. Версия 0.2.1; DOCS; общая сборка трёх ОС; установка в `/Applications`; GitHub Release.

Вне объёма: отдельный helper-bundle backend (требует отдельной упаковки и подписи) — только если живая проверка 0.2.1 снова покажет лишние плитки Dock.
