# Восстановление подготовки сессий — 0.5.18

Поручение пользователя: исправить запуск нового workspace без ручного открытия карточки, зависшие вложения, безрезультатный повтор и блокировку управления; добавить принудительную остановку службы. Выпустить и установить новый комплект. Работа одним агентом, действующие DONE сохраняются.

## Наблюдения

В 0.5.17 оба файла переданы HTTP PUT 201, но один поток обработки вложения не завершился. Повтор воспроизвёл ожидание прежних карточек. Обработчик retry удерживает общий actionPending интерфейса. Для обычного оркестратора отсутствует ограниченная перепроверка readiness, существующая для назначений. Корень внешней задержки обработки ChatGPT неизвестен; исправление не обещает устранить внешний сбой.

## Поведение

Новый проект сразу раскрывает выбранную сессию. Ограниченная перепроверка запуска действует для всех автоматических несостоявшихся стартов, прекращается при отправке, отмене, закрытии назначения и смене поколения.

Подготовка/повтор работают в фоне и не запирают весь sidebar. Во время подготовки доступна отмена, сохраняющая черновик и файлы. Она не отправляет сообщение и не возобновляется от фонового события; повтор — только явный. Отмена после начала Send не разрешает повтор.

Ожидание вложений показывает отдельную стадию и число готовых частей без текста файлов в диагностике. Исчезновение уже наблюдавшейся карточки прекращает ожидание. При явном повторе повторно загружается только принадлежащее этой попытке зависшее/ошибочное вложение: проверены request, полный пакет, документ, точная карточка, неизменённый текст. Готовые и чужие файлы не удаляются. Удаление и новая вставка разделены проверкой исчезновения карточки; неоднозначность, навигация, ручные изменения и отправленный/UNKNOWN запрос запрещают повтор. Повтор не означает успешное восстановление внешнего сервиса. Сообщение отправляется ровно один раз только после готовности всех частей.

Принудительная остановка доступна отдельно от штатной в меню службы и окна. Подтверждение предупреждает о прерывании текущих операций и возможной потере несохранённого состояния. После подтверждения она не ждёт безопасной точки/ответа модели или зависшего Promise очистки: останавливает только собственное дерево процессов, завершает backend; завершение/успех задач не подделывает. Штатная остановка остаётся прежней. Требуются проверки отмены подтверждения, адресности и завершения при зависшей штатной остановке.

## Проверки и поставка

Адресные fixtures: composer/context/session/sidebar/workspace/backend menu/shutdown; без моделей и пользовательских профилей. Проверить неизменность текста/UTF-8, отказ при чужих карточках/правках/UNKNOWN, удаление пользователем и повторные клики, отсутствие блокировки UI, отмену и readiness без выбора карточки. Полный Kit не затронут.

DOCS-2 согласует 0.5.18 и контракты, затем BUILD-2 собирает три ОС из одного sourceCommit, INSTALL-2 устанавливает проверенный комплект штатным installer. Перед production сборкой удаляются только Python-кэши в extra-resource без обхода symlink. Пользователь явно разрешил принудительную остановку текущей службы; после поставки не запускать приложение за него. GitHub-публикация не запрошена.
