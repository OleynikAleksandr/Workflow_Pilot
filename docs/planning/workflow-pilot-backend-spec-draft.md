# Workflow Pilot — независимый frontend и постоянно работающий backend

Дата: 15.10.2026. База: Workflow Pilot 0.1.6. Выпуск: 0.2.0 (решение пользователя).
План: [workflow-pilot-backend-todo-draft.md](workflow-pilot-backend-todo-draft.md).

## 1. Результат

Основной сценарий — backend и frontend на одном Mac; VPS не нужен. Одно открытие Workflow Pilot находит или запускает собственный backend (браузер ChatGPT, Control, Execution, Kit, MCP, мост плагина, выбранный туннель) и открывает отдельный клиент с панелями и интерактивным изображением страницы.

Закрытие окна, Cmd+Q и падение клиента отключают только интерфейс: страницы, команды, AutoPlan, Review, исполнители, MCP и туннель продолжают работу. Повторное открытие возвращает к тем же страницам без reload, второго разговора и повторного recovery. Системный значок показывает состояние, открывает клиент и явно останавливает backend; без Linux tray статус и остановка — в меню клиента. Сон, logout, выключение и падение backend не равны закрытию клиента.

## 2. Решения пользователя

Исходное задание — документ «Workflow Pilot — задачи клиент-серверной архитектуры», задача 1 и нужное для неё представление браузера. Приоритет у уточнений:
- один рабочий диалог — один живой экземпляр страницы на backend; все интерфейсы подключаются к его изображению и вводу;
- продолжение диалога через отдельно открытый ChatGPT.com или мобильное приложение — не штатный сценарий (наблюдение пользователя: второй браузер нарушает устойчивость больших планов; причина не установлена);
- полный интерактив: редактор, кнопки ответов, подсказки, меню, просмотр файлов, копирование, вложения;
- новые правила конфликтов ручных действий с автоматизацией — отдельный план; существующие защиты сохраняются.

Подтверждены: транспорт T001, тонкий клиент T007, освобождение профиля до T007 (T006R), версия 0.2.0, lease 10/45 с и draining без kill.

## 3. Границы

Включено: независимый backend/browser lifecycle; launcher и отдельный клиент; локальный API; полный интерактив; запуск/закрытие/переподключение/остановка; значок; MCP/туннель/плагин; один управляющий клиент; переход с 0.1.6; выпуск трёх ОС.

Не включено: публичный веб-доступ и мобильная приёмка; VPS-развёртывание, перенос проектов и распределённое выполнение; новая оркестрация и правила ручного вмешательства; голос/камера/микрофон; автоматическое возобновление UNKNOWN после падения и автозапуск при входе в ОС. Контракт пригоден для другого компьютера, но доступ выпуска ограничен loopback.

## 4. Процессы и владельцы

| Компонент | Ответственность |
| --- | --- |
| Launcher/клиент | Найти живой backend по приватному descriptor или запустить его отдельным процессом; окно, панели, изображение страницы, ввод |
| Backend | Control, Execution, Kit, stores, модель Desktop, workflow; `persist:workflow-pilot-chatgpt`, cookies и секреты |
| Browser runtime | Скрытые offscreen-страницы, popups, observer, автоматизация |
| MCP / туннель / мост плагина | Существующие службы; lifecycle координирует backend |
| Значок | Tray backend; без tray — меню клиента |

Реализовано (T003–T010): `--backend-host` защищён lock и приватным descriptor, повреждённые stores/Kit journal отвергаются; штатный выход освобождает профиль, owner завершённого процесса восстанавливается. Backend выполняет модель Desktop (каналы pilot:*/archive:*/colors через API), владеет страницами и восстанавливает AutoPlan/parallel и выбранную сессию. Detach зрителя не вызывает release/cancel/reset; crash страницы отмечен отдельно. Мост плагина и runtime MCP запускает backend. Обычный запуск — клиент; in-process Desktop остаётся только для smoke до T012.

macOS: топология activate/reopen в одном bundle — backend без Dock-иконки (accessory) по activate открывает или фокусирует клиент. Отдельный helper не создан; T011 проверяет упаковку и подпись. Живая проверка Finder/Dock/Spotlight, значка и reopen — у пользователя.

Kit — единственный владелец плана и транзакций. Готовность подтверждают identity, boot generation, версия API и состояние служб, а не PID/порт.

## 5. Браузерное представление

ChatGPT загружается только на backend; интерфейс ChatGPT не реконструируется. Страница допускает нескольких зрителей; reconnect не создаёт страницу. Управляющий клиент задаёт viewport; наблюдатели только масштабируют кадры. Без зрителей страница, observer и ожидания работают.

Интерактив: указатель, удержание, прокрутка, клавиатура, русский и составной ввод, меню и выделение; ввод адресован browserSessionId и поколению документа, поздний ввод отвергается; зажатое отпускается при разрыве или смене lease, ввод не переигрывается; clipboard по явному действию; файл клиента передаётся по transferId и прикрепляется к перехваченному выбору файла после полной передачи; скачивание — на устройство клиента; popups и авторизация — скрытые страницы backend. Branch/Delete/Retry передаются странице без новой политики; защиты draft/Stop/UNKNOWN сохраняются.

Транспорт T001 (Electron offscreen PNG/CDP, автоматическая плотность) — [протокол T001](workflow-pilot-backend-t001-evidence.md). Непроверенные ОС остаются pending.

## 6. Сетевой контракт

API версии 1: HTTP-команды/операции, SSE-события (bearer в заголовке), `/v1/browser/*`. Контракты: `src/contracts/{backend,browser-presentation,desktop}.mjs`, `src/backend/protocol.mjs`. UI не вызывает Control напрямую.

| Объект | Контракт |
| --- | --- |
| Handshake | Версия API, identity, boot generation, capabilities, готовность |
| State | Snapshot + sequence/revision; пропуск или новое поколение — resync; состояние Desktop — последнее значение |
| Command | requestId, allowlisted operation, args, lease generation для изменений |
| Result/Operation | accepted + operationId либо completed/failed/unknown; операция живёт без соединения |
| Error | Код и безопасное сообщение без секретов и текста чата |

Один requestId с теми же аргументами возвращает прежний operationId, с другими — конфликт. Приём фиксируется в журнале с fsync до эффекта; операции прошлого boot читаются как UNKNOWN и не повторяются. Очереди, сообщения и файлы ограничены; медленный клиент отключается и делает resync. Loopback требует bearer, точный Host и разрешённый Origin; токены не в URL; локальные пути выбирает backend; клиент не получает CDP, JS или shell.

## 7. Право управления

Один управляющий клиент, остальные наблюдают. Lease по clientId берётся явно, перехват — только явный; продление 10 с, истечение 45 с. Каждая мутация и ввод проверяют поколение; поздний запрос старого владельца отвергается; принятые операции продолжаются. Подписка не захватывает управление. Клиент без lease — наблюдатель; при обрыве он помечает устаревание и блокирует изменения, переподключается к новому boot, остановленную службу не перезапускает.

Потеря lease не выключает AutoPlan и агентские MCP-инструменты. UI-мутация плагина (запуск из меню) идёт через API под lease; connect и контекст — агентский MCP без клиента.

## 8. Жизненный цикл

| Событие | Поведение |
| --- | --- |
| Первый запуск | Один backend, затем клиент; этапы готовности видны |
| Нет настройки | setup-required и мастер в клиенте |
| Два запуска | Один backend; проигравший отказывается от владения |
| Закрытие / Cmd+Q / crash клиента | Только отключение |
| Разрыв связи | Устаревание показано; reconnect со свежим состоянием |
| Crash backend | Новый boot generation при следующем запуске; UNKNOWN без повторов |
| Явная остановка | Draining → безопасная точка → остановка своих служб → подтверждение выходом процесса |

Draining прекращает новые отправки, контекст и назначения; текущий ответ, инструменты и команды Kit завершаются. Причины ожидания видны в значке и клиенте, остановку можно отменить; timeout → kill нет. Descriptor удаляется только доказанным владельцем. Запуск не обходит ключи, вход и разрешения; запускается выбранный настроенный канал.

## 9. Совместимость и обновление

Сохраняются проекты/сессии, адресация и cwd фоновых задач, recovery once, UNKNOWN no-retry, AutoPlan/Review/sequential/parallel, настройки, архив/удаление/Доктор и подключения. Допуск workflow не зависит от окна и видимости. Профиль 0.1.6 сохраняется, донор не меняется; старая и новая версии не владеют профилем одновременно.

Установка при живом backend не заменяет используемые runtime-файлы: выбрать по проверке installer закреплённый за процессом runtime либо отложенное переключение. Несовместимый клиент показывает требуемый переход, не убивает backend и не создаёт второй.

## 10. Приёмка

Автотесты — временные профили, workspaces и fixture-страницы; без модельных ходов, управления окнами пользователя и изменения реальных служб. Критерии A01–A14 — objective плана. Пользовательская приёмка Mac: тестовый план → закрыть клиент → значок → открыть вновь → тот же диалог и продолжившаяся работа; отдельно меню/clipboard/файлы и остановка. Windows/Linux/clean — отдельные строки матрицы.
