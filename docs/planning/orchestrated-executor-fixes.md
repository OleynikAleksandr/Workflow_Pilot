# Исполнители плана оркестратора и окно клиента (0.4.2)

Временная спецификация выпуска 0.4.2. После выпуска действующее содержание переносится в docs/modules/orchestrated-execution.md и docs/modules/desktop.md, документ удаляется.

## Найдено при живой приёмке 0.4.1

Тестовый план оркестратора (5 задач) запущен кнопкой «Начать выполнение плана». Для T001 Kit создал worktree, приложение — сессию исполнителя, но:

1. Первое сообщение исполнителю не отправлено. Разрешение на отправку контекста исполнителю (`canSendContext` в backend) проверяло прежний переключатель AutoPlan родительского плана. План оркестратора ведёт только кнопка плана, AutoPlan у него выключен, поэтому исполнитель ждал вечно. Включение продолжений исполнителя тоже следовало только за AutoPlan.
2. Сессия исполнителя открылась в режиме Work — унаследовала режим сессии оркестратора.
3. При выборе исполнителя карточка плана заменялась прежней карточкой назначения: to-do plan пропадал.
4. Окно клиента после разрыва потока событий переподключилось по номеру события без снимка и навсегда осталось в состоянии «нет связи»: сброс устаревания происходил только по снимку. В этом состоянии окно отклоняет все действия, поэтому клик по сессии оркестратора не загружал её диалог. Исключение в обработчике данных потока обрывало поток без записи причины, а старое соединение оставалось открытым.

## Требования

1. В новой схеме нет AutoPlan. Для исполнителей плана оркестратора единственный переключатель — состояние кнопки плана: «выполняется» и «пауза запрошена» разрешают первое сообщение и продолжения исполнителя, «на паузе» и «не начат» — нет. Изменение состояния кнопки сразу применяется к живым исполнителям. Прежние планы (AutoPlan, sequential, parallel) не меняются.
2. Исполнитель плана оркестратора всегда создаётся в режиме Chat, независимо от режима оркестратора. Ещё ничего не отправивший исполнитель, сохранённый в 0.4.0–0.4.1 с режимом Work, при восстановлении переводится в Chat.
3. Клик по начатой или выполненной задаче в to-do plan показывает справа сессию её исполнителя; карточка плана с to-do plan остаётся, текущая задача выделена. Прежняя карточка назначения для исполнителей плана оркестратора не показывается. Клик по сессии оркестратора или чату обсуждения в дереве загружает его диалог.
4. Поток событий клиента: успешное переподключение (по снимку или по номеру события) снимает состояние «нет связи»; исключение обработчика не обрывает поток и пишется в `client-events.jsonl`; при ошибке чтения старое соединение закрывается; причина разрыва (код и сообщение без данных) пишется в журнал.

## Проверки

- Unit: разрешение исполнителя следует кнопке плана, а не AutoPlan; изменение кнопки включает и выключает продолжения живого исполнителя; исполнитель плана оркестратора создаётся в Chat при оркестраторе в Work.
- Подключение: обрыв потока и переподключение по номеру события снимают устаревание; исключение обработчика не обрывает поток.
- `desktop-client` (macOS): после выбора исполнителя карточка плана видна, карточка назначения скрыта; выбор сессии оркестратора загружает её.
- Живую приёмку тестового плана с настоящими чатами ChatGPT выполняет пользователь.
