# Восстановленная стартовая команда в новом Chat (0.6.1)

Невыпущенное исправление выпуска 0.6.1. Основа — 0.6.0 (`81d9d89`).

## Факт

ChatGPT сохраняет текст поля ввода нового чата в хранилище профиля и восстанавливает его в каждом следующем новом чате. Все страницы Workflow Pilot работают в одном persistent profile, поэтому после URL-старта (`https://chatgpt.com/?q=…`) любой новый Chat — фоновый исполнитель или новая сессия пользователя — открывается с чужой стартовой командой: «Открой панель Workflow Pilot: один раз вызови workflow_pilot_panel с аргументами {"enrollment_ticket":"…"}…». URL-старт (`ContextSession.tickUrl`) считает любой непустой черновик пользовательским и ждёт (`waiting-draft`) бесконечно; попытка старта не создаётся, навигации с q нет. Подтверждено журналами 30.10 (тесты `Workflow_Pilot_Test_0.6.0_001`, `_002`: тикет в поле принадлежит оркестратору другого проекта) и ручной очисткой поля пользователем, после которой работа продолжилась. Впервые проявилось 29.10 в 0.5.41; код старта с 0.5.41 не менялся.

## Требование

- Перед решением о черновике URL-старт новой сессии (без адреса и без попытки, страница нового чата `/` без сообщений, тот же документ) очищает поле, если его текст **в точности** является стартовой командой Workflow Pilot с любым тикетом. Такой текст никогда не бывает пользовательским, а его отправка передала бы чужое приглашение.
- Проверка повторяется непосредственно перед q-навигацией: ChatGPT может восстановить черновик позже первого наблюдения.
- Любой другой текст — пользовательский: не стирается, старт ждёт, как в 0.6.0; задача исполнителя показывает оранжевую причину «В новом чате исполнителя черновик: откройте чат и очистите поле».
- Шаблон команды один для формирования и распознавания (контракт), распознавание выполняется в документе страницы, текст черновика за пределы страницы не передаётся.
- Без новых кнопок, режимов, DOM Send и изменений рабочего профиля/donor. Живую проверку выполняет пользователь: новая сессия и фоновые исполнители стартуют без ручной очистки поля.

## Проверка

Composer: точная команда очищается, команда с добавленным текстом и обычный текст — нет, вне `/` — нет. ContextSession: восстановленная команда очищается и старт доходит до q; пользовательский черновик сохраняется и ждёт; поздно восстановленная команда перед q очищается. Проекция исполнителя: `waiting-draft` — оранжевая причина. Полная регрессия, затем DOCS-2 и выпуск трёх ОС.
