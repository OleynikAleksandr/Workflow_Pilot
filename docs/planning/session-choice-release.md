# Дополнение: выполнение и выпуск 0.5.36

26.10.2026 после согласования session-choice-and-delivery пользователь поручил выполнение без пауз до нового GitHub Release. Это прямое разрешение реализации и delivery, заменяющее прежние границы «только документы» и «без выпуска» основной спецификации. Функциональный объём NAME001/EXEC003 и согласованные барьеры сохраняются.

Порядок: CHOICE → NAME → PROOF → VERSION → DOCS → RELEASE → INSTALL → PUBLISH. Разработка последовательная, без делегирования; живую проверку выполняет пользователь. Новый источник Kit 1.10.2 и ролевой протокол 11 готовятся в NAME, версия приложения 0.5.36 и согласованный build — в VERSION. Новые зависимости не нужны.

VERSION согласует package.json/lock, src/contracts/backend.mjs и реально связанные версии/fixtures. DOCS перед production сверяет действующие контракты с результатом, переносит реализованное из двух временных спецификаций в модули и удаляет временные документы без архивных копий. Required-ссылки заменяются точными существующими Git blob. Отложенные требования сохраняются. Неизменяемая приёмка 0.5.35 не переписывается; новый playbook сохраняет живые NOT_RUN и ограничение обратной совместимости хранилища после topic.

RELEASE собирает macOS arm64, Windows x64 и Linux x64 из одного sourceCommit после DOCS, проверяет семь assets, подпись, состав и SHA, согласованность staging/Downloads/manifest. Перед каждой production-командой, включая Kit package-check, проверить точные пути Python caches в tools/codex-app-server-mcp без перехода по симлинкам; удалить только сгенерированное. Python запускать -B. Не ослаблять строгий состав.

INSTALL штатным installer доставляет готовое распакованное macOS-приложение в проект и /Applications/Workflow Pilot.app без пересборки/переподписи. Проверить manifest, версию, подпись и возможность отката bundle. При действующей службе допустим только проверенный pending: её не останавливать, окно не закрывать/перезапускать, переключение версии делает пользователь. Receipt bundle не доказывает data downgrade; после записи topic старая 0.5.35 несовместима с данными, что должно быть явно описано до установки. Профиль и реальные тестовые проекты не изменять.

PUBLISH публикует собственный GitHub Release v0.5.36, tag на manifest.sourceCommit, все семь assets по size/digest; main должен совпадать с итоговым HEAD. Проверить итог после последнего push. Повторная сборка для публикации не нужна. Секреты не выводить.

У каждого delivery своя проверка: three-platform-release, release-installed, github-release. Успех приложения/fixtures не заменяет эти доказательства, а архивы не доказывают native Windows/Linux/ChatGPT. После всех задач план остаётся READY_FOR_ACCEPTANCE до отдельного принятия пользователем.
