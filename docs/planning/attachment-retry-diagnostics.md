# Повтор вложений и диагностика — 0.5.19

Пользователь поручил исправить распознавание повторного вложения, добавить диагностику зависания, проверить адресно, собрать и установить выпуск. Продолжение текущего плана одним агентом. GitHub-публикация не запрошена.

## Доказательства и границы

В живом 0.5.18 первоначальная передача обоих файлов закончилась HTTP 201; один поток обработки оставался открытым до удаления файла. Повтор обработался примерно за две секунды, затем наша проверка увидела missing и остановила Send. Изолированно воспроизведено переименование повторного файла после обработки: карточка остаётся, но точное старое имя не находится. Переименование в живом сбое пока гипотеза; первоначальная задержка не объяснена.

## Исправление

При явном повторе сохранять исходный payload, проверять владение, неизменённый черновик, документ и отсутствие Send/UNKNOWN. Удалять только подтверждённую собственную незавершённую карточку. Повтор получает уникальное транспортное имя с прежним расширением и тем же содержимым, чтобы не сталкиваться с сохранённым именем удалённого файла. Это имя связывается с исходным индексом только в текущем документе/попытке. Допустимое переименование с числовым суффиксом распознаётся только для такого повторного имени; обычные чужие и неоднозначные карточки не принимаются. Доверенный ручной paste/drop/выбор файлов или удаление отменяет право автоматического восстановления. Готовые части сохраняются; Send один раз после полной готовности. Поддержать асинхронное появление карточки и повтор нескольких незавершённых частей.

## Диагностика

Composer пишет индекс, состояния и способ сопоставления карточек, интервалы ожидания и отсутствие прогресса; без имён/текста файлов. Сетевая диагностика отдельно связывает request с этапом создания, передачи или обработки, статусом ответа, числом порций/байтов, временем последнего поступления данных и завершением/ошибкой. Периодический stall означает отсутствие наблюдаемого сетевого прогресса, а не доказанное зависание сервера. Никаких тел ответа, signed URL, query values или секретов. Ограничить размер реестра и частоту записей; очищать таймеры/реестр при закрытии/навигации/отсоединении.

## Приёмка и поставка

Адресные composer/context и chromium-diagnostics fixtures: позднее переименование, замена DOM-карточки, сохранность готовых частей, чужой файл/дубликат/изменение черновика, ручное вмешательство, UNKNOWN и один Send; stalled stream, resumed stream, завершение, отмена, границы памяти и отсутствие секретов. Архитектурная проверка после исходников. Полная suite/Kit не требуются без изменений соответствующих модулей.

VERSION согласует 0.5.19, DOCS переносит контракт и удаляет эту спецификацию с Git blob-ссылкой. BUILD собирает три ОС из одного sourceCommit, INSTALL применяет готовый комплект. Работающую службу installer не останавливает: при необходимости проверенный pending с точным сообщением пользователю. Живую проверку выполняет пользователь.
