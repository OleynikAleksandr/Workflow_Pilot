# Отложено: фазовое планирование и бюджет recovery

Дата: 15.10.2026. Поручение пользователя: сохранить требование; реализацию обсудить отдельно.

## Требование пользователя

Большой проект имеет короткую общую карту логических фаз. Только текущая фаза содержит активные микрозадачи и обязательный execution context. Пока она не завершена, микрозадачи следующей фазы не появляются в активном плане, recovery и автоматическом исполнении. Будущие требования сохраняются по ссылкам, не теряются. После завершения фазы фиксируются результат и необходимые решения, затем детализируется и проходит применимое Review следующая фаза. Общая цель, зависимости, границы и итоговая поставка остаются видимыми в краткой карте.

## Наблюдавшийся дефект

План backend-independence опубликован после approved раунда 2; формирование итогового recovery завершилось CONTEXT_TOO_LARGE: 230354 bytes, 11 частей при пределах 180000 bytes и 7 частей. Публикация уже создала коммит и PUBLISHED, хотя команда вернула ошибку. Ни одна задача не начата. Это не отказ Git и не основание повторять публикацию.

Recovery сейчас выводит все задачи плана. Дополнительно required-контекст включал полную спецификацию, отдельный to-do с повтором задач и все профильные module docs. task.context_pack пока не использовался.

## Что проверить при будущем исправлении Kit

- Поддержка фаз: roadmap отдельно, микрозадачи только текущей фазы; безопасная смена фазы, история, зависимости и единственное право исполнения.
- Отдельная политика Review и выполнения плана на границе фаз; не считать завершение фазы разрешением на несогласованные решения.
- Завершённые фазы представлены кратким результатом и Git-ссылками, не полным накопленным списком.
- Проверка бюджета контекста ДО публикации/фиксации плана и переходов задач/фаз; отказ не должен оставлять неожиданно опубликованный непригодный контекст.
- Бюджет проверяется для каждой будущей текущей задачи, не только первой; нужен запас для результатов и решений.
- При сбое после коммита сообщение явно различает успешную фиксацию и ошибку recovery.
- Требования не обрезаются автоматически; optional означает доступность по ссылке, а не удаление документа.

## Возможности нынешнего Kit

plan:extend позволяет добавлять следующую порцию задач. Recovery всё равно включает накопленные задачи, поэтому это поэтапная детализация, не полноценная фазовая поддержка. task.context_pack включает документы только выбранной текущей/следующей задачи; required:false оставляет ссылку. plan:apply не удаляет существующие задачи. archive требует завершения всех задач. plan:carryover переносит ВСЕ незавершённые задачи, поэтому не решает нынешний случай, где все 16 задач TODO.

Для текущего опубликованного плана практично сначала убрать повтор to-do из обязательного recovery, перенести модульные документы в контекст соответствующих задач и проверить размер пакетов. Сам план и его критерии сохраняются. Это предложение, не выполненная перестройка. Настоящее скрытие будущих микрозадач требует поддержки фаз либо штатной замены незапущенного плана; вручную удалять записи нельзя.
