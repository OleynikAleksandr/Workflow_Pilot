# Архив проекта с активным планом и восстановление исполнителя (0.4.3)

Временная спецификация выпуска 0.4.3. После выпуска действующее содержание переносится в docs/modules/orchestrated-execution.md, docs/modules/desktop.md и docs/modules/backend.md, документ удаляется.

## Найдено при живой приёмке 0.4.2

1. Проект с выполняемым планом оркестратора нельзя было перенести в архив (`PLAN_ACTIVE`), а удалить с диска можно только архивный проект. Застрявший план навсегда оставлял проект в списке.
2. Исполнитель T001, созданный в 0.4.1 и не получивший ни одного сообщения, после перезапуска службы считался сессией с неизвестным исходом отправки (`EXECUTOR_CHAT_UNKNOWN`): задачу не получал, план показывал «Требует внимания», а запрошенная пауза ждала его вечно.

## Требования

1. Архивирование проекта с активным планом оркестратора разрешено после явного подтверждения пользователя. Без подтверждения backend отвечает `PLAN_ACTIVE`; боковая панель сама спрашивает подтверждение и повторяет команду с `stopExecution`. Подтверждённое архивирование сразу переводит выполнение плана в «пауза» (без ожидания исполнителей): новые задачи, первые сообщения и продолжения исполнителей не отправляются. План, назначения и worktree в Kit не меняются. Возврат из архива показывает план на паузе; выполнение продолжается кнопкой «Продолжить». Удаление архивного проекта с диска, как и прежде, удаляет и worktree его исполнителей.
2. Исполнитель, в чат которого ни разу ничего не отправлялось (нет адреса чата, нет начатой отправки и ручного старта), при восстановлении открывается заново: режим Chat, новый черновик, затем обычная отправка контекста задачи по кнопке плана. Исполнитель с адресом чата или начатой отправкой по-прежнему не переотправляется автоматически.

## Проверки

- Unit: архив активного плана без подтверждения — `PLAN_ACTIVE`, с подтверждением — архив и пауза плана, план Kit не меняется; восстановление из архива оставляет паузу.
- Unit: восстановление исполнителя без отправки переводит его в Chat и открывает новый черновик; исполнитель с начатой отправкой — прежняя ошибка `EXECUTOR_CHAT_UNKNOWN`.
- `sidebar`: подтверждение перед архивом проекта с активным планом, отказ ничего не отправляет.
- Живую приёмку выполняет пользователь.
