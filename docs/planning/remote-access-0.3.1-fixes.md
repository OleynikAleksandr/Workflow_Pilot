# Workflow Pilot 0.3.1 — исправления живой проверки доступа с iPad

Статус: невыпущенные требования. Основа — [удалённый доступ](../modules/remote-access.md) 0.3.0. Поручение пользователя 16.10.2026: сделать новую версию, собрать и опубликовать.

## Наблюдения

- Фоновая служба запускается без терминала. Бинарник Tailscale на macOS в таком окружении стартует как графическое приложение («The Tailscale GUI failed to start») и не отдаёт `status --json`. Из Терминала та же команда работает. В итоге Workflow Pilot показывал «не вошли» и «HTTPS не разрешён» при правильной настройке. С переменной `TAILSCALE_BE_CLI=1` команда работает и без терминала.
- Пользователь принял платные тарифы при регистрации за отсутствие бесплатного. Вход рабочей почтой на собственном домене создал сеть организации с пробным платным периодом и обязательным одобрением устройств.
- Состояние Tailscale в Настройках не обновлялось после входа, пока не нажать «Проверить снова»; ошибка прошлой попытки оставалась на экране.
- Две попытки остановить службу со значка не дошли до backend: фаза осталась `running`, а в журнале нет ни нажатия, ни ответа диалога.

## Требования

1. Все вызовы Tailscale CLI выполняются в консольном режиме (`TAILSCALE_BE_CLI=1`) без зависимости от терминала. Причина неудачного вызова видна в Настройках.
2. Мастер и Настройки предупреждают: Tailscale бесплатен для личного использования (тариф Personal); входить нужно личным аккаунтом Google, Apple или GitHub, потому что рабочая почта на своём домене создаёт сеть организации с платным пробным периодом.
3. При открытии раздела состояние Tailscale проверяется заново автоматически.
4. Журнал `backend-events.jsonl` записывает нажатие «Остановить фоновую службу…» в меню значка, ответ диалога и запрос остановки. Перед показом диалога приложение выводится на передний план и затем снова скрывается из Dock.
5. Версия 0.3.1; DOCS; сборка трёх ОС; установка в `/Applications`; GitHub Release.
