# Восстановление панели связи — выпуск 0.5.3

## Поручение и результат

18.10.2026 пользователь передал отчёт внешнего эксперимента и подтвердил: после закрытия браузера и повторного выбора сессии панель полностью пустая, привязки нет, кнопка включения недоступна. Пользователь согласовал восстановление контекста с одним ручным включением и увеличение разрешения с 10 до 30 минут в общем выпуске. Работа выполняется самостоятельно в основном checkout, без модельных исполнителей и живого управления UI.

Согласно переданному отчёту 0.5.2: самопробуждение P0 и конечный автоматический обмен P1-02 в двух окнах Chrome получены; P1-03 со свёрнутым окном также получен. P1-01 во встроенном приложении требовал ручного включения. Закрытая страница перестала ждать, сообщения сохранились pending. Серия 29 Stop относится к O. Причины конкретной серой кнопки и серии Stop не установлены; данных о старых открытых экземплярах нет. Полный экспорт недоступен, подтверждена граница seq525 и один frontend.gap; это не потеря серверной последовательности. Исходный run не менять и не повторять старые вопросы.

## Текущий объём

- App-only восстановление по свежей доверенной identity хоста: только собственные run/participant/роль. Один запуск выбирается автоматически; несколько требуют явного выбора. Не хранить секреты, не считать ID авторизацией, не восстанавливать panel_instance_id или разрешение.
- После handshake автоматически восстановить поля и привязку нового экземпляра. После join в уже открытой панели доступно повторное восстановление. Понятные ошибки SDK/службы/принадлежности и причина блокировки Enable видны до bind.
- Различать временную приостановку pagehide и окончательный dispose; pageshow даёт рабочий путь восстановления без автоматического Send. Один wait, отмена старых асинхронных операций, новая привязка после restart.
- Изменения известных полей оформления хоста не выключают связь. Неизвестное изменение контекста блокирует отправку и требует восстановления; свежая identity по-прежнему проверяется при bind/claim/verify. Не обещать атомарность SDK Send и проверки адресата.
- Пользовательский Stop глобален для участника. Автоматическая остановка экземпляра применима только к его текущему поколению. Запоздалые ответы enable/stop, старые панели и повторный вход не отзывают новое разрешение. Повтор Stop уже остановленного участника не увеличивает поколение бесконечно.
- Разрешение действует 30 минут. Истечение и ручной Stop сохраняются; новое разрешение только по клику. После восстановления сохранённое pending доставляется однократно независимо от курсора журнала. claimed/accepted/unknown не возвращаются в pending.
- Диагностика SDK, bind, ожидания, жизненного цикла и причин Stop без raw payload; исключить самоподдерживающуюся цепочку диагностических событий.
- Тот же плагин, endpoint и UI URI, новая видимая версия/build_id. Несовместимые HTML/backend отклоняются. Проверить политику ресурса; кэш хоста не объявлять управляемым без доказательств.
- Проверить код переключения страниц встроенного приложения; большую перестройку и живые проверки не выполнять.

## За пределами этого выпуска

Связь на всё время выполнения плана с отключением по его завершению — согласованное направление следующего этапа. Нужен отдельный контракт привязки run к плану, паузы/отмены/ошибок и разрешения; сейчас не соединять протокол с Kit и не выдавать таймер за такой режим. Отмена обычных pending сообщений не реализуется автоматически; журнал опыта сохраняется.

## Проверки и приёмка

Настоящие staged HTML/SDK/Python MCP и изолированный test host: reload→restore→bind→ручной enable→старое pending→один read; pageshow того же экземпляра; несколько run; чужая/отсутствующая identity; смена темы/размеров и неизвестного контекста; параллельные Stop; поздний enable и старый dispose; 30 минут и истечение; сетевой отказ/restart/unknown без повторов. Полная suite, architecture, electron-smoke, executor-channel.

DOCS-2 переносит действующее содержание в контракты/инструкцию и удаляет эту временную спецификацию, сохраняя отложенное требование отдельным документом. RELEASE-2 → INSTALL-2 → PUBLISH-2: три платформы из одного sourceCommit, установка проверенного macOS-комплекта штатным installer, полный GitHub Release. Работающую службу не останавливать по старому поручению: при BACKEND_RUNNING оставить pending.

Живая приёмка пользователем: закрыть браузер → открыть → выбрать сессию исполнителя → увидеть восстановленные данные → включить связь → получить сохранённое сообщение. Прежние успешные опыты не доказывают исправление нового выпуска; техническое DONE не закрывает план.
