# Неотправленная стартовая команда (0.6.3)

Невыпущенное исправление выпуска 0.6.3. Основа — 0.6.2 (`743b355`).

## Факт

Тест `Test_0.6.2_001`, 30.10: из 7 q-стартов два (сессия обсуждения 11:28:13 UTC и исполнитель T004 11:37:45) не дошли до сервера. ChatGPT показал сообщение пользователя локально (`/c/local-chatgpt:…`), сразу вывел «Учетная запись сменилась. Отправьте сообщение еще раз» с кнопкой «Повторить» и вернул текст в поле ввода. Сетевой журнал: запрос `POST /backend-api/f/conversation` из этого документа не уходил (в пяти удачных — через 1–3 с), адрес не стал настоящим `/c/<id>`, генерации ответа не было, регистрации по приглашению нет. Учётная запись не менялась (`_account` не обновлялся с 14.10); одновременных загрузок других страниц не было. Внутренняя причина отказа ChatGPT не установлена; единственное отличие — поздний `sentinel/chat-requirements/finalize`.

Workflow Pilot считал попытку неподтверждённой: `waiting-registration`, через 180 с «исход неизвестен», без причины и без восстановления.

## Требование

- **Доказанная неотправка**: попытка `url-query` без регистрации и без привязанного адреса, ни разу не наблюдавшая настоящий адрес разговора (`addressCandidate` пуст), прошло не меньше 30 с от q-навигации, страница всё ещё тот же документ этой навигации (incarnation и epoch попытки), адрес — временный `local-chatgpt:`/`WEB:`, генерации нет. Удачный старт получает настоящий адрес за 1–4 с. Пока признаки не выполнены, ContextSession сам проверяет их по таймеру (страница после сбоя затихает).
- **Автоповтор (решение пользователя 30.10)**: попытка отменяется с причиной `start-not-sent`, приглашение отзывается. Только при статусе `revoked` (никто не зарегистрировался) служба очищает попытку и выполняет **один** новый старт той же сессии с новым приглашением из чистого нового чата; поле с возвращённой командой очищает правило 0.6.1. Если по старому приглашению кто-то зарегистрировался (`registered-stopped`), повтора нет. Повтор доступен один раз на цепочку (`startupRetry.count`), переживает перезапуск службы.
- **Причина**: во время повтора — нейтральное «ChatGPT не отправил стартовое сообщение · повторяем старт»; если не отправлен и повтор — оранжевое «ChatGPT не отправил стартовое сообщение · откройте чат и нажмите „Повторить“ или создайте сессию заново».
- Без DOM Send, нажатий кнопок и повторной отправки отправленного; доставленное, UNKNOWN и бюджет не меняются. Версия 0.6.3, панель `0.6.3-communication-9`.

## Проверка

ContextSession: неотправка распознаётся по таймеру; удачный, медленный (реальный адрес), занятый и чужой документ не задеваются; отзыв `revoked` даёт один новый старт с новым приглашением; `registered-stopped` и второй сбой — оранжевая причина без повтора; перезапуск между отзывом и очисткой продолжает повтор. Проекция исполнителя: обе причины. По решению пользователя полная регрессия не выполняется: целевые проверки затронутых модулей и живая проверка пользователем.
