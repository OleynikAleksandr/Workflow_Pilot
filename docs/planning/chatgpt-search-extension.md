# Автоматическое подключение ChatGPT search

## Поручение и границы

24.10.2026 пользователь поручил автоматическую загрузку, установку и подключение официального поискового расширения по Workflow Kit, проверку запуска, выпуск для macOS arm64 / Windows x64 / Linux x64 и публикацию на GitHub. Это продолжение действующего Chat-only плана; прежние DONE и пользовательская приёмка не переписываются. Новая версия приложения — 0.5.32. Нативный Enter, подмена User-Agent, ввод через DOM и Work не добавляются.

## Основание

В загруженном реальным приложением файле ChatGPT `87162.8221492420.js` автоотправка для вошедшего пользователя при Sec-Fetch-Site=none разрешена Safari или странице с dataset.searchExtension=1. Официальное расширение ChatGPT search 1.11 (Chrome Web Store ID ejcfepkfckglbgocfkanmcdngdijcgld) устанавливает этот признак content script при document_start. Изолированный Electron 44.5.1 подтвердил загрузку неизменённого расширения и прохождение той же проверки; это не живая приёмка отправки.

Официальные источники: https://help.openai.com/en/articles/9237897-searching-the-web-with-chatgpt и https://www.electronjs.org/docs/latest/api/extensions-api . CRX получен с официального Google update endpoint; SHA-256 95bb61ea1d4c2fd4f96fa02a3ea6943c7b9ae0f935b055dc1cd9884d8868e4f2, размер 12091 байт.

## Контракт

- Execution владеет скачиванием, проверкой, распаковкой и Electron extension API. Control не получает файловую систему, HTTP или Electron. Backend только связывает адаптер с собственной persistent session.
- Официальный пакет скачивается в собственный служебный каталог Workflow Pilot. Релиз содержит проверенный pin с версией, URL конкретного blob и hashes всех файлов; не включает и не меняет код расширения. Проверяется HTTPS и ограниченный список хостов, лимит перенаправлений/времени/размера и SHA-256 CRX до распаковки. Изменившаяся версия не принимается как latest.
- Используется ZIP-библиотека. Запрещены traversal, абсолютные имена, симлинки, дубликаты, дополнительные файлы, неверный размер/содержимое, неподходящий manifest/content script. Каталоги кэша не могут быть симлинками. Исполняемые файлы/manifest/иконки сохраняются побайтно. Служебный `_metadata/verified_contents.json` проверяется в CRX, но не переносится в unpacked-копию: Electron удаляет эти установочные метаданные.
- Установка атомарная: download/validate/unpack во временную собственную папку, затем rename готовой версии. Повреждённая копия не загружается; сохраняется отдельно при восстановлении. Чужие папки и старые версии не удаляются. Ошибки не превращаются в тихое продолжение без расширения.
- Повторный запуск проверяет и использует локальную копию без HTTP. Конкурирующие запросы разделяют одну подготовку. После ошибки возможна новая подготовка, без бесконечного фонового повтора. Каждый новый backend загружает расширение через session.extensions.loadExtension до первой страницы ChatGPT.
- BrowserSessions получает узкий prepareNavigation hook. Для ChatGPT он ожидает готовность расширения до loadURL и до расходования bootstrapToken. После ожидания проверяются освобождение страницы, актуальность запроса и конкурирующая навигация. Чужой URL не запускает скачивание. Ошибка до первого корня не создаёт/не отправляет q; сохраняется существующая обработка ошибки страницы.
- Существующая схема одного q, токенов, WAL, отзывов, принадлежности, sent по регистрации и no-q-reload сохраняется. Расширение не выдаёт контекст и не подтверждает отправку/чтение/приёмку. Все страницы и исполнители используют ту же persistent session.
- Изолированные fixtures не трогают рабочие профили и не вызывают модели. Release-приложение не получает тестового обхода загрузки. Проверки реального расширения используют официальный пакет и локальный HTTPS host; реальный chatgpt.com не автоматизируется.

## Приёмка и проверки

1. Unit: cold/cache/offline/concurrent/retry, повреждение CRX и кэша, redirect/timeout/limit, несовпадение manifest, traversal/duplicates/symlinks, ошибка установки и loadExtension, повторный backend и выгрузка расширения.
2. Интеграция: первая страница/q ждут hook; отменённая/устаревшая/released навигация не стартует; ошибка не расходует токен и не вызывает loadURL. Backend подключает hook к настоящей session. Прежние startup/recovery suites сохраняются.
3. Нативный изолированный Electron: настоящий автоматический cold download/install/load официального 1.11; local q fixture учитывает признак при document_start; сообщение ровно одно. Второй процесс использует проверенный кэш с запрещённой сетью. Повреждение проверяется до загрузки. Это не приёмка настоящего ChatGPT или native Windows/Linux.
4. Полная Node suite, архитектура, изолированный Electron smoke, обе обязательные части Kit и проверки plugin/release-tooling. DOCS перед общей production-сборкой. Пакеты трёх ОС из одного sourceCommit; native/VM/live флаги не повышаются автоматически.
5. Готовый macOS bundle штатно устанавливается или остаётся pending при активном backend. Служба и окно не закрываются. На GitHub публикуются семь проверенных assets; тег указывает на sourceCommit, remote main совпадает с финальным HEAD.
