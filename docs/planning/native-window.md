# Встроенное окно Mac (0.5.0)

## Результат

На Mac обычный запуск Workflow Pilot открывает встроенное окно фоновой службы: родной сайдбар и настоящая страница ChatGPT (WebContentsView Chromium) в одном окне, без передачи кадров через HTTP. Ввод, буфер обмена, контекстное меню, перетаскивание файлов и вставка картинок работают средствами Chromium. Закрытие окна не останавливает работу: страницы, наблюдатели, выполнение планов, Review, MCP и туннель продолжаются в службе, как с 0.2.0.

HTTP-клиент остаётся: для проверки на Mac, для iPad и для будущего переноса службы на Linux/VPS. На Mac он открывается пунктом «Окно через HTTP (тест)»; в Настройках переключателя режима нет и отдельного ярлыка нет.

## Устройство

### Страницы службы: два режима

- `BackendBrowserHost` получает режим страниц, выбираемый при старте службы: `view` на macOS и `offscreen` в остальных случаях (Linux, VPS, fixtures offscreen-режима). Режим не меняется во время работы, потому что offscreen задаётся при создании webContents.
- В режиме `view` каждая страница — WebContentsView с прежними webPreferences (partition, preload наблюдателя, sandbox, `backgroundThrottling: false`). Пока страница не показана во встроенном окне, она находится в скрытом окне-хосте службы (show: false), которое не появляется на экране и не берёт фокус.
- Показ страницы во встроенном окне переносит её WebContentsView из окна-хоста в окно (addChildView), скрытие — обратно; страница при этом не перезагружается, CDP-подключение и перехват выбора файлов сохраняются.
- Кадры и ввод для HTTP-зрителей (Mac-клиент, iPad) работают в обоих режимах через `PagePresentation`: в `view` кадр снимается через CDP `Page.captureScreenshot` с ограниченной частотой (у страницы в скрытом окне-хосте нет поверхности экрана, и capturePage отвечает «Current display surface not available for capture»), в `offscreen` — capturePage по событиям paint. Окно-хост — скрытый BaseWindow без собственной страницы. Popup-окна авторизации остаются скрытыми окнами службы.
- Пробная проверка (T001) пройдена на fixture-службе: страница в скрытом окне-хосте выполняет таймеры JavaScript, принимает ввод, отдаёт кадры через CDP примерно за 70 мс, переносится в окно и обратно без перезагрузки; полный тест представления (popup, выбор файла, перетаскивание, выделение, lease) проходит в режиме `view`. Поведение настоящего ChatGPT в окне-хосте — в живой приёмке. Исходное условие проверки: страница в скрытом окне-хосте продолжает выполнять JavaScript, наблюдатель страницы и отправку fixture-чата, отдаёт непустые кадры, переносится между окнами без перезагрузки. Если хотя бы одно не выполняется, работа останавливается и решение возвращается пользователю.

### Встроенное окно

- Модуль окна принадлежит службе (`src/backend/native-window.mjs`), а не процессу клиента: только служба владеет webContents страниц. Модуль загружает сайдбар по тем же `ui/index.html` и `preload.cjs`, что и клиент (по пути ресурса, без импорта кода frontend), и показывает выбранную страницу справа.
- Окно — поверхность (surface) модели Desktop рядом с удалённой поверхностью событий: состояние публикуется обеим; окна архива, цветов и выбор папки открываются у того окна, из которого пришло действие (встроенное — у себя, HTTP-клиент — у себя, iPad — по прежним ограничениям).
- Действия сайдбара встроенного окна идут через ту же точку входа операций службы, что и `ui.invoke` клиента: тот же allowlist каналов, журнал операций до эффекта и lease. Встроенное окно — локальный клиент службы со своим clientId; оно и HTTP-клиент работают одновременно: управляет держатель lease, другой наблюдает или забирает управление, как сейчас Mac и iPad.
- Закрытие окна (кнопка, Cmd+W, Cmd+Q в меню окна, «Завершить» на плитке Dock) закрывает только окно: страница возвращается в окно-хост, lease освобождается, каналы окна снимаются, служба продолжает работу. Остановка службы — как сейчас, из меню значка; сигналы ОС (выход из системы) останавливают службу штатно.
- Встроенное окно — тот же модуль клиента (`frontend/desktop/client.mjs`, режим embedded), который точка входа передаёт службе фабрикой: служба не импортирует код frontend. Окно подключается к API службы по loopback со своим clientId, вместо кадров прикрепляет настоящий WebContentsView выбранной страницы; меню правой кнопки страницы — системное (вырезать, копировать, вставить, выделить всё), выбор файла и загрузки идут через зрителя без кадров.
- Пока встроенное окно открыто, у службы есть плитка Dock и меню приложения (activation policy `regular`); после закрытия окна служба снова без плитки (`accessory`). Окна архива и цветов встроенного режима открывает служба по тем же HTML и preload; общий код окна цветов переносится туда, где его можно использовать без нарушения границ модулей.

### Запуск

- Обычный запуск на Mac (Finder, Dock, Spotlight, повторный запуск) запускает службу, если она не работает, и вызывает операцию `window.open`; процесс запуска затем завершается. `window.open` — класс операций `window`: без lease и журнала (это показ, а не работа), с удалённого устройства запрещена (`REMOTE_LOCAL_ONLY`). Служба другой версии или без встроенного окна получает прежнее окно клиента с объяснением. Работающая служба на повторный запуск, activate и пункт меню значка «Открыть Workflow Pilot» показывает своё окно (или выводит его вперёд), а не запускает клиент.
- «Окно через HTTP (тест)» в меню значка и в меню встроенного окна запускает прежний клиент с флагом `--http-client`; он подключается к той же службе по HTTP с прежним lease. Fixture-клиенты (`--client-fixture`) остаются окнами клиента; путь запуска в fixtures включает `--client-launcher`.
- На Linux, а позже для удалённой службы, обычный запуск открывает HTTP-клиент, как сейчас. Выбор «Фоновая служба: на этом Mac / удалённая (адрес)» относится к отдельному этапу VPS.
- In-process окно разработки (`frontend/desktop/application.mjs`) остаётся только smoke-стендом и недоступно packaged-сборке.

## Проверка

Автоматически (fixtures, без показа и фокуса окон ОС, без модельных ходов):
- Служба в режиме `view`: страница fixture-чата в скрытом окне-хосте загружается, наблюдатель видит состояние, отправка проходит, кадры непустые; перенос в окно и обратно не перезагружает страницу.
- Служба в режиме `offscreen` проходит прежние тесты backend и клиента.
- Встроенное окно fixture-службы: сайдбар получает состояние, выбор сессии показывает страницу в окне, действия идут через операции с lease; закрытие окна оставляет страницу и выполнение; HTTP-клиент одновременно наблюдает и может забрать управление.
- Запуск: работающая служба на повторный запуск открывает окно, а не клиент; пункт «Окно через HTTP (тест)» запускает клиент.
- Существующие unit-all, electron-smoke, kit-check, architecture и migration-compatibility проходят.

Живая приёмка пользователем: запуск из Dock/Finder/Spotlight открывает встроенное окно; закрытие окна во время ответа ChatGPT и повторное открытие; вставка текста и картинки, контекстное меню, перетаскивание файлов; окно через HTTP одновременно со встроенным; iPad при открытом и закрытом встроенном окне; длительная работа плана с закрытым окном (страница в окне-хосте).

## Границы

- Служба по-прежнему владеет страницами и работой; встроенное окно — ещё одна поверхность, а не возврат работы в окно.
- Режим страниц выбирается при старте службы; переключение без перезапуска службы не делается.
- Перенос службы на Linux/VPS и выбор удалённой службы в Настройках — отдельный этап; здесь только сохраняется режим `offscreen` и HTTP-клиент.
- Windows не меняется: служба и клиент как в 0.4.x.
- Донорский проект и его приложение не меняются.

## Состояние реализации

Проверено автоматически (T001–T004): `tests/backend-native-pages.test.mjs` — страницы режима `view` и `offscreen` на настоящей fixture-службе; `tests/backend-native-window.test.mjs` — встроенное окно (состояние, lease, настоящая страница, закрытие и повторное открытие без перезагрузки), процесс запуска, `window.open` без lease и с отказом удалённому устройству, встроенное окно вместе с процессом HTTP-клиента (один пишущий, ввод через клиента, закрытие во время работы); полный тест представления (`browser-presentation`) идёт в режиме `view`.

Фактические ограничения:
- Popup-окна авторизации во встроенном режиме показываются как окна клиента с кадрами, а не настоящими окнами Chromium.
- При одновременно открытых встроенном окне и HTTP-клиенте в Dock две плитки Workflow Pilot.
- Windows и Linux работают как в 0.4.x: страницы `offscreen`, обычный запуск — HTTP-клиент.
- Служба 0.4.x, запущенная до установки 0.5.0, не знает `window.open`: новый запуск откроет окно клиента с предложением остановить старую службу.

Ожидает живой приёмки пользователем: перечисленное в разделе «Проверка», включая вход в ChatGPT через popup и длительную работу настоящего ChatGPT в окне-хосте при закрытом окне.
