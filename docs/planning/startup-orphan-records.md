# Старт службы и записи исполнителей удалённого проекта (0.4.5)

Временная спецификация выпуска 0.4.5. После выпуска действующее содержание переносится в docs/modules/backend.md и docs/modules/project-lifecycle.md, документ удаляется.

## Найдено при живой приёмке 0.4.4

Фоновая служба 0.4.4 завершалась сразу после старта (`COMMAND_FAILED`), пункт «Запустить фоновую службу» не помогал. Причина: тестовый проект WP_0.4.0_Test был удалён, а запись его исполнителя T001 осталась вместе с worktree, чей `.git` указывает на удалённый репозиторий. Проверка незавершённых транзакций Kit при старте (`assertNoPendingKitTransactions`) вызвала git в этом worktree и выбросила ошибку, остановив весь запуск. Запись осталась потому, что «Убрать из списка» удаляет только сам проект, а удаление с диска — только исполнителей, чьи worktree удалось найти.

## Требования

1. Один отсутствующий, очищенный или битый проект не мешает старту службы. Если состояние транзакции Kit проекта нельзя прочитать (папки нет, git не открывает checkout), проект пропускается при проверке старта; его ошибка видна при выборе проекта. Действительно незавершённая транзакция Kit по-прежнему останавливает старт (`BACKEND_KIT_TRANSACTION_PENDING`).
2. «Убрать из списка» и удаление проекта с диска убирают из приложения и записи всех его исполнителей (по владельцу: projectId и папка родителя), даже если их worktree не найден. Папки исполнителей при «Убрать из списка» не трогаются, как и папка проекта.

## Проверки

- Unit: старт пропускает проект с битым worktree и с отсутствующей папкой; незавершённая транзакция Kit останавливает старт.
- Unit: «Убрать из списка» и подтверждённое удаление убирают записи исполнителей родителя, не трогая соседей.
- Живую проверку выполняет пользователь.
