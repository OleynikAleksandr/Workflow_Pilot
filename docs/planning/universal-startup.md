# Единый старт сессий через панель

Любая новая локальная сессия получает короткое DOM-приглашение открыть панель. Роль и наличие плана не выбирают транспорт. Все части полного ролевого recovery идут через panel/read_context/startup_complete в одном ходе. O сохраняет полномочия своего плана, E получает только recovery назначения, обычный чат получает собственный пакет без права выдавать grant или общаться от имени O. Текст задания E и выбранный контекст по-прежнему готовит O.

Для обычных и legacy-сессий вводится участник S со своим запуском связи, изолированным от O/E. Получение контекста не меняет роль сессии и не назначает второго оркестратора. Ошибки подтверждения identity, актуальности пакета или назначения блокируют выдачу; fallback на вложения запрещён. Отправленные и UNKNOWN попытки не воспроизводятся, неотправленный старый черновик сохраняется с явным отказом; новый чат запускается через панель.

Генератор прежнего сообщения с вложениями сохранён отдельным модулем без вызовов из production-пути. Низкоуровневый модуль прикрепления файлов остаётся, но первоначальный контекст его больше не использует. E подтверждает весь пакет до рабочего уведомления, заканчивает bootstrap и не начинает task:start без отдельного поручения.

Адресные проверки: матрица ролей и состояний плана, публичный panel/read/complete, полнота UTF-8, чужой получатель, stale/restart, отсутствие grant у S, рабочий цикл E и отсутствие DOM-вложений, запрет старой неотправленной попытки. Выпуск 0.5.22: DOCS, комплект трёх ОС из одного commit и штатная установка без остановки службы. Живые проверки выполняет пользователь; GitHub publication не запрошена.
