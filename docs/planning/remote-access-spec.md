# Workflow Pilot — доступ к backend из интернета (iPad через Tailscale)

Статус: спецификация плана `workflow-pilot-remote-access` для Claude Review. Реализация — только после отдельного согласия пользователя. База: выпуск 0.2.1 ([Backend](../modules/backend.md)), план 0.2.x принят и закрыт 16.10.2026.

## 1. Результат

Пользователь открывает интерфейс Workflow Pilot на iPad в Safari из любой точки интернета (дом, мобильная сеть, чужой Wi-Fi) и работает с тем же backend на своём Mac: видит и ведёт те же страницы ChatGPT, проекты, AutoPlan и Review. Mac и iPad могут быть подключены одновременно: одно окно управляет, остальные наблюдают; управление передаётся явно (существующий lease).

## 2. Решения пользователя

- Транспорт — Tailscale: Mac и iPad в одной личной tailnet. Промежуточного этапа «только домашняя сеть» нет: тот же путь работает дома (напрямую) и вне дома.
- Служба не публикуется в открытый интернет: Tailscale Funnel, проброс портов роутера и публичный адрес запрещены.
- Подключение Tailscale входит в мастер первого запуска как необязательный шаг с последовательными инструкциями для компьютера и для удалённого устройства; тот же сценарий — в Настройках.
- Реализация начинается только после согласия пользователя с планом: после публикации план переводится в BLOCKED (`plan:apply`, blocked_reason) до записанного в user_decisions согласия. Номер выпуска предлагается 0.3.0; задача версии блокируется до подтверждённого пользователем номера.

## 3. Топология

- Основной API backend остаётся на `127.0.0.1` со случайным портом и descriptor; клиент Mac не меняется.
- Новый удалённый шлюз backend — отдельный loopback-порт для веб-клиента, включаемый явно в настройках («Доступ с других устройств»), по умолчанию выключен. Шлюз отдаёт веб-клиент и проксирует к тем же операциям, что и основной API; собственных операций в обход API нет.
- Tailscale Serve публикует шлюз только внутри tailnet по HTTPS: `https://<mac>.<tailnet>.ts.net` → `127.0.0.1:<порт шлюза>`; сертификат выдаёт Tailscale. Workflow Pilot не устанавливает Tailscale, не входит в аккаунт и не меняет его настройки без явного действия пользователя: мастер проверяет состояние (`tailscale status`, `tailscale serve status`), показывает или по кнопке с подтверждением выполняет команду Serve и проверяет результат. Funnel не используется никогда.
- Mac должен быть включён, в сети и не спать. При включённом удалённом доступе backend удерживает систему от сна (power assertion, без запрета сна дисплея); закрытая крышка без питания остаётся ограничением.

## 4. Аутентификация и права

Три независимых слоя:
1. Сеть: запрос приходит только через Tailscale Serve на loopback-шлюз; прямой доступ из LAN невозможен.
2. Владелец tailnet: шлюз принимает только запросы с заголовком Tailscale Serve `Tailscale-User-Login`, равным владельцу, подтверждённому при включении; запросы без заголовка (не через Serve) отвергаются. Проверить в T001, что заголовок нельзя подделать в обход Serve.
3. Устройство: первое подключение показывает на iPad одноразовый код; Mac (окно или значок) показывает запрос с именем устройства, пользователь подтверждает. Устройство получает отдельный долгоживущий токен (cookie `HttpOnly; Secure; SameSite=Strict`, хранится хешем), список устройств с последним входом и отключением в настройках Mac. Отключение мгновенно закрывает потоки устройства и снимает его lease.

**Право управления устройства.** Сейчас lease подтверждается только номером поколения, который виден всем подписчикам, а `clientId` называет сам клиент. Для удалённых устройств этого недостаточно. Шлюз сам назначает устройству `clientId` (из записи устройства) и подменяет им `args.clientId` в `control.acquire/renew/release`; для мутирующих команд, ввода, вставки, файлов и viewport шлюз проверяет, что текущий держатель lease — именно это устройство, иначе `BACKEND_LEASE_STALE`. Viewer принадлежит создавшему его устройству; чужие viewerId недоступны. Наблюдатель с подсмотренным номером поколения получает отказ.

**Подтверждение и отзыв.** Запрос пары доставляется в окно Mac (состояние модели Desktop, новое действие подтверждения в фиксированном списке каналов и preload) и в меню значка; подтвердить можно в любом из них. Отзыв устройства вызывает принудительный `revoke(clientId)` lease (новая операция владельца lease, не через generation держателя), отсоединяет его viewers и закрывает его потоки событий.

Локальные процессы того же пользователя Mac могут обратиться к loopback-шлюзу напрямую и подделать заголовок слоя 2; поэтому слой 3 (подтверждённое устройство) обязателен для каждого запроса, кроме страницы подключения, а одноразовый код подтверждается только на Mac. Эти процессы уже находятся внутри границы доверия (профиль пользователя), но не получают доступ без подтверждения.

Дополнительно: точный Host `*.ts.net` шлюза и Origin веб-клиента, защита от CSRF, ограничение частоты попыток кода, журнал входов в `backend-events.jsonl` без токенов. Удалённое устройство получает те же разрешённые операции, что окно Mac; CDP, JavaScript, shell и пути backend по-прежнему недоступны. Выбор папки проекта на iPad — ввод пути на Mac или из списка разрешённых корней, не файловый диалог iPad.

## 5. Веб-клиент iPad

- Тот же UI (`src/frontend/desktop/ui`): боковая панель, архив, настройки, Доктор, цвета. Preload Electron заменяется браузерной прослойкой `window.webPilot` поверх API (`ui.invoke`, SSE), без второй реализации логики.
- Оконные команды (`ui.open-archive`, `open-colors`, `focus`, `layout`, `close-archive`) сейчас рассылаются всем клиентам. Они адресуются клиенту-инициатору: `ui.invoke` несёт `clientId`, событие доставляется только ему. Действие на iPad не открывает окна на Mac и наоборот; у удалённого клиента архив и редактор цветов открываются внутри страницы.
- Выбор папки проекта сейчас открывает нативный диалог backend на Mac. С удалённого клиента он заменяется вводом пути или выбором из разрешённых корней (родительские папки существующих проектов), с той же проверкой setup; нативный диалог на Mac не открывается.
- Изображение страницы: касание → pointer, прокрутка пальцем → wheel, долгое нажатие → контекстное меню, масштаб жестом — только масштаб кадра на клиенте.
- Ввод: экранная клавиатура iPad через скрытое поле, русский и составной ввод (composition), аппаратная клавиатура iPad.
- Буфер обмена: копирование выделения и вставка только по явному действию пользователя (ограничения Safari проверить на iPad).
- Файлы: вложение через выбор файла Safari → существующие transfers; скачивание в «Файлы» iPad.
- Popups и авторизация ChatGPT — отдельный слой просмотра внутри веб-клиента.
- Состояние связи, устаревание и наблюдение — как у окна Mac; переподключение после сна iPad или смены сети без повторной отправки.

## 6. Кадры через интернет

Полные PNG годятся для loopback, но не для мобильной сети. Требования: сжатые кадры (JPEG/WebP с настраиваемым качеством), плотность по `devicePixelRatio` устройства, передача только при изменении, ограничение частоты и адаптация к пропускной способности. Видеопоток (WebRTC) — только если эти меры не обеспечат комфорт на живой проверке. Viewport страницы задаёт управляющее устройство; переход управления между Mac и iPad меняет размер страницы без её перезагрузки.

## 7. Мастер первого запуска и настройки

Удалённый доступ — отдельный необязательный шаг [мастера первого запуска](../modules/first-run-onboarding.md) после подключения ChatGPT и туннеля MCP: «Доступ с iPad и других устройств». Шаг можно пропустить; тот же сценарий доступен позже в Настройках. Каждый шаг проверяется состоянием компьютера, а не отметкой пользователя; при ошибке показывается понятная причина и кнопка повторной проверки. Мастер не вводит пароли, не входит в аккаунт Tailscale и не меняет его настройки без явной кнопки с подтверждением.

**На компьютере с Workflow Pilot (Mac; для Windows и Linux — те же шаги со своими ссылками):**
1. «Установите Tailscale». Кнопка открывает официальную страницу загрузки. Мастер проверяет, что приложение установлено и запущено.
2. «Войдите в Tailscale» (Google, Apple, Microsoft, GitHub или почта) и включите подключение. Мастер показывает аккаунт и имя этого компьютера в сети Tailscale.
3. «Разрешите HTTPS в вашей сети Tailscale» — один раз в панели управления Tailscale (раздел DNS: MagicDNS и HTTPS Certificates). Кнопка открывает нужную страницу, мастер проверяет результат.
4. «Включите доступ с других устройств». После подтверждения Workflow Pilot настраивает Tailscale Serve только внутри вашей сети, проверяет адрес `https://<имя-компьютера>.<сеть>.ts.net` и включает запрет сна на время удалённого доступа.
5. Мастер показывает адрес и QR-код для iPad и объясняет: компьютер должен оставаться включённым и подключённым к интернету; крышку ноутбука без питания не закрывать.

**На iPad (или другом удалённом устройстве):**
1. Установите Tailscale из App Store и войдите тем же аккаунтом, что на компьютере. Разрешите добавление конфигурации VPN и включите переключатель Tailscale.
2. Откройте в Safari показанный адрес или отсканируйте QR-код камерой.
3. На iPad появится код подключения, а на компьютере — запрос с именем устройства и тем же кодом. Подтвердите его на компьютере.
4. По желанию: «Поделиться» → «На экран Домой», чтобы открывать Workflow Pilot как приложение.
5. Если адрес не открывается: проверьте, что Tailscale включён на обоих устройствах, компьютер не спит, а фоновая служба Workflow Pilot работает (значок в строке меню). Подсказки выводятся прямо на странице ошибки шлюза, если она доступна.

**В Настройках компьютера:** состояние Tailscale и Serve, адрес и QR-код, список подтверждённых устройств с последним входом и кнопкой «Отключить», кнопка «Выключить доступ с других устройств» (снимает настройку Serve, созданную Workflow Pilot, и закрывает все удалённые сессии). Тексты шагов — короткие, последовательные, на русском, без технических терминов там, где можно обойтись без них; технические детали — в раскрываемой подсказке.

## 8. Контракт шлюза и проверки

- Шлюз переиспользует существующие обработчики: команды (`/v1/commands` с allowlist), операции, поток событий (SSE) и `/v1/browser/*`. Аутентификация шлюза — cookie устройства вместо bearer; клиент Mac продолжает работать по bearer на основном порту. Устройство получает свой `clientId` и lease как отдельное окно.
- Шлюз отдаёт статические файлы веб-клиента только из собственного каталога пакета (без обхода путей), с CSP, запрещающим сторонние источники.
- Порт шлюза фиксирован (кандидат 18854) с проверкой владельца и подбором свободного порта при конфликте; настройка Serve указывает фактический порт и пересоздаётся при его смене.
- Ошибки: `REMOTE_DISABLED`, `REMOTE_OWNER_MISMATCH`, `REMOTE_DEVICE_REQUIRED`, `REMOTE_DEVICE_REVOKED`, `REMOTE_PAIRING_EXPIRED`, `REMOTE_RATE_LIMIT`, `TAILSCALE_NOT_INSTALLED`, `TAILSCALE_LOGGED_OUT`, `TAILSCALE_HTTPS_DISABLED`, `TAILSCALE_SERVE_CONFLICT` (порт 443 Serve занят чужой настройкой — не перезаписывается).
- Автоматические проверки: fixtures шлюза за локальным прокси, имитирующим заголовки Serve; поддельный CLI Tailscale для мастера; веб-клиент в Chromium-fixture и jsdom. Safari/WebKit на iPad, настоящий Tailscale и мобильная сеть — живая проверка пользователя; fixture не объявляется проверкой iPad.

## 9. Вне объёма

Funnel и любой публичный адрес; другие транспорты (Cloudflare, VPS); нативное приложение iPad; голос, камера и микрофон; несколько пользователей; автоматический запуск Mac или выход из сна по сети.

## 10. Критерии приёмки

- R01 Удалённый доступ выключен по умолчанию; включение и выключение явные, состояние видно на Mac.
- R02 Без Tailscale Serve, без заголовка владельца, с чужого аккаунта tailnet или без подтверждённого устройства доступ невозможен; отключённое устройство теряет доступ сразу.
- R03 iPad из мобильной сети открывает интерфейс, видит те же проекты и страницу, берёт управление; Mac становится наблюдателем и возвращает управление явно.
- R04 Ввод с экранной клавиатуры (русский, составной), касания, прокрутка, меню ответов и разговора работают; поздний ввод другого документа отвергается.
- R05 Вложение файла с iPad и скачивание на iPad работают сквозным образом.
- R06 Сон iPad, смена сети и обрыв не повторяют мутаций, Send и recovery; переподключение к той же странице.
- R07 Объём кадров через интернет ограничен; задержка и чёткость приемлемы на живой проверке.
- R08 Окно Mac, плагин ChatGPT и MCP работают как в 0.2.1; основной API остаётся loopback.
- R09 Мастер первого запуска и Настройки проводят пользователя по шагам для компьютера и iPad, проверяют каждый шаг фактическим состоянием, допускают пропуск и повторную проверку; выключение снимает только собственную настройку Serve.
- R10 Документы, выпуск трёх ОС, установка и GitHub Release по обычному порядку; iPad и Tailscale — живая проверка пользователя.

## 11. Деление на задачи

Последовательно (общие владельцы: backend API, lease, UI):
- T001 Сверить Tailscale Serve по официальной документации и тестовому прокси: заголовки идентичности, Host/Origin/X-Forwarded-*, HTTPS, буферизация SSE, обход Serve; сравнить PNG/JPEG/WebP кадров по объёму и чёткости на fixture и наличие кодировщика (Electron nativeImage умеет PNG и JPEG). Агент только читает состояние Tailscale (`version`, `status --json`, `serve status --json`); живую проверку Serve выполняет пользователь по инструкции либо агент после явного подтверждения с `serve reset` своей настройки; иначе pending manual. Итог записывается в эту спецификацию.
- T002 Удалённый шлюз и контракт: включение/выключение, порт, Host/Origin/CSRF, заголовок владельца, cookie устройства, назначение `clientId` устройства и проверка держателя lease для мутаций и `/v1/browser/*`, владение viewer, прокси к существующим операциям и событиям, раздача веб-клиента, ошибки `REMOTE_*`.
- T003 Пара устройств: одноразовый код, запрос в окне Mac и меню значка, токены устройств, список, принудительный отзыв со снятием lease, viewers и потоков, журнал входов, ограничение попыток.
- T004 Веб-клиент: прослойка `window.webPilot` поверх API, тот же UI, адресация оконных команд инициатору, архив и цвета внутри страницы, выбор папки вводом пути, состояние связи, наблюдатель/управление, переподключение; проверка в Chromium-fixture.
- T005 Изображение страницы на iPad: касания, прокрутка, долгое нажатие, экранная и аппаратная клавиатура с составным вводом, буфер обмена по действию, файлы туда и обратно, popups.
- T006 Сжатые адаптивные кадры: формат по итогу T001, плотность по устройству, только изменения, ограничение частоты; viewport управляющего устройства.
- T007 Tailscale в мастере первого запуска и Настройках: обнаружение CLI по известным путям трёх ОС (на macOS — внутри `Tailscale.app`, не в PATH) с `TAILSCALE_NOT_INSTALLED`, состояние Tailscale, QR-код проверенной библиотекой, шаги для компьютера и iPad, Serve по кнопке с подтверждением, QR-код, устройства, запрет сна, выключение.
- T008 Общая проверка: сквозной сценарий fixture (включение → пара → управление с удалённого клиента → обрыв → переподключение → отзыв устройства), регрессия 0.2.1, сценарий пользователя для iPad.
- T009 Версия выпуска (предложение 0.3.0, подтверждает пользователь).
- DOCS, затем T010 сборка трёх ОС, T011 установка в `/Applications`, T012 GitHub Release.

## 12. Действия пользователя до живой проверки

Установить Tailscale на Mac и iPad под одним аккаунтом и один раз разрешить HTTPS в панели Tailscale — по шагам мастера. Workflow Pilot сам не устанавливает Tailscale и не входит в аккаунт.
