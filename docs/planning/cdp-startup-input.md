# Старт сессии через CDP-ввод (0.6.4)

Статус: решение пользователя 30.10.2026. Заменяет отправку первой команды через адрес `chatgpt.com/?q=…` (chat-only-url-bootstrap, 0.5.33) для всех ролей: сессия планирования/обсуждения, оркестратор и исполнители.

## Проблема

Три выпуска подряд (0.6.1–0.6.3) латали сбои автоотправки `?q=` при загрузке новой страницы ChatGPT: восстановленный черновик, «Учетная запись сменилась» с локальным разговором, команда в поле без отправки на корне `/` (T_001). Все они возникают внутри загрузки q-документа, которым Workflow Pilot не управляет.

## Решение

Стартовая команда вводится в уже проверенный предварительный документ корня `/` через общий CDP-канал страницы (`webContents.debugger`), как доверенный ввод пользователя:

1. Предварительная проверка не меняется: чистый корень, вход подтверждён, поле доступно, черновик пуст (восстановленная чужая команда очищается), генерации нет; пакет, приглашение и `contextRef` сохранены до ввода.
2. Composer в том же документе (`documentId` наблюдателя) ставит фокус в поле и курсор в конец. Это не ввод и не Send.
3. `Input.insertText` вставляет команду. Затем проверка в странице: поле содержит ровно команду (`draftMatches`), Send доступен, генерации нет, документ тот же.
4. Несовпадение, смена документа, отмена или ошибка до Enter — ничего не отправлено: Composer очищает только свою точную команду (`clear-new-draft` с шаблоном), попытка отзывается как `start-not-sent` и один раз автоматически стартует заново с новым приглашением (механизм 0.6.3). Чужой или смешанный текст не стирается.
5. Перед Enter runtime принимает токен попытки (`navigationOwner = requestId`, один раз на токен: `BOOTSTRAP_ALREADY_DISPATCHED`) без новой навигации и без смены epoch. Enter — `Input.dispatchKeyEvent` keyDown (`text '\r'`) и keyUp. Runtime и клиент iPad/HTTP шлют клавиши через один `webContents.debugger`, поэтому runtime пропускает в `before-input-event` ровно свой keyDown Enter (счётчик собственных нажатий, взведённый непосредственно перед отправкой). Любой другой ввод (клавиша или нажатие мыши пользователя, в том числе с iPad) с начала ввода и до Enter меняет версию подготовки страницы и отменяет попытку без Enter; после Enter он, как и прежде, снимает владельца стартовой навигации.
6. Ошибка после начала Enter — `unknown`, повтора нет. Отправку по-прежнему подтверждают регистрация панели и настоящий адрес `/c/<id>`, который in-page навигация ChatGPT связывает с токеном.
7. На время ввода включается `Emulation.setFocusEmulationEnabled`, после — выключается: фоновым страницам не нужен фокус окна ОС.

`bootstrapTransport` новой попытки — `composer-input`; `url-query` распознаётся только у попыток, сохранённых прежними версиями (отзыв/восстановление). Отправка `?q=` удаляется целиком, второго пути нет. Защиты от перезагрузки и восстановления q-адреса остаются.

## Защита 0.6.3 расширяется

Если после Enter ChatGPT оставил разговор локальным (`/c/local-…`) или страница осталась на корне с той же командой в поле, без генерации и без сообщений, через 30 с это доказанная неотправка: отзыв приглашения и один автоматический новый старт; второй сбой — оранжевая причина «ChatGPT дважды не отправил стартовое сообщение».

## Правило клавиатуры

Прежнее правило «нет резервного Send через DOM/клавиатуру» уточнено решением пользователя: первая команда отправляется доверенным CDP-вводом (`insertText` и Enter) ровно один раз; DOM-клика Send и резервного второго пути нет. Доставка следующих сообщений не меняется.

## Критерии приёмки

- Для всех ролей (обсуждение, оркестратор, исполнитель) первая команда не попадает в адрес; навигаций на `?q=` нет.
- Enter нажимается только после точной проверки текста в том же документе; без проверки команда очищается и не отправляется.
- Один токен — не более одного Enter; ошибка после Enter не повторяется.
- Владелец стартовой навигации снимается после привязки адреса (0.6.2) и вводом пользователя, но не собственным Enter runtime; чужой ввод до Enter отменяет попытку.
- Проверка на настоящем Electron: скрытые фоновые страницы исполнителей и smoke стартуют через CDP-ввод; fixtures реагируют на ввод в поле и Enter, а не на q.
- Локальный разговор или корень с неотправленной командой ведут к одному автоматическому повтору.
- Версия 0.6.4; выпуск трёх ОС из одного sourceCommit; полный VERIFY не выполняется по решению пользователя, только целевые проверки; живую проверку выполняет пользователь.

## Ограничения

Ввод в фоновой странице через CDP проверен для видимого клиента (iPad/HTTP), для фоновой стартовой команды первая живая проверка за пользователем. Если пользователь печатает в той же странице во время старта, проверка точного текста не даст отправить смесь.
