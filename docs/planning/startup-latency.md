# Ускорение стартового контекста O

Продолжение принятого функционального старта 0.5.20: пользователь подтвердил работоспособность, но поручил сократить задержку и собрать новый выпуск. В наблюдаемом Test_06 от выбора сессии до startup.complete прошло 97,317 с. Не приписываем промежутки скрытому рассуждению модели.

## Решение

Применить уже используемые у E принципы: контекст подготовлен до триггера, полезный блок возвращается сразу инструментом, независимые чтения не требуют отдельных ходов. Bootstrap O открывает панель и продолжает тот же ход. Ответ workflow_pilot_panel после проверки приглашения/host identity и свежести пакета содержит startup_context: message_id, digest, первую часть, число частей и инструкции. Это подтверждает выдачу контекста через MCP, а не готовность iframe/SDK. Готовность панели остаётся независимым фактом; grant плана не выдаётся.

Новый пакет с delivery_mode=model-pull никогда не запускает SDK-уведомление: потерянный ответ восстанавливается повторным открытием панели/чтением того же пакета, без повторной отправки. Первая часть и read receipt сохраняются атомарно до ответа инструмента. Повтор безопасен; запрет чужого O/E, stale/cancel/remove, SHA и чтение всех частей перед ack сохраняются. Завершение ответа не подменяется ack. Для старых пакетов 0.5.20 сохраняется прежний SDK/UNKNOWN протокол: нельзя переводить уже начатый Send в новый канал.

read_message нового старта тоже возвращает первую часть. Остальные части можно читать независимо/параллельно, не превышая бюджет 28000 байт на часть с оформлением (текст 24000). Полный пакет не складывать в один огромный ответ. startup_complete обязателен и не разрешает выполнение. Панель при model-pull показывает прогресс без wait/claim/Send и без ожидания завершения первого модельного хода; обновление состояния отделено от MCP-чтения агентом. Для рабочих E/O сохраняются требования bind, физического конца хода, SDK intent/UNKNOWN и автоматическая отправка авторизованного поручения.

## Проверки и поставка

Адресные тесты через настоящий публичный panel/read_context/startup_complete путь: старт без SDK и без окончания bootstrap, первая часть в panel, атомарность/повтор/restart, старый UNKNOWN, stale/cancel/remove/чужой разговор, отсутствие grant и дублирующего SDK, многочастный UTF-8/лимит, инструкции bootstrap/MCP и панель. Регрессия рабочего диалога E и старых вложений. Полная suite и Kit без изменений не нужны.

Выпуск 0.5.21, отдельная DOCS, сборка трёх ОС из одного sourceCommit и штатная установка готового macOS bundle. Не останавливать приложение/службу; занятая копия означает pending. До production-сборки очистить только Python cache tools/codex-app-server-mcp без симлинков. Живое ускорение и хост проверяет пользователь. Публикация GitHub в это поручение не входит.
