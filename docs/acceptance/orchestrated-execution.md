# Приёмка оркестрованного выполнения 0.5.6

Статус: автоматические проверки пройдены; живая приёмка пользователем ожидается. Контракт — [оркестрованное выполнение](../modules/orchestrated-execution.md).

## Подготовка

1. Штатно остановите старую службу, завершите pending-установку при её наличии и откройте 0.5.6. Для автоматического диалога — новые разговоры/workspace по [S1–S3](../modules/automatic-agent-dialogue-acceptance.md); старый план сохраняет маршрут.
2. Откройте проект с Kit 1.8.2; прежний Kit обновляет installer при отсутствии незавершённых назначений/интеграций.
3. Для проекта, который выпускает приложение, задайте хвост выпуска через `config:apply` с `delivery_tail` (для Workflow Pilot: `three-platform-release` → `release-installed` → `github-release`).

## Сценарий

| № | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Новая Chat/Work-сессия проекта без плана | В дереве «Оркестратор · Планирование» |
| 2 | Обсудить задачу, попросить спецификацию и план | План оркестратора опубликован (при Review ON — после согласования); выполнение не началось, в шапке плана «Начать выполнение плана» |
| 3 | Открыть ещё одну сессию | В дереве «Обсуждение»; агент не меняет план и не создаёт документов без просьбы |
| 4 | Нажать «Начать выполнение плана» | Последовательная задача получает отдельный чат исполнителя; параллельные стартуют вместе в пределах лимита |
| 5 | Кликнуть ● и ✓ в to-do plan, затем оркестратора в дереве | Справа открывается сессия исполнителя в режиме Chat с полученной задачей; слева остаются дерево и to-do plan с выделенной строкой; клик по оркестратору возвращает его диалог; ○ не кликабельна |
| 6 | Нажать «Пауза» во время параллельной волны | Работающие исполнители доделывают, новые задачи не выдаются; затем «Продолжить» |
| 7 | Исполнитель не может завершить задачу | Оркестратор получает сообщение о блокировке и отвечает; при невозможности — пауза и объяснение в его диалоге |
| 8 | Дождаться DOCS и delivery | Оркестратор получает итоговое поручение, затем задачи выпуска по одной и очистку; остаётся один main |
| 9 | Открыть оркестратор выполненного плана | Пометка «Выполнено», итог доступен; после удаления worktree выбор выполненной задачи оставляет оркестратора |
| 10 | Повторить шаги 4–6 с iPad | Кнопка работает с правом управления устройства |
| 11 | Перенести проект с выполняемым планом в архив, вернуть, затем удалить | Подтверждение; план на паузе после возврата; удаление убирает проект и worktree исполнителей |
| 12 | Посмотреть карточку плана без плана, у прежнего плана и у плана оркестратора | Нигде нет «Включить автовыполнение»; у прежнего и оркестрованного плана одна кнопка выполнения |

Отметьте результат каждого шага и сохраните `backend-events.jsonl` при отклонениях.

## Проверка нового диалогового маршрута

Для автоматизации 0.5.6 по S1–S3 проверить нового Chat/Work оркестратора и новые Chat-назначения: один Start, без ручных ID, открытия панелей исполнителей и Enable. Живой результат пока NOT_RUN.

- Исполнитель сначала пробует разрешённый ремонт, затем сохраняет ошибку, попытки, состояние команд/файлов и точку продолжения через task:block. Его задача остаётся IN_PROGRESS; независимый исполнитель продолжает работу.
- Оркестратор получает block_id и отвечает через assignment:message --block-id. Исполнитель автоматически продолжает ту же задачу до проверенного коммита и интеграции; accepted/read недостаточны.
- Поздний ответ на предыдущий block_id не снимает новую блокировку. Третье повторение той же проблемы с прежним problem_id требует эскалации с фактами; новый цикл требует явного решения пользователя.
- При паузе заблокированное назначение без активных команд паркуется; после одной кнопки Continue работа возобновляется. Исполнитель и оркестратор одновременно общую среду не меняют.
- Открытая подключённая сессия получает обновлённые роли через очередное сообщение; task:start, первоначальный контекст и выполненные команды не повторяются. Исторический результат панели не разрешает отправку.
