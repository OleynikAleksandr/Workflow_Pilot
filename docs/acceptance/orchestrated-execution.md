# Приёмка оркестрованного выполнения 0.5.22

Живые опыты **A–D — NOT_RUN**. Test_02 0.5.7 — FAIL целевого workflow, несмотря на два проверенных коммита. [Контракт](../modules/orchestrated-execution.md), [подробные A–D](../modules/automatic-agent-dialogue-acceptance.md).

## Основной опыт

1. Пользователь запускает установленную службу 0.5.22 / Kit 1.9.3, панель 0.5.22-communication-4. Pending-установка завершается штатно после остановки старой службы пользователем.
2. Новый workspace/O, обычный полный bootstrap; панель открывается автоматически. Обсудить spec/to-do двух независимых E, Review по выбору пользователя, публикация без запуска.
3. Нажать Start один раз, остаться у O. E создаются и получают минимальный bootstrap без посещения карточек; O одновременно сохраняет prepare с dispatch_when_ready=true. После ready backend отправляет неизменяемый авторский task/context без дополнительного хода O. До готовности канала grant и отправки нет.
4. E выполняют задачи, вопросы и результаты отправляют O по каналу. O уточняет, решает проблему, проверяет diff/proof, принимает точный SHA и интегрирует штатным Kit. Не считать READY/DONE E общим DONE.
5. После интеграций автоматически запускаются зависимые задачи/DOCS, допустимо при продолжающемся текстовом ответе O; O готовит и авторизует актуальный контекст одновременно с bootstrap. Итог может перекрываться с терминальными квитанциями E, но cleanup/complete ждут все доказательства. Worktree очищаются только после интеграции, терминальных квитанций и конца команд E. До complete UI различает 3/3 интеграции и завершение плана, показывает причину и время стадии. После complete нет активной «Паузы», есть инструкция приёмки; restart сохраняет завершение. Архив complete не предупреждает об остановке и не возобновляет работу при возврате; незавершённый план требует подтверждения.

## Регрессии интерфейса и жизненного цикла

- Новый чат при активном плане — обсуждение, не второй владелец. Выбор task/E сохраняет to-do O слева; кнопки отдельного запуска связи нет.
- Выбор E во время bootstrap проверяется отдельным опытом: сохраняется исходная страница/Send/наблюдение до постоянного URL, без второго чата. Он не заменяет основной опыт без посещений.
- Пауза в новом режиме запрещает новые назначения/SDK-пробуждения/интеграции, текущий ход сохраняет outbox и заканчивает команды. Continue общий, без Enable/ID.
- Блокировка: question → clarification → facts → decision по одному block_id; уточнения не расходуют попытки ремонта, старое решение не снимает новую блокировку. Третья неудачная попытка требует предметной эскалации.
- Результат возвращён до merge: новая попытка, новый proof/result/acceptance; только потом INTEGRATED. После INTEGRATED исправление отдельной задачей.
- Архив всего активного проекта с подтверждением ставит его на паузу; возврат требует Continue. Подтверждённое удаление незавершённого проекта не требует DONE, «Убрать из списка» сохраняет папки; сосед продолжает, ссылки не оживают после restart.
- Restart — один Continue, UNKNOWN не повторяется. Закрытие только окна при живом backend проверяется отдельно со временем событий.
- Тот же интерфейс/кнопка доступны HTTP-клиенту/iPad с правом управления. Старые sequential/parallel сохраняют прежний маршрут; миграция активного 0.5.7 — явная безопасная операция O.

Каждый опыт получает отдельный результат, действия пользователя и очищенный экспорт. Автоматические fixtures, native Windows/Linux, clean install, iPad через мобильную сеть и настоящий ChatGPT не взаимозаменяемы. Модели и живые профили разработка не запускает; приёмка и закрытие scope остаются за пользователем.
