# Приёмка Workflow Pilot 0.5.35

Исправления семи замечаний тестирования 0.5.34: UI001, REVIEW001–003, EXEC001–002 и STATUS001. Прежняя [приёмка D001–D011](release-0534-defects.md) сохраняет собственные результаты; её статусы не переносятся на этот выпуск.

Автоматические проверки используют временные проекты, настоящий Kit/Git, backend API, Python MCP, полный HTML/SDK и Chromium renderer с детерминированными ответами. Модельные команды, пользовательские профили, службы и удалённый Test_002 не используются. Живые ChatGPT/macOS, native Windows/Linux и реальный iPad/Tailscale — **NOT_RUN** до проверки пользователем.

## Подготовка

Проверить фактически работающую службу 0.5.35, Kit проекта 1.10.1 и новую панель `0.5.35-communication-5`, протокол 5. Установка приложения не заменяет старый iframe. Если installer оставил pending из-за работающего backend, сначала штатно завершить переход версии; закрытия окна недостаточно.

Создать новый тестовый workspace и новый обычный Chat. Первая команда открывает панель с приглашением; полный контекст приходит через неё. Ручные ID/join/Enable и DOM Send для рабочего канала не нужны. Не восстанавливать удалённый Test_002.

## Живые случаи

| Случай | Ожидание | Результат |
| --- | --- | --- |
| UI001 | В sidebar нет кнопки «Текущие действия», dialog-копии и замены в меню. Полный выбор только в основной MCP-панели. Review на прежнем месте; опубликованный план и необходимые recovery-действия доступны по условиям. | NOT_RUN |
| REVIEW001 | До задания включить Review. Решение адресовано этой сессии; после разрешённой доставки агент знает ON и сверяет review:status перед prepare/публикацией. Запись/SDK accepted/read различаются в диагностике. Переключение не запускает реализацию. | NOT_RUN |
| REVIEW002 | Во время фактического Review в основной панели видны Claude, номер раунда, затем рассмотрение замечаний и ожидание публикации. Выбор другого проекта не подставляет чужой раунд. | NOT_RUN |
| REVIEW003 | История содержит подготовку пары, запрос/запуск, отзыв, позицию автора и публикацию. Повторный раунд имеет свой номер; после публикации и повторного открытия история остаётся без дублей и выдуманных дат. | NOT_RUN |
| EXEC001 | После одного Start два независимых E подключаются автоматически. Обычная задержка регистрации не создаёт оранжевого RECIPIENT; задача каждому передаётся один раз, без дополнительного сочинения O после Start. Настоящий отказ остаётся видимым. | NOT_RUN |
| EXEC002 | Выбор режима до публикации, в том числе без новой видимой пользовательской реплики, не удерживает результаты после Start. O получает оба result, принимает точные SHA и интегрирует их; затем идут зависимая задача, DOCS, cleanup и complete. | NOT_RUN |
| STATUS001 | Главная строка объясняет фактическую работу/ожидание. Старый выбор или команда названы причиной задержки, прочитанный result не называется недоставленным или уже проверенным. Оранжевое означает нужное действие; инструкция и таймер не перекрываются при сужении панели. | NOT_RUN |

Для рабочего плана использовать два независимых небольших изменения, зависимый интеграционный пример и DOCS. Поручения и выбранный контекст всех задач должны быть сохранены до Review/публикации. После выбора оркестрации нажать Start один раз и не посещать E ради их запуска. Сверить четыре интеграции отдельно от передачи результатов и отдельно от complete. Принимать и закрывать план только после собственной проверки результата.

HTTP-клиент без MCP iframe не имеет удалённого fallback выбора. Это ограничение; новый экран не создаётся. Если возникает реальная ошибка, сохранить время, текст и диагностику до повторных действий; неизвестный Send не повторять.

## Автоматические доказательства

- `automatic-agent-dialogue.test.mjs` / `fixtures/automatic-agent-dialogue.mjs`: OFF → ON/read → реальное нажатие карточки MCP без нового user bubble → changes_requested/позиция → второй Review/approved/позиция → публикация → один Start → задержка reservation двух E → task/read → два result/read/acceptance → интеграции → зависимая задача → DOCS → cleanup/complete. Без модельных вызовов.
- `workflow-channel`, `plan-review`, `prepared-task-flow`, `dialogue-delivery` и recovery tests: WAL/intent/read, rapid toggle, restart, точный адресат, stale identity/attempt, manual Stop и UNKNOWN, поздние callbacks и один эффект. Снятие одного gate не снимает чужой запрет.
- `electron-smoke`: реальный sidebar/preload/IPC для Review, актуальный backend → Python MCP → полный HTML/SDK для двух раундов и истории публикации. Отсутствие копии проверяется также HTTP fixture.
- `current-actions-layout`: Chromium, 320/480/900 CSS px, обе темы, 100/200% текста; длинная инструкция/ID и таймер без горизонтального clipping. Jsdom сам по себе геометрию не доказывает.

Назначенные проверки зафиксированы в Git/evidence задач, включая обе части Kit (`kit-check` и `kit-assignments`). DOCS с checks:[] не запускает application tests и не служит их доказательством. Сборка трёх ОС, manifest/архивы/подпись, установленная либо проверенная pending-копия и GitHub assets проверяются отдельными RELEASE/INSTALL/PUBLISH; результаты находятся в manifest и Kit evidence. Они не повышают live/native статусы этой таблицы.
