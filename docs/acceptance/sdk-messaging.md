# Проверка постоянного SDK — Workflow Pilot 0.5.38

[Контракт](../modules/sdk-messaging.md). Автоматические доказательства и живая приёмка разделены. Экспериментального режима и шагов активации нет. Новый подробный сценарий живой проверки формулируется с пользователем после выпуска.

## Автоматические доказательства

Задачи SDK/PROOF/VERSION плана `sdk-messaging` сохраняют фактические checks и SHA в Git/Workflow Kit. Проверены назначенные unit-all, electron-smoke, chatgpt-plugin, executor-channel, codex-tools-live, architecture, обе части kit-check/kit-assignments, kit-upgrade и release-tooling. DOCS не запускает эти проверки повторно и не является их доказательством.

| Область | Проверенное свойство |
| --- | --- |
| Адресная доставка | O→E, E→O и сервисные сообщения приложения используют один SDK; busy, активная команда, draft, prior accepted/unread/read/yield не задерживают следующий вызов |
| Очередь передачи | Один in-flight на получателя, больше двух сообщений, независимые адресаты, сохранение порядка intent, приоритет claimed/UNKNOWN над другим pending |
| Полный цикл | Реальные API/MCP/HTML-панель/Kit/Git; подготовка до Start, параллельные E, зависимая задача и DOCS, read, acceptance точного SHA, интеграции, terminal/cleanup/complete |
| Сбои | Две панели, restart/remount/lease loss, неизвестный исход, поздний Promise, ручной Stop/Continue и неверная identity без повторов SDK или интеграции |
| Старые планы | SDK вместо DOM после свежего Continue; сохранённый legacy UNKNOWN Review/continuation блокирует только тот же чат, включая новые типы сообщений/новый scope |
| Electron | Настоящая кнопка выполнения вызывает SDK; продолжение зависимой задачи передано при занятом чате и сохранённом черновике; восстановление не повторяет отправку |
| Инструкции и upgrade | Реальный MCP-каталог dispatch/yield согласован с SDK; неизменяемые архивы Kit 1.10.1/1.10.2 обновляются до 1.10.3/ролей 12 без замены плана |
| Версии панели | Package/backend/build/протокол и immutable HTML согласованы, несовместимый старый iframe получает явный отказ |

Fixtures используют изолированные временные проекты и симулированного хоста ChatGPT. Проверка SDK-вызова через настоящий код панели и MCP не доказывает внутреннюю очередь живого ChatGPT. Команды моделей и пользовательские рабочие профили в этих тестах не запускаются.

## Живая приёмка

| Проверка | Статус |
| --- | --- |
| Живой ChatGPT: все роли, занятый O/E, команды, несколько входящих, полный цикл | NOT_RUN |
| Новый установленный macOS backend и штатное восстановление реальных чатов | NOT_RUN |
| Native Windows/Linux, clean install/VM | NOT_RUN |
| iPad/HTTP/Tailscale | NOT_RUN |

Прежний Test_04 доказал приём двух result занятому O, чтение и две интеграции в ограниченном опыте. Остальные задачи шли прежним путём; это не PASS всей новой схемы. Его старые OFF/burst/GO условия отменены новым поручением полного перехода и не являются условиями публикации 0.5.38.

Поставка трёх ОС, подпись/состав/хеши, локальная установка или verified pending и GitHub проверяются отдельными delivery-задачами после DOCS. Факты находятся в release-manifest.json, записях Kit и опубликованном комплекте. Ни сборка, ни pending-копия, ни публикация не заменяют запуск новой версии и живую приёмку.
