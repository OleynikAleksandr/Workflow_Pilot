## Автоматические доказательства

Текущий план incoming-obligations-and-sdk-recovery сохраняет checks/SHA в Git/Kit. Выполнены intake-instructions, выбранный actual MCP catalog/send/status/yield, sdk-recovery-targeted, closed-card-targeted, один intake-sdk-scenario, kit-upgrade, architecture, chatgpt-plugin, panel-resource-targeted. Для изменённого Kit отдельно проверены check-package, check-plan-review-fixture и check-orchestrated-execution-fixture. Это адресные проверки; unit-all, весь electron-smoke и полный Kit этого раунда не запускались. DOCS не повторяет тесты и не является доказательством их PASS.

Fixtures используют временные проекты и подставленного хоста ChatGPT; модельные команды и рабочие профили не запускаются. Они подтверждают сформированные инструкции и технический маршрут, но не доказывают, что настоящая модель всегда продолжит все запросы. Поздний ответ SDK может быть проигнорирован самим SDK; accepted не выдумывается. Прежние полные suite и Electron smoke относятся к предыдущим выпускам; причина отдельных старых bootstrap-тайм-аутов не установлена.

## Живая приёмка

В тесте 002_Test на 0.5.40 Review был прочитан, но исходный пользовательский запрос продолжился после напоминания. Результат T003 был сохранён, три уведомления получили -32000/unknown, а read появился после напоминания. Это задержанная обработка, а не доказанная потеря содержимого. Первопричина -32000 не установлена. Финальное отображение DOCS пользователь признал неподтверждённым инцидентом; под него исправлений нет. Живой основной сценарий 0.5.39 принят пользователем и сохранён в README.

Поставка трёх ОС, подпись/состав/хеши, локальная установка либо verified pending и GitHub проверяются отдельными delivery-задачами после DOCS.
