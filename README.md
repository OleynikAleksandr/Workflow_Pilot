# Workflow Pilot

Настольное приложение: локальные проекты, планы и сессии ChatGPT Web. Chat и Work используют веб-аккаунт ChatGPT; локальные файлы и команды доступны через собственный MCP-исполнитель, без модельных запросов к OpenAI API. С 0.2.0 работа идёт в фоновой службе: окно можно закрыть, а план, ChatGPT, MCP и туннель продолжат работать. С 0.3.0 тот же интерфейс открывается на iPad из любой точки интернета через вашу сеть Tailscale.

## Версия и готовность

Экспериментальная версия исходников 0.5.13, Electron 44.5.1, Node 24.21.0, Workflow Kit 1.9.3. Добавлен [пассивный пробник PiP](docs/modules/pip-probe.md) в существующее MCP-подключение: два независимых ресурса и синтетические данные, без управления агентами. Одновременное отображение с основной панелью проверяет пользователь; перенос плана из sidebar и настоящая лента переписки ещё не реализованы.

[Фоновая служба](docs/modules/backend.md) владеет страницами ChatGPT, проектами, выполнением планов и Review, MCP, туннелем и мостом плагина. Обычный запуск на macOS, Windows и Linux открывает [встроенное окно](docs/modules/native-window.md) с настоящей страницей ChatGPT; для проверки и iPad доступен отдельный HTTP-клиент. Закрытие окна не завершает службу.

[План](docs/modules/orchestrated-execution.md) ведёт одна кнопка «Начать выполнение плана» / «Пауза» / «Продолжить» и Review. Новые планы выполняют оркестратор и исполнители в отдельных worktree; начатые sequential/parallel-планы сохраняют прежний механизм с той же кнопкой. Выбор проекта/сессии не меняет владельца фоновой работы. [Проекты и архив](docs/modules/project-lifecycle.md), [ввод и файлы](docs/modules/desktop.md), [доступ с iPad](docs/modules/remote-access.md).

В 0.5.12 O сохраняет основу поручений task_brief ещё при планировании. После Start читает уже доступные подготовительные уведомления и авторизует поручения одним ходом; отправка ждёт подтверждённой готовности каждого канала. Итог по умолчанию короткий. После подтверждённого complete панель прекращает wait/sync без ложной сетевой ошибки; новая работа требует восстановления актуальной привязки. Sidebar различает интеграции, завершение ответа и пользовательскую приёмку. Kit 1.9.2 штатно обновляется до 1.9.3.

В живом контрольном опыте 0.5.10 подтверждены три интеграции, очистка, complete и отсутствие «Паузы». Новые оптимизации 0.5.12 проверены изолированными fixtures; фактическое ускорение ChatGPT ещё предстоит измерить по [таймингам](docs/modules/dialogue-timing.md).

[Оркестратор управляет диалогом](docs/modules/assignment-dialogue.md): после одного Start сам выдаёт E задачи и выбранный контекст, уточняет проблемы, принимает точные результаты и выполняет проверенные интеграции. E получают минимальный bootstrap без всего проекта, обязательно отправляют result и продолжают после решения O. Два-пять E автоматически подключаются без посещения карточек/ID/Enable; доработка, DOCS/cleanup и итог входят в тот же канал.

В 0.5.7 согласована конкурентная подготовка общей службы; выбор исполнителя сохраняет уже открытый разговор до получения постоянного адреса. Карточка различает bootstrap, регистрацию, SDK и прочтение задания. Незавершённый план больше не запрещает убрать проект из приложения или подтвердить удаление его репозитория и собственных worktree. Сбой транзакции Kit удерживает только свой проект, архив остаётся доступным.

Состав комплекта подтверждает release-manifest.json. Test_02 0.5.7 — FAIL целевого workflow; [живые A–D нового выпуска](docs/modules/automatic-agent-dialogue-acceptance.md) — NOT_RUN. Fixtures/Review не заменяют приёмку ChatGPT. Остальные отложенные требования окна, Review и readiness сохраняются в docs/planning. [Следующие этапы backend](docs/planning/backend-independence-followup.md), [происхождение и лицензия](PROVENANCE.md).

## Установка и запуск

На macOS arm64 установите Node 24.21.0 и Git, затем из корня проекта:

```bash
npm ci
npm start
```

Prestart подготавливает Kit, observer и HTML плагина. `npm start` открывает клиент; если фоновая служба не запущена, клиент запускает её сам. Используется собственный профиль `~/Library/Application Support/Workflow Pilot` (профиль 0.1.6 подходит без изменений). Пройдите [мастер](docs/modules/first-run-onboarding.md): самостоятельный вход/регистрация ChatGPT, подготовка компьютера, свой Secure MCP Tunnel и коннектор. VPS требует отдельного собственного маршрута; без него отображается необходимость настройки. Ключи, cookies и службы донора не импортируются.

Для существующего проекта выберите папку, проверьте предложение Kit, создайте новую Chat/Work-сессию и отправьте recovery. Прежде прекратите исполнение этого же плана в другом приложении. [Совместимость старых проектов](docs/modules/project-compatibility.md).

**Окно и фоновая служба.** «Закрыть окно (работа продолжится в фоне)», Cmd+Q, Cmd+W и закрытие окна закрывают только окно — встроенное окно или HTTP-клиент. Пункт «Окно через HTTP (тест)» в меню значка и меню окна открывает HTTP-клиент рядом со встроенным окном. Состояние службы показывает значок в строке меню; повторное открытие Workflow Pilot (Dock, Finder, Spotlight или значок → «Открыть Workflow Pilot») возвращает к той же странице. Чтобы остановить всё, выберите значок → «Остановить фоновую службу…» или то же в меню Workflow Pilot: новые отправки прекратятся, текущий ответ ChatGPT, инструменты и команды Kit завершатся, затем служба выйдет. Остановку во время ожидания можно отменить; принудительного завершения нет. Без системного tray (часть Linux-окружений) статус и остановка доступны в меню клиента. Одновременно управляет одно окно; другие наблюдают, пока управление не взято явно.

**iPad из любой точки интернета.** Настройки → «Доступ с iPad и других устройств» (или шаг «+ Доступ с iPad» в мастере). Tailscale бесплатен для личного использования (тариф Personal); входите личным аккаунтом Google, Apple или GitHub, не рабочей почтой на собственном домене — она создаёт платную сеть организации. На компьютере: установите Tailscale, войдите, один раз разрешите HTTPS в панели Tailscale (DNS → HTTPS Certificates) и нажмите «Включить доступ с других устройств». На iPad: установите Tailscale из App Store тем же аккаунтом, откройте показанный адрес в Safari (или QR-код), подтвердите код на компьютере. Доступ работает только внутри вашей сети Tailscale, без публичного адреса; пока он включён, компьютер не засыпает.

**Готовый комплект и обновление.** Комплект находится в `~/Downloads/WorkflowPilot-<version>`; распакуйте пакет своей платформы и следуйте INSTALL.txt. После каждого выпуска штатный installer обновляет `/Applications/Workflow Pilot.app` и собственную копию в корне проекта без пересборки; он не закрывает и не перезапускает приложение. Переход с 0.1.6: полностью завершите 0.1.6 и откройте новую копию из Applications. Переход с 0.2.0 и новее: закрытия окна недостаточно — остановите фоновую службу (значок или меню), дождитесь её выхода и откройте новую версию. Если служба работала во время установки, installer оставил проверенную копию в ожидании: после остановки службы повторите установку. Клиент новой версии, подключившийся к старой службе, только объясняет переход. Подробности — [контракт поставки](docs/modules/release.md); Linux-зависимости — [Linux runtime](docs/modules/linux.md).

## Проверки

Адрес панели зависит от её содержимого. После обновления приложения обновите инструменты подключения Workflow Pilot в ChatGPT и попросите оркестратора заново вызвать панель. Старая панель из истории может сохранить прежний HTML; переустановка приложения её не переписывает. Очистка истории и профиля не требуется. [Контракт обновления](docs/modules/chatgpt-plugin.md#ресурс-панели-и-обновление).

После запуска проверить службу 0.5.13, Kit 1.9.3, свежий MCP-каталог и панель `0.5.13-communication-3`, протокол 3. В этом эксперименте открыть `pip_probe_open_dialogue` рядом с основной панелью и выполнить [проверку PiP](docs/modules/pip-probe.md). Рабочий протокол и матрица [A–D](docs/modules/automatic-agent-dialogue-acceptance.md) версии 0.5.12 не менялись; их прежние результаты не доказывают совместимость двух UI. Ручной join/Enable остаётся только в отдельном [legacy P0/P1](docs/modules/plugin-communication-handoff.md). Старые активные назначения переходят через [штатную безопасную миграцию](docs/modules/assignment-dialogue-reliability.md#переход-старого-плана); обновление не переключает их молча.

```bash
npm test
npm run smoke
npm run check:architecture
npm run check --prefix packages/workflow-kit
node --test tests/codex-app-server-mcp.test.mjs
npm run check:codex-tools
```

Unit suite использует четыре процесса и включает backend-тесты на временных профилях с локальной fixture-страницей вместо ChatGPT. Smoke запускает скрытый in-process стенд разработки с изолированными Chromium fixtures. Executor fixtures используют настоящий Codex App Server без модельных ходов; Python-среда тестов — .harness/runtime/test-python (Python 3.13.9, requirements.txt; для Linux fixtures также mss/python-xlib). Проверки не заменяют действия пользователя в аккаунте, native VM и clean-install.

[Приёмка 0.2.x и сценарий Mac](docs/acceptance/backend-independence.md), [приёмка и сценарий iPad](docs/acceptance/remote-access.md), [приёмка оркестрации](docs/acceptance/orchestrated-execution.md), [результаты миграции 0.1.x](docs/acceptance/migration-0.1.0.md), [архитектура и карта модулей](docs/architecture/OVERVIEW.md).

Сборка: npm run build, только в назначенной delivery-задаче после DOCS. Обязательны все три платформы из одной базы; подпись выбирается явно. Частичный комплект не публикуется.
