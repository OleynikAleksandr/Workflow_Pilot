# Workflow Pilot

0.5.40 — оранжевое выделение только для необходимого действия пользователя и корректная карточка закрытого плана. Ожидание операций, решений оркестратора и очистки нейтрально. Примеры кода внутри задания больше не обрывают чтение истории. [Контракт внимания](docs/modules/current-actions.md), [закрытый план](docs/modules/project-lifecycle.md#закрытый-план). Доставка через SDK и идентичность workspace сохранены.

Настольное приложение: локальные проекты, планы Workflow Kit и сессии ChatGPT Web. Локальные файлы и команды доступны через собственный MCP-исполнитель без модельных запросов к OpenAI API. Backend продолжает работу после закрытия окна; тот же интерфейс доступен на iPad через Tailscale.

## Что подтверждено в живой работе

В пользовательском тесте 0.5.39 на macOS 27 октября 2026 года основной чат одновременно служил разговорным интерфейсом и оркестратором проекта. Пользователь обсуждал с агентом посторонние вопросы, пока два исполнителя выполняли независимые задачи. Результаты поступали через SDK, оркестратор читал их, принимал точные SHA и интегрировал изменения. После интеграции T001 и T002 продолжилась зависимая T003, затем DOCS; вручную управлять исполнителями не потребовалось.

Во время обсуждения названий утилиты оркестратор получил результат T003, занялся его проверкой и интеграцией, затем вернулся к вопросу пользователя. Разговор не остановил выполнение плана: отдельный управляющий цикл модели и запрет общения с оркестратором не понадобились.

| Компонент | Ответственность |
| --- | --- |
| ChatGPT | Очерёдность обработки входящих сообщений и ходы модели; агент ведёт диалог, проверяет результаты и принимает решения |
| Workflow Pilot | Сохранение сообщений, уведомления через SDK, запуск исполнителей и их жизненный цикл; отправка не ждёт «освобождения» чата |
| Workflow Kit | Состояние плана, зависимости, проверки, принятие конкретных коммитов и Git-интеграции |

Доставка и чтение результатов T001/T002, их интеграции и получение задания T003 проверены по журналу и Git. По итоговому отчёту тестового оркестратора все четыре задачи завершены и интегрированы, worktree очищены, Git чистый, `node --test` — 10/10 PASS, CLI — PASS. Пользователь принял результат и закрыл план исправлений приложения; приёмка тестового плана — отдельное действие.

Это подтверждает основной сценарий совместной работы диалога и оркестрации, но не все пограничные случаи. Длительная занятость модели, массовое поступление событий, прерывания и сетевые сбои требуют отдельных живых проверок. Тест не раскрывает внутреннее устройство очереди ChatGPT и не означает непрерывного рассуждения модели между ходами. Ложное предупреждение и ошибка карточки после закрытия исправлены в 0.5.40 и проверены на fixtures; новая живая приёмка ожидается.

## Версия и готовность

Перед первой страницей ChatGPT приложение автоматически скачивает и проверяет официальное поисковое расширение, устанавливает его в свой каталог и подключает к браузерной сессии. При повторном запуске использует проверенный кэш без загрузки. Первому запуску нужен доступ к Google download host; ошибка подготовки показывается до открытия страницы и отправки q. [Контракт расширения](docs/modules/chatgpt-search-extension.md).

Только обычный ChatGPT Chat, без выбора режима и чтения старых Work-сессий. Новая локальная сессия получает одну короткую команду открытия панели с тикетом через `q`; проверяются вход, принадлежность и пустой черновик нужного документа. DOM-ввода и повтора неизвестной отправки нет. Полный recovery приходит через панель: первая часть в ответе инструмента, остальные через MCP, затем SHA-подтверждение. Регистрация, адрес, контекст и разрешение плана подтверждаются отдельно; E ждёт рабочего поручения. [Контракт старта](docs/modules/chat-only-startup.md), [приёмка](docs/acceptance/chat-only-startup.md).

Выпуск — 0.5.40, Electron 44.5.1, Node 24.21.0, Workflow Kit 1.10.4. [Фоновая служба](docs/modules/backend.md) владеет страницами ChatGPT, проектами, выполнением планов и Review, MCP, туннелем и мостом плагина. Обычный запуск на macOS, Windows и Linux открывает [встроенное окно](docs/modules/native-window.md) с настоящей страницей ChatGPT; для проверки и iPad доступен отдельный HTTP-клиент. Закрытие окна не завершает службу.

**Workflow Kit 1.10.4.** Новые orchestrated-планы сохраняют полный task_brief и prepared_task каждой обычной задачи и DOCS до Review/публикации. Неизменяемые байты, автор, project/scope и semantic digest проверяются до выдачи. После Start приложение механически связывает пакет с настоящим назначением и доставляет каждому готовому E без нового хода O для сочинения. Старые brief-only планы сохраняют прежний путь. Штатный installer обновляет проектный Kit отдельно от приложения и добавляет общее `.DS_Store`, сохраняя пользовательские правила. [Контракт подготовки](docs/modules/prepared-tasks.md), [совместимость](docs/modules/project-compatibility.md).

**Исправления startup и состояния плана.** После выдачи первой части S может закончить чтение **того же** защищённого SHA-снимка при соседнем изменении plan_revision; до первой выдачи stale отклоняется, O/E и проверки identity/SHA/полноты не ослаблены. В Desktop/HTTP и панели receipt `startup.complete` приоритетнее старого `delivery=pending`, а текущая отмена прекращает дальнейшую выдачу; ошибка/stale — терминальный статус с дальнейшим действием, без бесконечного spinner/повторного Send. Незавершённая транзакция Kit удерживает только затронутый проект (`PROJECT_RECOVERY_REQUIRED`); после проверенного закрытия удержание снимается автоматически, **не включая** sequential-продолжение и не отменяя паузу O. Ручная пауза и технический OFF различаются. Кнопка плана при удержании остаётся штатной перепроверкой: пока транзакция открыта, она отказывает; после снятия sequential-план показывает «Продолжить». [Контракт startup](docs/modules/orchestrator-startup.md).

**Проверяемый прогресс.** UI отдельно показывает полученные результаты E (checked source/Kit proof) и интеграции в main (Kit DONE), различает prepared/authorized/pending/SDK accepted/прочтение/начало работы. `READY_FOR_ACCEPTANCE` при всех DONE означает ожидание приёмки пользователя для orchestrated и sequential/parallel-плана, даже пока scope ACTIVE. Квитанции и ответы prepare/dispatch оркестратору содержат `delivery_stage`, `delivered` и пояснение: сохранённое или разрешённое поручение не называется доставленным. `DOCS checks:[]` — отсутствие **запуска application checks этой задачей**, а не доказательство их PASS. Полная `unit-all` и назначенные адресные проверки выполнены в коммитах исправлений и автоматических регрессий; **DOCS с пустым `verification_ids` не запускает их повторно**. [Изолированные O1/O2/E1/E2/NET](docs/acceptance/interruption-recovery.md) автоматизированы, все семь **живых** Stop/NET/UI/RESTART-сценариев остаются `NOT_RUN` и требуют отдельного запуска пользователем.

[План](docs/modules/orchestrated-execution.md) ведёт одна кнопка «Начать выполнение плана» / «Пауза» / «Продолжить» и Review. Режим нового плана выбирает пользователь: сам последовательно или оркестрация с исполнителями в отдельных worktree. Начатые legacy-планы сохраняют семантику Kit и ту же кнопку, но доставка также использует SDK; старые неизвестные отправки не повторяются. Выбор проекта/сессии не меняет владельца фоновой работы. [Проекты и архив](docs/modules/project-lifecycle.md), [ввод и файлы](docs/modules/desktop.md), [доступ с iPad](docs/modules/remote-access.md).

[Текущая работа](docs/modules/current-actions.md) показана в основной MCP-панели: одна понятная причина, независимая работа участников, история и свёрнутая диагностика. Слева остаются навигация, нейтральный агент, опубликованный план и необходимые операции восстановления. Выбор после сохранения нейтрален, после read — в истории. Review читается из актуального Kit, оба раунда и позиции автора сохраняются после публикации. Тексты и инструкции переносятся целиком. Кнопки «Текущие действия» и dialog-копии нет; HTTP без MCP iframe не получает удалённый fallback выбора.

Смена generation/истёкшая lease восстанавливаются через существующие status/sync/wait с проверкой identity и без второго Send. MAIN_DIRTY даёт техническую паузу и «Продолжить»; свежий preflight не снимает ручную паузу и UNKNOWN. Сохранённый собственный Chat URL не теряется из-за старого startup attempt. [Повторная приёмка D001–D011](docs/acceptance/release-0534-defects.md) и [тайминги](docs/modules/dialogue-timing.md) отделяют fixture PASS от живого опыта.

[Оркестратор управляет диалогом](docs/modules/assignment-dialogue.md): после одного Start сам выдаёт E задачи и выбранный контекст, уточняет проблемы, принимает точные результаты и выполняет проверенные интеграции. E получают минимальный bootstrap без всего проекта, обязательно отправляют result и продолжают после решения O. Два-пять E автоматически подключаются без посещения карточек/ID/Enable; доработка, DOCS/cleanup и итог входят в тот же канал.

После одного Start оркестратор ведёт уточнения, принимает точные результаты и интеграции; готовность E не требует посещения его карточки. DOCS, terminal receipts, cleanup и итог предшествуют complete. Удаление незавершённого проекта сохраняет адресную остановку и защиту соседей; новая работа не разрешает повтор неизвестной отправки.

Состав комплекта подтверждает release-manifest.json. Test_02 0.5.7 — FAIL целевого workflow; [живые A–D нового выпуска](docs/modules/automatic-agent-dialogue-acceptance.md) — NOT_RUN. Fixtures/Review не заменяют приёмку ChatGPT. Остальные отложенные требования окна, Review и readiness сохраняются в docs/planning. [Следующие этапы backend](docs/planning/backend-independence-followup.md), [происхождение и лицензия](PROVENANCE.md).

| Платформа | Формат | Статус |
| --- | --- | --- |
| macOS arm64 | .app / ZIP | Вход/туннель/контекст подтверждены ранее; автоматические проверки пройдены; живая приёмка A–D ожидается |
| Windows x64 | Portable ZIP | Реализация и fixtures проверены; native/UTM pending |

## Установка и запуск

На macOS arm64 установите Node 24.21.0 и Git, затем из корня проекта:

```bash
npm ci
npm start
```

Prestart подготавливает Kit, observer и HTML плагина. `npm start` открывает клиент; если фоновая служба не запущена, клиент запускает её сам. Используется собственный профиль `~/Library/Application Support/Workflow Pilot` (профиль 0.1.6 подходит без изменений). Пройдите [мастер](docs/modules/first-run-onboarding.md): самостоятельный вход/регистрация ChatGPT, подготовка компьютера, свой Secure MCP Tunnel и коннектор. VPS требует отдельного собственного маршрута; без него отображается необходимость настройки. Ключи, cookies и службы донора не импортируются.

Для существующего проекта выберите папку, проверьте предложение Kit, создайте новый Chat; приложение откроет панель и передаст recovery. Прежде прекратите исполнение этого же плана в другом приложении. [Совместимость старых проектов](docs/modules/project-compatibility.md).

**Окно и фоновая служба.** Закрытие окна, Cmd+Q и Cmd+W закрывают только окно; служба продолжает работу. Повторный запуск возвращает ту же страницу. «Остановить фоновую службу…» в меню значка или окна ждёт завершения текущих ответов и команд; ожидание можно отменить. При зависшей работе выберите отдельный пункт «Принудительно остановить службу…»: после подтверждения операции прерываются, несохранённое состояние может быть потеряно. Очистке даётся до двух секунд, затем завершаются собственные процессы. Полностью заблокированный главный процесс может не обработать меню — тогда требуется системное принудительное завершение. Без tray остановка доступна в меню окна. «Окно через HTTP (тест)» открывает дополнительный клиент; одновременно управляет одно окно.

**iPad из любой точки интернета.** Настройки → «Доступ с iPad и других устройств» (или шаг «+ Доступ с iPad» в мастере). Tailscale бесплатен для личного использования (тариф Personal); входите личным аккаунтом Google, Apple или GitHub, не рабочей почтой на собственном домене — она создаёт платную сеть организации. На компьютере: установите Tailscale, войдите, один раз разрешите HTTPS в панели Tailscale (DNS → HTTPS Certificates) и нажмите «Включить доступ с других устройств». На iPad: установите Tailscale из App Store тем же аккаунтом, откройте показанный адрес в Safari (или QR-код), подтвердите код на компьютере. Доступ работает только внутри вашей сети Tailscale, без публичного адреса; пока он включён, компьютер не засыпает.

**Готовый комплект и обновление.** Комплект находится в `~/Downloads/WorkflowPilot-<version>`; распакуйте пакет своей платформы и следуйте INSTALL.txt. После каждого выпуска штатный installer обновляет `/Applications/Workflow Pilot.app` и собственную копию в корне проекта без пересборки; он не закрывает и не перезапускает приложение. Переход с 0.1.6: полностью завершите 0.1.6 и откройте новую копию из Applications. Переход с 0.2.0 и новее: закрытия окна недостаточно — остановите фоновую службу (значок или меню), дождитесь её выхода и откройте новую версию. Если служба работала во время установки, installer оставил проверенную копию в ожидании: после остановки службы повторите установку. Клиент новой версии, подключившийся к старой службе, только объясняет переход. Подробности — [контракт поставки](docs/modules/release.md); Linux-зависимости — [Linux runtime](docs/modules/linux.md). После сохранения titleSource=topic данные несовместимы с 0.5.35: откат bundle сам по себе не является откатом данных. [Условия совместимости](docs/modules/project-compatibility.md#данные-сессий-и-обратный-переход).

## Проверки

Адрес панели зависит от её содержимого. После обновления приложения обновите инструменты подключения Workflow Pilot в ChatGPT и попросите оркестратора заново вызвать панель. Старая панель из истории может сохранить прежний HTML; переустановка приложения её не переписывает. Очистка истории и профиля не требуется. [Контракт обновления](docs/modules/chatgpt-plugin.md#ресурс-панели-и-обновление).

После запуска проверить службу 0.5.40, Kit 1.10.4, свежий MCP-каталог и панель `0.5.40-communication-7`, протокол 7. Затем вживую: карточки выбора Е1–Е5 и оба режима плана ([приёмка](docs/modules/user-choice.md#проверки)), карточку сессии при сужении sidebar, ожидание запуска готового плана, ход O до появления плана, итог панели и sidebar после приёмки и закрытия плана, карточку плана с закреплёнными зонами на большом плане, стадии задач и спиннеры, «Сейчас»/«История»/«Диагностика» панели и одинаковую палитру в светлой и тёмной темах. Для любой новой сессии проверьте [получение контекста без вложений](docs/modules/orchestrator-startup.md#живая-приёмка). Для рабочего опыта — [A–D](docs/modules/automatic-agent-dialogue-acceptance.md): новый workspace, новые разговоры, один Start, без посещения E. Ручной join/Enable остаётся только в отдельном [legacy P0/P1](docs/modules/plugin-communication-handoff.md). Старые активные назначения переходят через [штатную безопасную миграцию](docs/modules/assignment-dialogue-reliability.md#переход-старого-плана); обновление не переключает их молча. Уничтоженный iframe хоста отдельно проверяется на восстановление SDK.

```bash
npm test
npm run smoke
npm run check:architecture
npm run check --prefix packages/workflow-kit
node --test tests/codex-app-server-mcp.test.mjs
npm run check:codex-tools
```

Unit suite использует четыре процесса и включает backend-тесты на временных профилях с локальной fixture-страницей вместо ChatGPT. Smoke запускает скрытый in-process стенд разработки с изолированными Chromium fixtures. Executor fixtures используют настоящий Codex App Server без модельных ходов; Python-среда тестов — .harness/runtime/test-python (Python 3.13.9, requirements.txt; для Linux fixtures также mss/python-xlib). Проверки не заменяют действия пользователя в аккаунте, native VM и clean-install.

[Приёмка 0.2.x и сценарий Mac](docs/acceptance/backend-independence.md), [приёмка и сценарий iPad](docs/acceptance/remote-access.md), [приёмка оркестрации](docs/acceptance/orchestrated-execution.md), [результаты миграции 0.1.x](docs/acceptance/migration-0.1.0.md), [архитектура и карта модулей](docs/architecture/OVERVIEW.md).

Сборка: npm run build, только в назначенной delivery-задаче после DOCS. Обязательны все три платформы из одной базы; подпись выбирается явно. Частичный комплект не публикуется.
