# Workflow Pilot

0.5.33 — запуск и выдача стартового контекста без переключателя Chat/Work. В приложении остаётся только Chat; чтения старых Work-сессий нет. Официальное ChatGPT search автоматически обеспечивает первую команду через URL, полный контекст поступает через MCP. Регистрация, адрес и чтение подтверждаются отдельно. [Контракт старта](docs/modules/chat-only-startup.md), [живая приёмка](docs/acceptance/chat-only-startup.md).

Настольное приложение: локальные проекты, планы Workflow Kit и сессии ChatGPT Web. Локальные файлы и команды доступны через собственный MCP-исполнитель без модельных запросов к OpenAI API. Backend продолжает работу после закрытия окна; тот же интерфейс доступен на iPad через Tailscale.

## Версия и готовность

Перед первой страницей ChatGPT приложение автоматически скачивает и проверяет официальное поисковое расширение, устанавливает его в свой каталог и подключает к браузерной сессии. При повторном запуске использует проверенный кэш без загрузки. Первому запуску нужен доступ к Google download host; ошибка подготовки показывается до открытия страницы и отправки q. [Контракт расширения](docs/modules/chatgpt-search-extension.md).

Любая новая локальная Chat-сессия получает короткую команду открытия панели через `q`. Перед ней проверяются вход, режим и пустой черновик нужного документа; DOM-ввод и повтор неизвестной отправки запрещены. Роль и состояние плана не выбирают транспорт. Полный ролевой recovery приходит через панель: первая часть в ответе инструмента, остальные через MCP, затем SHA-подтверждение. Обычный чат не получает полномочия O; E ждёт отдельное поручение. Новые живые старты ChatGPT остаются NOT_RUN; автоматические fixtures их не заменяют.

Выпуск — 0.5.33, Electron 44.5.1, Node 24.21.0, Workflow Kit 1.9.9. [Фоновая служба](docs/modules/backend.md) владеет страницами ChatGPT, проектами, выполнением планов и Review, MCP, туннелем и мостом плагина. Обычный запуск на macOS, Windows и Linux открывает [встроенное окно](docs/modules/native-window.md) с настоящей страницей ChatGPT; для проверки и iPad доступен отдельный HTTP-клиент. Закрытие окна не завершает службу.

**Workflow Kit 1.9.9.** Входит в приложение; с 1.9.8 записывает запрос режима агентом и выбор пользователя (`plan:mode-request`/`plan:mode-choose`) и не создаёт план сессии Workflow Pilot без него; с 1.9.7 знает владельца планирования и проверяет задачи при Review-публикации; с 1.9.6 переключатель Review действует по положению в момент публикации и заблокирован во время ревью и после публикации плана; исходный Kit и поставляемый runtime имеют версию 1.9.9; установленную копию `.harness/kit` обновляет штатный installer проекта отдельно от доставки приложения. Во время `commit --task` Kit записывает, какая проверка идёт и какая она по счёту; приложение показывает «Kit проверяет коммит · проверка · N из M». Review не имеет неявного ограничения ходов, времени и раундов; явные `--max-turns` / `--timeout-ms` доступны, при неизвестном исходе — диагностика без автоматического повторного запуска.

**Исправления startup и состояния плана.** После выдачи первой части S может закончить чтение **того же** защищённого SHA-снимка при соседнем изменении plan_revision; до первой выдачи stale отклоняется, O/E и проверки identity/SHA/полноты не ослаблены. В Desktop/HTTP и панели receipt `startup.complete` приоритетнее старого `delivery=pending`, а текущая отмена прекращает дальнейшую выдачу; ошибка/stale — терминальный статус с дальнейшим действием, без бесконечного spinner/повторного Send. Незавершённая транзакция Kit удерживает только затронутый проект (`PROJECT_RECOVERY_REQUIRED`); после проверенного закрытия удержание снимается автоматически, **не включая** sequential-продолжение и не отменяя паузу O. Ручная пауза и технический OFF различаются. Кнопка плана при удержании остаётся штатной перепроверкой: пока транзакция открыта, она отказывает; после снятия sequential-план показывает «Продолжить». [Контракт startup](docs/modules/orchestrator-startup.md).

**Проверяемый прогресс.** UI отдельно показывает полученные результаты E (checked source/Kit proof) и интеграции в main (Kit DONE), различает prepared/authorized/pending/SDK accepted/прочтение/начало работы. `READY_FOR_ACCEPTANCE` при всех DONE означает ожидание приёмки пользователя для orchestrated и sequential/parallel-плана, даже пока scope ACTIVE. Квитанции и ответы prepare/dispatch оркестратору содержат `delivery_stage`, `delivered` и пояснение: сохранённое или разрешённое поручение не называется доставленным. `DOCS checks:[]` — отсутствие **запуска application checks этой задачей**, а не доказательство их PASS. Полная `unit-all` и назначенные адресные проверки выполнены в коммитах исправлений и автоматических регрессий; **DOCS с пустым `verification_ids` не запускает их повторно**. [Изолированные O1/O2/E1/E2/NET](docs/acceptance/interruption-recovery.md) автоматизированы, все семь **живых** Stop/NET/UI/RESTART-сценариев остаются `NOT_RUN` и требуют отдельного запуска пользователем.

[План](docs/modules/orchestrated-execution.md) ведёт одна кнопка «Начать выполнение плана» / «Пауза» / «Продолжить» и Review. Режим нового плана выбирает пользователь: сам последовательно или оркестрация с исполнителями в отдельных worktree. Начатые legacy parallel-планы сохраняют прежний механизм с той же кнопкой. Выбор проекта/сессии не меняет владельца фоновой работы. [Проекты и архив](docs/modules/project-lifecycle.md), [ввод и файлы](docs/modules/desktop.md), [доступ с iPad](docs/modules/remote-access.md).

В 0.5.12 O сохраняет основу поручений task_brief ещё при планировании. После Start читает уже доступные подготовительные уведомления и авторизует поручения одним ходом; отправка ждёт подтверждённой готовности каждого канала. Итог по умолчанию короткий. После подтверждённого complete панель прекращает wait/sync без ложной сетевой ошибки; новая работа требует восстановления актуальной привязки. Sidebar различает интеграции, завершение ответа и пользовательскую приёмку. Kit 1.9.2 штатно обновляется до 1.9.3.

В живом контрольном опыте 0.5.10 подтверждены три интеграции, очистка, complete и отсутствие «Паузы». Новые оптимизации 0.5.12 проверены изолированными fixtures; фактическое ускорение ChatGPT ещё предстоит измерить по [таймингам](docs/modules/dialogue-timing.md).

[Оркестратор управляет диалогом](docs/modules/assignment-dialogue.md): после одного Start сам выдаёт E задачи и выбранный контекст, уточняет проблемы, принимает точные результаты и выполняет проверенные интеграции. E получают минимальный bootstrap без всего проекта, обязательно отправляют result и продолжают после решения O. Два-пять E автоматически подключаются без посещения карточек/ID/Enable; доработка, DOCS/cleanup и итог входят в тот же канал.

В 0.5.7 согласована конкурентная подготовка общей службы; выбор исполнителя сохраняет уже открытый разговор до получения постоянного адреса. Карточка различает bootstrap, регистрацию, SDK и прочтение задания. Незавершённый план больше не запрещает убрать проект из приложения или подтвердить удаление его репозитория и собственных worktree. Сбой транзакции Kit удерживает только свой проект, архив остаётся доступным.

Состав комплекта подтверждает release-manifest.json. Test_02 0.5.7 — FAIL целевого workflow; [живые A–D нового выпуска](docs/modules/automatic-agent-dialogue-acceptance.md) — NOT_RUN. Fixtures/Review не заменяют приёмку ChatGPT. Остальные отложенные требования окна, Review и readiness сохраняются в docs/planning. [Следующие этапы backend](docs/planning/backend-independence-followup.md), [происхождение и лицензия](PROVENANCE.md).

## Установка и запуск

На macOS arm64 установите Node 24.21.0 и Git, затем из корня проекта:

```bash
npm ci
npm start
```

Prestart подготавливает Kit, observer и HTML плагина. `npm start` открывает клиент; если фоновая служба не запущена, клиент запускает её сам. Используется собственный профиль `~/Library/Application Support/Workflow Pilot` (профиль 0.1.6 подходит без изменений). Пройдите [мастер](docs/modules/first-run-onboarding.md): самостоятельный вход/регистрация ChatGPT, подготовка компьютера, свой Secure MCP Tunnel и коннектор. VPS требует отдельного собственного маршрута; без него отображается необходимость настройки. Ключи, cookies и службы донора не импортируются.

Для существующего проекта выберите папку, проверьте предложение Kit, создайте новый Chat; приложение откроет панель и передаст recovery. Прежде прекратите исполнение этого же плана в другом приложении. [Совместимость старых проектов](docs/modules/project-compatibility.md).

**Окно и фоновая служба.** Закрытие окна, Cmd+Q и Cmd+W закрывают только окно; служба продолжает работу. Повторный запуск возвращает ту же страницу. «Остановить фоновую службу…» в меню значка или окна ждёт завершения текущих ответов и команд; ожидание можно отменить. При зависшей работе выберите отдельный пункт «Принудительно остановить службу…»: после подтверждения операции прерываются, несохранённое состояние может быть потеряно. Очистке даётся до двух секунд, затем завершаются собственные процессы. Полностью заблокированный главный процесс может не обработать меню — тогда требуется системное принудительное завершение. Без tray остановка доступна в меню окна. «Окно через HTTP (тест)» открывает дополнительный клиент; одновременно управляет одно окно.

**iPad из любой точки интернета.** Настройки → «Доступ с iPad и других устройств» (или шаг «+ Доступ с iPad» в мастере). Tailscale бесплатен для личного использования (тариф Personal); входите личным аккаунтом Google, Apple или GitHub, не рабочей почтой на собственном домене — она создаёт платную сеть организации. На компьютере: установите Tailscale, войдите, один раз разрешите HTTPS в панели Tailscale (DNS → HTTPS Certificates) и нажмите «Включить доступ с других устройств». На iPad: установите Tailscale из App Store тем же аккаунтом, откройте показанный адрес в Safari (или QR-код), подтвердите код на компьютере. Доступ работает только внутри вашей сети Tailscale, без публичного адреса; пока он включён, компьютер не засыпает.

**Готовый комплект и обновление.** Комплект находится в `~/Downloads/WorkflowPilot-<version>`; распакуйте пакет своей платформы и следуйте INSTALL.txt. После каждого выпуска штатный installer обновляет `/Applications/Workflow Pilot.app` и собственную копию в корне проекта без пересборки; он не закрывает и не перезапускает приложение. Переход с 0.1.6: полностью завершите 0.1.6 и откройте новую копию из Applications. Переход с 0.2.0 и новее: закрытия окна недостаточно — остановите фоновую службу (значок или меню), дождитесь её выхода и откройте новую версию. Если служба работала во время установки, installer оставил проверенную копию в ожидании: после остановки службы повторите установку. Клиент новой версии, подключившийся к старой службе, только объясняет переход. Подробности — [контракт поставки](docs/modules/release.md); Linux-зависимости — [Linux runtime](docs/modules/linux.md).

## Проверки

Адрес панели зависит от её содержимого. После обновления приложения обновите инструменты подключения Workflow Pilot в ChatGPT и попросите оркестратора заново вызвать панель. Старая панель из истории может сохранить прежний HTML; переустановка приложения её не переписывает. Очистка истории и профиля не требуется. [Контракт обновления](docs/modules/chatgpt-plugin.md#ресурс-панели-и-обновление).

После запуска проверить службу 0.5.33, Kit 1.9.9, свежий MCP-каталог и панель `0.5.33-communication-5`, протокол 5. Затем вживую: карточки выбора Е1–Е5 и оба режима плана ([приёмка](docs/modules/user-choice.md#проверки)), карточку сессии при сужении sidebar, ожидание запуска готового плана, ход O до появления плана, итог панели и sidebar после приёмки и закрытия плана, карточку плана с закреплёнными зонами на большом плане, стадии задач и спиннеры, «Сейчас»/«История»/«Диагностика» панели и одинаковую палитру в светлой и тёмной темах. Для любой новой сессии проверьте [получение контекста без вложений](docs/modules/orchestrator-startup.md#живая-приёмка). Для рабочего опыта — [A–D](docs/modules/automatic-agent-dialogue-acceptance.md): новый workspace, новые разговоры, один Start, без посещения E. Ручной join/Enable остаётся только в отдельном [legacy P0/P1](docs/modules/plugin-communication-handoff.md). Старые активные назначения переходят через [штатную безопасную миграцию](docs/modules/assignment-dialogue-reliability.md#переход-старого-плана); обновление не переключает их молча. Уничтоженный iframe хоста отдельно проверяется на восстановление SDK.

```bash
npm test
npm run smoke
npm run check:architecture
npm run check --prefix packages/workflow-kit
node --test tests/codex-app-server-mcp.test.mjs
npm run check:codex-tools
```

Unit suite использует четыре процесса и включает backend-тесты на временных профилях с локальной fixture-страницей вместо ChatGPT. Smoke запускает скрытый in-process стенд разработки с изолированными Chromium fixtures. Executor fixtures используют настоящий Codex App Server без модельных ходов; Python-среда тестов — .harness/runtime/test-python (Python 3.13.9, requirements.txt; для Linux fixtures также mss/python-xlib). Проверки не заменяют действия пользователя в аккаунте, native VM и clean-install.

[Приёмка 0.2.x и сценарий Mac](docs/acceptance/backend-independence.md), [приёмка и сценарий iPad](docs/acceptance/remote-access.md), [приёмка оркестрации](docs/acceptance/orchestrated-execution.md), [результаты миграции 0.1.x](docs/acceptance/migration-0.1.0.md), [архитектура и карта модулей](docs/architecture/OVERVIEW.md).

Сборка: npm run build, только в назначенной delivery-задаче после DOCS. Обязательны все три платформы из одной базы; подпись выбирается явно. Частичный комплект не публикуется.
